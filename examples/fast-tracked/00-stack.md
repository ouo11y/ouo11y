# 00. Run the LGTM + collector stack

Goal: in about ten minutes you have Grafana, Loki, Tempo, Mimir, the ouo OpenTelemetry
Collector distribution and Muninn (the replay store, on MinIO) running on your machine, and
you can prove with `curl` that a trace makes the full round trip.

Everything below is copy and paste. Commands have no `$` prompt. Config files are linked
with their path in this repo; copy them as they are.

```
browser / mobile SDK ─┐ Authorization: Basic base64("demo:pt_dev_demo_...")
your backend         ─┼──> ouo-collector :4318 (OTLP: /v1/traces /v1/logs /v1/metrics) ──> tempo (traces)
any OTel SDK         ─┘    401 without credential, CORS, rate limit,                  ──> loki  (logs / session events)
                           ouo.project.id stamped from the username                    ──> mimir (metrics)
                           logs on scope ouo.replay (replay chunks) ──Bearer <Muninn ingest token>──> muninn (internal) ──> minio
Sentry SDK ──> ouo-collector :4320 (Sentry bridge) ──> tempo, loki
grafana --> loki, tempo, mimir (provisioned datasources)
```

One ingest for everybody (ADR-0007): browsers, phones **and your backend** post OTLP to
the collector with an HTTP Basic credential whose username is the **project id** and
whose password is the **public project token**. The collector checks it against an
htpasswd file, stamps `ouo.project.id`, rate-limits and forwards. Replay chunks are OTLP
log records on scope `ouo.replay` sent to the same `/v1/logs`; the collector routes them to
Muninn ([`docs/specs/muninn.md`](../../docs/specs/muninn.md)) and keeps a reference copy
without the chunk bytes in Loki. Muninn is internal: SDKs never talk to it. Its tokens
(ingest, read, admin) are server side.

## Prerequisites

- Docker Desktop (Compose v2 is bundled). The stack uses about 2 GB of RAM at rest.
- `curl`. `python3` only if you want to run `deploy/scripts/smoke.sh`.
- Free host ports: 3000, 3100, 3200, 9009, 4317, 4318, 4320, 13133, 8081, 3400, 9000,
  9001 (4317, 13133, 3400, 9000 and 9001 are bound to `127.0.0.1` only). If any of them is
  taken, see "Ports and the .env override" below. Do not skip that check: an
  OTLP endpoint that belongs to another collector swallows your telemetry silently.

## Step 1. Get the files

### One file, no clone (quickstart)

[`deploy/compose/quickstart.yaml`](../../deploy/compose/quickstart.yaml) is the whole stack
in a single compose file: the released images plus the config files, inlined as compose
`configs:` entries. Copy it into an empty folder as `compose.yaml` (no login: the images are
public, "Pull access" in Step 3), then:

```bash
docker compose up -d
```

That is all: Grafana on `:3000` (admin / testing567), OTLP on `:4318`, the Sentry bridge on
`:4320`, Muninn on `127.0.0.1:3400`, the `demo` project credential. Port overrides go in a
`.env` file next to it, with the `OUO_*_PORT` names from Step 2. It has no demo backend
(that one is built from source). It is generated by `deploy/scripts/gen-quickstart.sh`, so
`main`'s unreleased config changes may not be in it. Skip to Step 4 to verify.

### From a clone

The other route is to run the stack straight from a clone of this repo next to your
own project. Nothing in `deploy/` knows about your code; your backend, web and mobile
apps all need the same two things: the collector's URL and the project credential
(`projectId` + `projectToken`).

```bash
git clone https://github.com/ouo11y/ouo11y.git
```

```bash
cd ouo11y
```

The stack runs the **released images** of the two ouo components, pinned to exact
versions in `deploy/compose/.env.example`:

| Image | Default version | Variable |
|---|---|---|
| `ghcr.io/ouo11y/collector` (ouo-collector: OTLP and Sentry receivers) | `0.7.0` | `OUO_COLLECTOR_VERSION` |
| `ghcr.io/ouo11y/muninn` (replay store) | `0.2.0` | `OUO_MUNINN_VERSION` |

Grafana (`grafana/grafana:13.2.5`, no plugin), Loki, Tempo, Mimir and MinIO are stock
upstream images. The ouo images come in through the override file
`deploy/compose/compose.images.yaml`; without it, `compose.yaml` builds the same two from
source (the contributor path, see "Build from source" in Step 3).

If you would rather vendor the stack into your own repo, copy these paths **keeping

## Step 2. Ports and the `.env` override

Default host ports (container ports never change):

| Service | Host port | Purpose |
|---|---|---|
| grafana | 3000 | UI, login `admin` / `testing567` |
| loki | 3100 | Loki API (`/ready`, `/loki/api/v1/...`) |
| tempo | 3200 | Tempo API (`/ready`, `/api/search`, `/api/traces/{id}`) |
| mimir | 9009 | Mimir (`/ready`, `/prometheus/api/v1/...`) |
| otel-collector | 4318 | **the SDK endpoint**: OTLP/HTTP (`/v1/traces`, `/v1/logs`, `/v1/metrics`; replay chunks are logs), Basic credential, CORS for browsers |
| otel-collector | 4320 | Sentry SDK bridge, DSN key auth ([`docs/specs/sentry-bridge.md`](../../docs/specs/sentry-bridge.md)) |
| otel-collector | 127.0.0.1:4317 | OTLP/gRPC, loopback only (backend development on this machine) |
| otel-collector | 127.0.0.1:13133 | collector health (`GET /`) |
| backend | 8081 | ouo demo backend (delete the service if you do not want it) |
| muninn | 127.0.0.1:3400 | **internal** replay store (`/ready`, read API with the read token) |
| minio | 127.0.0.1:9000, 9001 | Muninn's object store (S3 API, web console) |

To change any host port or token, copy the example file and edit it. Compose reads
`deploy/compose/.env` automatically and so do the scripts. Without a `.env` the stack runs
with the development values in [`.env.example`](../../deploy/compose/.env.example)
(`OUO_*_PORT`, `OUO_MUNINN_INGEST_TOKEN` / `OUO_MUNINN_READ_TOKEN` / `OUO_MUNINN_ADMIN_TOKEN`
= `mit_dev_` / `mrt_dev_` / `mat_dev_0000000000000000`), which is fine as long as nobody but
you can reach port 4318.

```bash
cp deploy/compose/.env.example deploy/compose/.env
```

In-cluster addresses are fixed and independent of `.env`: `otel-collector:4318`,
`loki:3100`, `tempo:3200`, `mimir:9009`, `muninn:3400`, `minio:9000`.

## Step 3. Start

### Pull access

The `ghcr.io/ouo11y/*` images are public: no GitHub account, no token, no
`docker login`. If a pull stops with `denied` (HTTP 403), Docker still sends an old
ghcr.io login whose token expired or was revoked; drop it and pull again:

```bash
docker logout ghcr.io
```

No route to ghcr.io? Use **Build from source** below: it needs only the full checkout.

### Start the stack

From the repo root:

```bash
docker compose -f deploy/compose/compose.yaml -f deploy/compose/compose.images.yaml up -d
```

The first run pulls the Grafana, Loki, Tempo, Mimir and MinIO images plus the pinned ouo
collector and Muninn images, and builds the demo backend if you kept it. To save typing,
put `COMPOSE_FILE=deploy/compose/compose.yaml:deploy/compose/compose.images.yaml` in your
shell (`export`) and drop the `-f` flags; the commands below show `compose.yaml` alone,
add the second `-f` (or keep `COMPOSE_FILE` set) for every one of them.

To try another version, set `OUO_COLLECTOR_VERSION` / `OUO_MUNINN_VERSION` in
`deploy/compose/.env` and run the same `up -d`. Pin exact versions.

**Build from source** (you change `collector/` or `services/muninn/`, or an image is not
published yet): leave `compose.images.yaml` out.

```bash
docker compose -f deploy/compose/compose.yaml up -d
```

That builds the ouo collector distribution (the OpenTelemetry Collector Builder compiles
it from `collector/`; this is the slow step) and Muninn. Allow several minutes.

Useful variants:

```bash
docker compose -f deploy/compose/compose.yaml ps
```

```bash
docker compose -f deploy/compose/compose.yaml logs -f otel-collector
```

```bash
docker compose -f deploy/compose/compose.yaml down
```

```bash
docker compose -f deploy/compose/compose.yaml down -v
```

`down` keeps the data (named volumes, replay chunks in `minio-data` included). `down -v`
wipes it.

## Step 4. Verify the stack is ready

Loki, Tempo, Mimir and the collector ship distroless images (no shell, no `wget`),
so there are no Docker healthchecks. Readiness is probed over HTTP from the host.

Reference script (reads `.env`, polls every service up to 120 s):

```bash
deploy/scripts/wait-ready.sh
```

Manual equivalents, one per service. Each must print `200`.

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3100/ready
```

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3200/ready
```

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:9009/ready
```

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:13133/
```

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/api/health
```

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3400/ready
```

Grafana answers within seconds. Loki, Tempo and Mimir return a non-200 body that
explains what they are still waiting for for roughly the first 15 to 30 s; keep polling.

Confirm the browser path on the collector (the web SDK posts to it from your dev server
origin). You want `access-control-allow-origin` and an `access-control-allow-headers`
that includes `authorization` in the reply:

```bash
curl -s -i -X OPTIONS http://localhost:4318/v1/traces -H 'Origin: http://localhost:5173' -H 'Access-Control-Request-Method: POST' -H 'Access-Control-Request-Headers: authorization,baggage,content-type,traceparent'
```

And that the collector refuses anonymous writes (expect `401`):

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://localhost:4318/v1/traces -H 'Content-Type: application/json' --data-binary '{"resourceSpans":[]}'
```

The credential every client sends is `Authorization: Basic base64("<project id>:<project token>")`.
For the development project:

```bash
BASIC=$(printf '%s' 'demo:pt_dev_demo_0000000000000000' | base64)
```

(`ZGVtbzpwdF9kZXZfZGVtb18wMDAwMDAwMDAwMDAwMDAw`.) The project id is the Basic username
and becomes `ouo.project.id`; the token is checked against
`deploy/compose/collector/projects.htpasswd`.

### Send one trace by hand and find it in Tempo

`deploy/scripts/smoke.sh` does this for traces, logs and metrics with assertions. If
you have `python3`, run it:

```bash
deploy/scripts/smoke.sh
```

The manual version for traces only. First set the timestamps and ids:

```bash
NOW_NS=$(( $(date +%s) * 1000000000 ))
```

```bash
TRACE_ID=0af7651916cd43dd8448eb211c80319c
```

Post one span to the collector with the development credential and `session.id`
as a span attribute (this is the attribute the ouo SDKs and the backend baggage
processor set). The collector stamps `ouo.project.id=demo` on the resource for you:

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://localhost:4318/v1/traces -H "Authorization: Basic $BASIC" -H 'Content-Type: application/json' --data-binary '{"resourceSpans":[{"resource":{"attributes":[{"key":"service.name","value":{"stringValue":"hello"}},{"key":"ouo.platform","value":{"stringValue":"web"}}]},"scopeSpans":[{"scope":{"name":"hand"},"spans":[{"traceId":"'"$TRACE_ID"'","spanId":"b7ad6b7169203331","name":"GET /hello","kind":2,"startTimeUnixNano":"'"$((NOW_NS - 50000000))"'","endTimeUnixNano":"'"$NOW_NS"'","attributes":[{"key":"session.id","value":{"stringValue":"hand-session"}}],"status":{"code":1}}]}]}]}'
```

Expect `200`. Fetch it by id (works within a second or two):

```bash
curl -s http://localhost:3200/api/traces/$TRACE_ID | head -c 300
```

Search by session (TraceQL). Tempo only searches a tiny recent window when you omit
`start`/`end`, so always pass them. Searchable about 10 to 60 s after ingestion:

```bash
curl -s -G http://localhost:3200/api/search --data-urlencode 'q={ resource.ouo.project.id = "demo" && span.session.id = "hand-session" }' --data-urlencode "start=$(( $(date +%s) - 600 ))" --data-urlencode "end=$(( $(date +%s) + 60 ))"
```

Logs and metrics follow the same pattern: `POST /v1/logs` and `POST /v1/metrics` on
port 4318 with the same header, then query `http://localhost:3100/loki/api/v1/query_range`
and `http://localhost:9009/prometheus/api/v1/query`.

Replay chunks come from the SDKs (OTLP/protobuf log records on scope `ouo.replay`, format
in [`docs/specs/muninn.md`](../../docs/specs/muninn.md) section 3). Once an SDK has
recorded a session, list its replays in Muninn with the read token:

```bash
curl -s -H 'Authorization: Bearer mrt_dev_0000000000000000' http://127.0.0.1:3400/api/v1/projects/demo/sessions/<session id>/replays
```

Any stock OTel SDK, your backend included, posts the same way with two standard
variables: `OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318` and
`OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic%20ZGVtbzpwdF9kZXZfZGVtb18wMDAwMDAwMDAwMDAwMDAw`
(`%20` is how the OTLP env variables encode the space). On a server install the endpoint
is `https://otel.<domain>`.

## Step 5. Log in to Grafana

Open http://localhost:3000 and sign in with `admin` / `testing567` (set in `compose.yaml`
via `GF_SECURITY_ADMIN_USER` / `GF_SECURITY_ADMIN_PASSWORD`; anonymous access is off).
Sessions are found by `session_id` in Explore:

- Explore -> Tempo -> TraceQL `{ span.session.id = "hand-session" }` finds the span
  you posted above.
- Explore -> Loki -> `{service_name="<your service>"} | session_id="<session id>"` shows a
  session's events, `{event_name="session.start"}` the sessions that started.
- Explore -> Mimir -> `traces_spanmetrics_calls_total` (written by Tempo's metrics
  generator) once traces flow.

Datasources are provisioned with fixed uids `loki`, `tempo`, `mimir` and are not
editable from the UI. Trace to logs is a custom query on `service_name` plus
`session_id`; logs to trace uses the `trace_id` structured metadata field.

## What each collector pipeline does

[`deploy/compose/collector/config.yaml`](../../deploy/compose/collector/config.yaml)
configures the ouo collector distribution, the single ingress for browsers, phones and
backends alike; its header comment draws the pipelines. The `basicauth/server` extension
(htpasswd file `/etc/otelcol/projects.htpasswd`), reached through `ouoauth` (which counts
every rejected credential as `ouo_auth_failures_total{reason}`), guards the `otlp`
receiver (gRPC 4317 on loopback, HTTP 4318 public, with CORS). The `ouosentry` receiver
(4320) takes Sentry SDK envelopes and authenticates their DSN key itself. A `resource`
processor stamps `ouo.project.id` from the authenticated username on every signal, and
`ouoratelimit` limits per project and per client.

- **traces**: `otlp`, `ouosentry` -> `batch` -> `otlp_grpc/tempo`.
- **metrics**: `otlp` -> `batch` -> `otlp_http/mimir`. Mimir runs with
  `otel_metric_suffixes_enabled: false`, so a counter named `ouo.demo.requests` is queried
  as `ouo_demo_requests`.
- **logs/in** -> `routing/replay`: records on scope `ouo.replay` go to **logs/replay**
  (no batch, disk queue) -> `otlp_http/muninn` (`MUNINN_ENDPOINT`, `MUNINN_INGEST_TOKEN`,
  `MUNINN_TENANT`), and to **logs/replay-index** (chunk body dropped, `ouo.replay.ref`
  set) -> Loki; everything else goes to **logs** -> `transform/events`, `batch` -> Loki.
  `transform/events` copies `event_name` into `event.name` and `ouo.platform` from the
  resource to the record; both become Loki stream labels, while `session.id` stays
  structured metadata (filter with `| session_id="..."`).
- **logs/sentry**: `ouosentry` -> `routing/replay`: with `replay_wire: muninn` Sentry
  replays go to Muninn like any replay chunk, the other Sentry logs to Loki.

Your own backend still has to allow `traceparent`, `tracestate` and `baggage` in *its*
CORS, because the browser calls your API directly (covered in
[`10-backend.md`](10-backend.md)).

`projects.htpasswd` has one line per project token, `<project id>:{SHA}<base64 sha1>`.
`demo` is for your apps, `internal` for the platform's own telemetry (Muninn and the demo
backend). Add yours with `htpasswd -nbs <id> <token> >> deploy/compose/collector/projects.htpasswd`
(or `printf '%s:{SHA}%s\n' <id> "$(printf '%s' <token> | openssl dgst -binary -sha1 | openssl base64)"`),
then `docker compose -f deploy/compose/compose.yaml restart otel-collector`.

## What you should see

- `docker compose -f deploy/compose/compose.yaml ps` lists `grafana`, `loki`, `tempo`,
  `mimir`, `otel-collector`, `minio`, `muninn` (and `backend` if kept) as `running`;
  `muninn-init` has exited `0`; `grafana` shows `(healthy)`.
- The six readiness curls print `200`. `deploy/scripts/wait-ready.sh` prints seven
  `ready:` lines.
- The preflight reply contains `Access-Control-Allow-Origin: http://localhost:5173` and
  `authorization` in `Access-Control-Allow-Headers`; the credential-less POST prints `401`,
  the one with `$BASIC` prints `200`.
- `curl http://localhost:3200/api/traces/0af7651916cd43dd8448eb211c80319c` returns a
  JSON trace, and the TraceQL search returns one entry under `traces`.
- `deploy/scripts/smoke.sh` ends with `SMOKE OK: trace_id=... session.id=... service=... project=demo run_id=...`.
- Grafana at http://localhost:3000 logs you in as `admin`, and Connections -> Data sources
  lists Loki, Tempo and Mimir.
- `docker compose -f deploy/compose/compose.yaml logs otel-collector` shows no
  `Exporting failed` lines once the backends are ready.
