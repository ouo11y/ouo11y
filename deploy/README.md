# deploy

Observability stack for ouo: Grafana, Loki, Tempo, Mimir, the ouo OpenTelemetry Collector
distribution (`collector/`), Muninn (the replay store, ADR-0019) on MinIO and the demo backend,
in one Docker Compose project. `deploy/vm` adds TLS and systemd for a server install,
`deploy/helm` is the Kubernetes chart. Already running Loki, Tempo and Mimir?
`compose.external.yaml` (or Helm `lgtm.mode: external`) points ouo at them:
[docs/operations/existing-lgtm.md](../docs/operations/existing-lgtm.md).

```
browser SDK ──┐  Authorization: Basic base64("<project id>:<project token>")
mobile SDK  ──┼──> ouo-collector :4318  /v1/traces /v1/logs /v1/metrics  (OTLP/HTTP; replay = logs of scope ouo.replay)
any OTel SDK ─┤                  :4320  Sentry SDK envelopes (bridge, ADR-0008)
your backend ─┘        │  401 no/unknown credential · CORS preflight · 413 · 429 (per project, per client)
                       │  stamps resource ouo.project.id = Basic username (client value overwritten)
                       ├──OTLP──> tempo  (traces)   loki (logs / session events)   mimir (metrics)
                       └──replay chunks + Bearer <Muninn ingest token> (disk queue)──> muninn :3400 (internal) ──> minio
grafana :3000 ──> loki, tempo, mimir (provisioned datasources)
```

Rule of thumb (ADR-0007): **the project token is public, the Muninn tokens are secrets.** The
project token ships inside browser bundles and only lets a client *write* telemetry into one
project, within the collector's CORS, size and rate limits. Muninn's ingest token is the shared
secret between the collector's `otlp_http/muninn` exporter and Muninn; its read and admin tokens
unlock replay reads and erasure. They live in `.env` and never reach a browser. Muninn, MinIO,
Loki, Tempo and Mimir are internal: SDKs only ever talk to the collector.

## Named environments (`ouo-env`, the default for agents)

Agents and the founder run stacks as named envs behind one proxy instead of raw
`docker compose` on numbered ports: `deploy/envs/ouo-env up <env>` gives
`http://grafana.<env>.ouo.localhost` (main: `http://grafana.ouo.localhost`, admin / testing567),
`ls`, `gc` and `down` keep the laptop clean, and only the SDK ingest ports a device needs are
published. See [envs/README.md](envs/README.md). The commands below are the plain compose path
(single stack, host ports from `.env`), still used by CI, the VM install and the fast-tracked guides.

**No clone at all:** [compose/quickstart.yaml](compose/quickstart.yaml) is the stack on the
latest release: the ouo images default to `:latest`, and every mounted config is inlined
(`configs.content`), minus the demo backend. Its header lists the exact version and digest of
each image it was generated for (pin them with `OUO_*_VERSION` in a `.env` next to it). Copy it
into an empty folder and `docker compose up -d` (the project is named after the folder, so
copies in two folders never collide). It is generated by `deploy/scripts/gen-quickstart.sh`:
the newest `<image>-vX.Y.Z` tag of the collector and Muninn, the configs and upstream image tags
of `deploy/compose` in this checkout. CI job `quickstart` runs `--check --verify-digests`: it
fails after a release until the file is regenerated, and when the file or its service blocks
drift from `compose.yaml` + `compose.images.yaml`, the release set breaks
[compatibility.md](../docs/compatibility.md), the `compose.images.yaml` / `.env.example` pins
lag, or a digest no longer matches ghcr.io.

## Self-hosted Sentry as the bridge's upstream (testing)

The Sentry bridge (`ouosentry`, ADR-0008) can forward to a real Sentry on this Mac instead of a
fake one: getsentry/self-hosted in `~/Desktop/personal/sentry-self-hosted`, compose project
`sentry-sbx`, at https://sentry.ouo.localhost through the ouo-env proxy (http://localhost:9000
direct; login `admin@ouo.localhost` / testing567). It needs about 14 GiB of Docker memory (Docker
Desktop at 20 GB + swap). Point an env's bridge at it with `OUO_SENTRY_UPSTREAM=http://host.docker.internal:9000`,
`OUO_SENTRY_PROJECT_ID` and `OUO_SENTRY_PUBLIC_KEY` of the Sentry project. Install, memory, the
read-only Sentry MCP server and what the first run showed: [project/kb-archive/sentry-self-hosted.md](../project/kb-archive/sentry-self-hosted.md).

## Start, stop, reset

```bash
docker compose -f deploy/compose/compose.yaml up -d          # start (builds collector/, examples/backend and services/muninn)
docker compose -f deploy/compose/compose.yaml ps             # status
docker compose -f deploy/compose/compose.yaml logs -f otel-collector muninn
docker compose -f deploy/compose/compose.yaml down           # stop, keep data
docker compose -f deploy/compose/compose.yaml down -v        # stop and wipe all data
```

A fresh clone works with no `.env`: every variable has the same default inside
`compose.yaml` (development tokens included) and `collector/projects.htpasswd` ships the
`demo` project. The first `up` builds the collector image with the OpenTelemetry Collector
Builder, which takes a few minutes. Data lives in named volumes (`ouo_grafana-data`,
`ouo_loki-data`, `ouo_tempo-data`, `ouo_mimir-data`, `ouo_minio-data` for replays, and
`ouo_replay-queue`, the collector's disk queue to Muninn).

**Released images instead of builds:** add `-f deploy/compose/compose.images.yaml` to pull
the pinned `ghcr.io/ouo11y/{collector,muninn}` images. They are public: no
`docker login` and no token. A pull that fails with `denied` (HTTP 403) means Docker still
sends an old ghcr.io login whose token expired; `docker logout ghcr.io` and pull again. The
plain `compose.yaml` above builds the same two from source. Full steps:
`examples/fast-tracked/00-stack.md`, Step 3.

## Ports

| Service | Host binding | Container | Purpose |
|---|---|---|---|
| otel-collector | `0.0.0.0:4318` | 4318 | **OTLP/HTTP for every SDK**: `/v1/traces`, `/v1/logs`, `/v1/metrics`; Basic credential required; CORS for browsers |
| otel-collector | `0.0.0.0:4320` | 4320 | Sentry SDK bridge (ADR-0008), DSN key auth |
| otel-collector | `127.0.0.1:4317` | 4317 | OTLP/gRPC for backend development on this host |
| otel-collector | `127.0.0.1:13133` | 13133 | collector health (`GET /`) |
| grafana | `0.0.0.0:3000` | 3000 | UI, `admin` / `testing567` |
| muninn | `127.0.0.1:3400` | 3400 | **internal** replay store ([spec](../docs/specs/muninn.md)): OTLP ingest (ingest token), reads (read token), erasure (admin token); `/healthz`, `/ready` open. Never exposed in production |
| backend | `0.0.0.0:8081` | 8081 | demo backend (`/healthz`, `/api/products`, `/api/cart`, `/api/checkout`) |
| loki | `0.0.0.0:3100` | 3100 | Loki API (`/loki/api/v1/...`, OTLP at `/otlp/v1/logs`) |
| tempo | `0.0.0.0:3200` | 3200 | Tempo API (`/api/search`, `/api/traces/{id}`) |
| mimir | `0.0.0.0:9009` | 9009 | Mimir (`/prometheus/api/v1/...`, OTLP at `/otlp/v1/metrics`) |
| minio | `127.0.0.1:9000`, `127.0.0.1:9001` | 9000, 9001 | S3 API and web console of Muninn's store (`minioadmin` / `minioadmin`, laptop only) |

On a server (`deploy/vm`) Caddy owns 80/443 and every port above is re-bound to loopback;
the collector is reached as `https://otel.<domain>`. Host ports can be changed without
touching the compose file: copy `deploy/compose/.env.example` to `deploy/compose/.env` and
edit the `OUO_*_PORT` values; compose and the scripts in `deploy/scripts/` read that file.
In-cluster addresses never change (`otel-collector:4318`, `loki:3100`,
`tempo:3200`, `mimir:9009`, `muninn:3400`, `minio:9000`).

## Environment (`deploy/compose/.env`, see `.env.example`)

| Variable | Default (compose) | Used by | Meaning |
|---|---|---|---|
| `OUO_MUNINN_INGEST_TOKEN` | `mit_dev_0000000000000000` | otel-collector, muninn | **secret** bearer the collector's `otlp_http/muninn` exporter sends to Muninn; same value on both sides |
| `OUO_MUNINN_READ_TOKEN` | `mrt_dev_0000000000000000` | muninn | **secret** read token of Muninn's replay reads |
| `OUO_MUNINN_ADMIN_TOKEN` | `mat_dev_0000000000000000` | muninn | **secret** erasure and audit (`ouo-erase`) |
| `OUO_BACKEND_OTLP_HEADERS` | `Authorization=Basic%20aW50ZXJu...` (`internal`) | backend, muninn | `OTEL_EXPORTER_OTLP_HEADERS` the in-compose services use for their own telemetry (`%20` = space) |
| `OUO_PROJECT_ID`, `OUO_PROJECT_TOKEN` | `demo`, `pt_dev_demo_0000000000000000` | scripts only | which project `smoke.sh` sends as; must match a line in `collector/projects.htpasswd`. Compose does not read them |
| `OUO_*_PORT` | see table above | compose, scripts | host ports |

Projects are not environment: they are lines in `deploy/compose/collector/projects.htpasswd`
(`<project id>:{SHA}<base64 sha1(token)>`, exactly what `htpasswd -nbs <id> <token>`
prints; cheap on purpose, the token is public). One line per project id: `basicauth` keeps
only the last line for an id, so rotation is a cut-over (replace the line, restart, ship the
new token; ADR-0007 section 2). After editing, `docker compose ... restart otel-collector`:

```bash
echo "pt_$(openssl rand -hex 16)"                                   # new token
htpasswd -nbs web-store pt_live_...  >> deploy/compose/collector/projects.htpasswd
# without apache2-utils:
printf '%s:{SHA}%s\n' web-store "$(printf '%s' pt_live_... | openssl dgst -binary -sha1 | openssl base64)" >> deploy/compose/collector/projects.htpasswd
```

**The defaults are development values and are committed to a public repo** (`demo` /
`pt_dev_demo_0000000000000000`, `mit_dev_...`, `mrt_dev_...`, `mat_dev_...`). They are fine
while the collector is reachable only from your laptop. Anything other people can reach needs
generated values: `echo pt_$(openssl rand -hex 16)` (and `mit_`, `mrt_`, `mat_`);
`deploy/vm/install.sh` does this for you and writes a server-side `projects.htpasswd`.

SDK configuration against this stack:

```ts
init({ endpoint: "http://localhost:4318",      // replay goes to /v1/logs of the same endpoint
          projectId: "demo", projectToken: "pt_dev_demo_0000000000000000",
          service: { name: "web-store", version: "1.4.2", environment: "local" } });
```

Any stock OpenTelemetry SDK, your backend included, posts the same way:
`OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318`
`OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic%20ZGVtbzpwdF9kZXZfZGVtb18wMDAwMDAwMDAwMDAwMDAw`
(`base64("demo:pt_dev_demo_0000000000000000")`; `%20` is how the OTLP env variables
encode a space). Inside the compose network the endpoint is `http://otel-collector:4318`
with the same header, which is what the `backend` service does. A backend on the stack
host may also use the loopback gRPC port `localhost:4317`.

## Verify

```bash
deploy/scripts/wait-ready.sh   # /ready of every service, collector health + the OTLP port, Muninn /ready
deploy/scripts/smoke.sh        # edge rules + 1 trace, 1 log, 1 metric round trip through the collector
node tests/e2e/muninn/run.mjs  # replay through the collector into Muninn (needs OUO_MUNINN_URL, OUO_COMPOSE_PROJECT: `ouo-env env <env>`)
```

`smoke.sh` sends OTLP/JSON to the collector's `/v1/{traces,logs,metrics}` with the Basic
credential, `service.name=smoke`, `session.id=smoke-session`, `event.name=session.start`
and a deliberately wrong `ouo.project.id=spoofed`, then asserts:

- CORS: preflight from `Origin: http://localhost:5173` on `:4318/v1/traces` returns
  `Access-Control-Allow-Origin` and allows `Authorization`; a preflight from
  `https://evil.example` returning allow-origin is reported as a warning (the list is global,
  ADR-0007 section 4).
- Auth: `POST` without credential `401`, wrong token `401`, unknown project id `401`.
- Collector accepted: OTLP `200` x3.
- Tempo: `{ span.session.id = "smoke-session" }` and
  `{ resource.ouo.project.id = "demo" }` both find the trace; `GET /api/traces/<id>` carries
  `ouo.project.id=demo` (the spoofed value is gone).
- Loki: `{service_name="smoke", event_name="session.start", ouo_platform="web"} | session_id="smoke-session" | ouo_project_id="demo"`
  returns the record (labels are `service_name`, `event_name`, `ouo_platform`,
  `deployment_environment_name`; everything else is structured metadata).
- Mimir: `ouo_smoke_requests{run_id="..."}` is queryable through `/prometheus/api/v1/query`.

Manual checks:

```bash
B=ZGVtbzpwdF9kZXZfZGVtb18wMDAwMDAwMDAwMDAwMDAw   # printf 'demo:pt_dev_demo_0000000000000000' | base64
curl -i -X OPTIONS -H "Origin: http://localhost:5173" -H "Access-Control-Request-Method: POST" -H "Access-Control-Request-Headers: authorization,content-type" localhost:4318/v1/traces
curl -i -X POST localhost:4318/v1/traces -H 'content-type: application/json' -d '{"resourceSpans":[]}'                               # 401
curl -i -X POST localhost:4318/v1/traces -H "authorization: Basic $B" -H 'content-type: application/json' -d '{"resourceSpans":[]}'   # 200
curl -s localhost:3400/ready                                                                         # Muninn ready (no token)
curl -H 'baggage: session.id=s1,user.id=u1,ouo.platform=web' localhost:8081/api/products             # demo backend -> collector (in-network, Basic header)
curl -G localhost:3200/api/search --data-urlencode 'q={ resource.service.name = "demo-backend" && span.session.id = "s1" }'
```

In Grafana (http://localhost:3000, admin/testing567): Explore -> Tempo -> search
`{ span.session.id = "smoke-session" }`; open a span and use "Logs for this span"
(trace to logs is a custom query on `service_name` + `session_id`). Explore -> Loki ->
`{event_name="session.start"}`. The Tempo metrics generator writes
`traces_spanmetrics_*` and `traces_service_graph_*` to Mimir, which feed the
service map.

## The collector

`collector/` is a custom OpenTelemetry Collector distribution built with ocb: upstream
`otlp` receiver, `basicauth`, `resource`/`attributes`/`transform`, `batch`,
`memory_limiter`, `routing`, the OTLP exporters, `file_storage`, `health_check`, plus ouo's
`ouosentry` receiver, `ouoauth` extension and `ouoratelimit` processor. Compose builds it as `ouo/collector` from
`../../collector` and mounts `deploy/compose/collector/config.yaml` at
`/etc/otelcol/config.yaml` and `projects.htpasswd` at `/etc/otelcol/projects.htpasswd`.
It needs `MUNINN_ENDPOINT`, `MUNINN_INGEST_TOKEN` and `MUNINN_TENANT` in its environment
for the replay route to Muninn. Config details:
`project/kb-archive/collector-lgtm.md` and the collector agent's notes.

## Muninn

`services/muninn` (Go, ADR-0019, [spec](../docs/specs/muninn.md)) is built from
`../../services/muninn` and configured by a mounted YAML file (`deploy/compose/muninn/config.yaml`,
started with `-config.file=/etc/muninn/config.yaml -config.expand-env=true`; every key is in
`services/muninn/config.example.yaml`). It stores replay chunks and debug files in MinIO, in a
bucket `muninn-init` creates together with a user whose policy only reaches that bucket
(`OUO_MUNINN_S3_*`); Muninn never runs with the MinIO root credentials. It listens on
`127.0.0.1:${OUO_MUNINN_PORT:-3400}` (laptop only). The collector writes replay chunks to it
with the ingest token; erasure runs through `ouo-erase` (`libs/ouo-go`) with the admin token.

The official `minio/minio` and `minio/mc` images are no longer published; the stack pins
the community-maintained builds `pgsty/minio` and `pgsty/mc` (same server and client,
override with `OUO_MINIO_IMAGE` / `OUO_MC_IMAGE`).

The web demo's `VITE_OTLP_ENDPOINT` points at the collector (default `http://localhost:4318`)
and `VITE_OUO_PROJECT_ID` / `VITE_OUO_PROJECT_TOKEN` at the project credential.

## Server install (`deploy/vm`)

```bash
curl -fsSL https://raw.githubusercontent.com/ouo11y/ouo11y/main/deploy/vm/install.sh \
  | sudo bash -s -- --domain ouo.example.com --email you@example.com
```

Caddy terminates TLS for `OUO_DOMAIN` (Grafana) and `OUO_OTEL_DOMAIN` (the collector:
`/api/*` to the Sentry bridge on 4320, everything else to 4318), every other port is re-bound
to loopback, a project credential and the Muninn and MinIO secrets are generated, the project's `{SHA}` line
is written to a server-side `projects.htpasswd`, a systemd unit keeps the stack up across
reboots. Details, firewall, data locations, upgrade and backup: `deploy/vm/README.md`.
Kubernetes: `deploy/helm/README.md`.

## Notes

- Loki, Tempo, Mimir and the collector images are distroless: no shell, no `wget`, so
  they have no Docker healthchecks. Use `wait-ready.sh`. The collector retries exports
  until the backends are up, Grafana tolerates datasources that are not ready yet.
- Every OTLP client needs the Basic credential, in-network services included: the
  `backend` and `muninn` services carry `OTEL_EXPORTER_OTLP_HEADERS` (from
  `OUO_BACKEND_OTLP_HEADERS`), so their own telemetry is stamped with the `internal`
  project: its own rate-limit buckets, never a client project's quota. On a VM install
  the installer sets it to the generated project's credential instead.
- Tempo 3.x logs `no jobs found` errors from its backend scheduler every few seconds
  in single-binary mode; harmless.
- Loki, Tempo and Mimir are still published on `0.0.0.0` in the laptop stack so
  Explore-style curls work from other devices on your LAN; the VM override binds them to
  loopback.
- Pinned images: see `compose.yaml` and `project/kb-archive/collector-lgtm.md`; collector component
  versions in `collector/builder.yaml`.
