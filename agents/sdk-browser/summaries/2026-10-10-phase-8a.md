# sdk-browser: 2026-10-10 Phase 8a (ingest gateway and project tokens, ADR-0007 section 7)

Branch `phase-8a-install-secure`, worktree `.claude/worktrees/mvp-product-roadmap-6becbb`. `@ouo/browser` 0.1.0 -> 0.2.0.

## What changed

- `sdk/browser/src/ingest.ts` (new): `deriveIngestUrls({ endpoint, projectToken, otlpEndpoint })`
  -> `{ endpoint, otlpBase, traces, logs, replay, otlpBypass }`; throws on an empty token or
  endpoint. `PROJECT_TOKEN_HEADER = "X-Ouo-Project-Token"`, `projectTokenHeaders(token)`,
  `OTLP_INGEST_PATH`, `REPLAY_CHUNKS_PATH`, `trimSlash`. Pure, no I/O.
- `sdk/browser/src/index.ts`: `initRUM` derives the URLs first (fails fast, nothing installed
  on a missing token); `OTLPLogExporter` / `OTLPTraceExporter` get `url` + `headers` (the token);
  the chunk uploader gets `projectToken`; replay is on unless `replay.enabled: false` (no more
  "no replayEndpoint" silent-off); built-in `ignoreUrls` are `^${otlpBase}/` and
  `^${endpoint}/v1/replay/`; the debug init line prints `endpoint`, `traces`, `logs`, `replay`,
  `otlpBypass`, `session`, `user`, never the token. Re-exports `deriveIngestUrls`,
  `PROJECT_TOKEN_HEADER`, `IngestUrls`.
- `sdk/browser/src/replay/uploader.ts`: `UploaderOptions.projectToken` (required); the header is
  in the single `headers` object used by both the gzip path and the `pagehide` keepalive path.
- `sdk/browser/src/types.ts`: see API diff below. `src/version.ts` 0.2.0.
- `sdk/browser/package.json`: 0.2.0, `repository` (`directory: sdk/browser`), `homepage`, `bugs`,
  `keywords`, `publishConfig.access: public`, `files` += `CHANGELOG.md`, `LICENSE`. New
  `sdk/browser/CHANGELOG.md` (0.2.0 breaking entry + migration diff) and `sdk/browser/LICENSE`
  (Apache-2.0 text, copied from `@opentelemetry/api`'s LICENSE; the repo root has none).
- `sdk/browser/README.md`: new init snippet, options table (`endpoint`, `projectToken`,
  `otlpEndpoint`), replay headers, a Debugging section (init line, rum-api status codes).
- `sdk/browser/playground/main.js` (`?rum=`, `?token=`, `?otlp=` params) and
  `playground/server.mjs`: the :8090 stub is now a rum-api ingest stub (401 without the token,
  accepts `/ingest/otlp/v1/*`, replay envelope validation unchanged, CORS header list extended).
- `examples/web`: `src/rum.ts` reads `VITE_RUM_API` (default `http://localhost:8080`) and
  `VITE_OUO_PROJECT_TOKEN` (default `pt_dev_demo_0000000000000000`), passes
  `{ endpoint, projectToken }`; `VITE_OTLP_ENDPOINT` dropped from `.env.example`, `README.md`
  and code; `src/rum-stub.ts` mirrors the new `RUMConfig` (throws on empty token, redacts it in
  its log); `package.json` dependency `@ouo/browser` `0.2.0`.
- `examples/fast-tracked/20-frontend.md`: section 0 bullet, tarball name/contents, section 2
  rewritten (one URL + one public token, what public means, rum-api CORS, 403/401 meaning),
  `rum.ts` copy, options table, section 6 expected console/network output, section 8 file walk
  (`ingest.ts`).
- `kb/otel-browser-sdk.md`: new section "Ingest gateway and project tokens" (items 14-20:
  exporter `headers` option, URL derivation, CORS preflight consequences, keepalive + custom

  `kb/web-demo-storefront.md`: env/stub/lockfile gotcha. No new kb file, so `kb/index.md`

- Root `package-lock.json`: `npm install` re-synced it for the 0.2.0 bump (3 lines: the
  `examples/web` dependency, `sdk/browser` version, and `plugins/ouo-rum-app` 0.3.0 which

## Public API diff (`RUMOptions`)

```diff
 export interface RUMOptions {
-  /** OTLP/HTTP base URL. The SDK appends `/v1/traces` and `/v1/logs`. */
+  /** rum-api base URL; SDK derives /ingest/otlp/v1/{traces,logs} and /v1/replay/chunks. */
   endpoint: string;
-  /** rum-api base URL for replay chunks. */
-  replayEndpoint?: string;
+  /** Public project identifier, sent as X-Ouo-Project-Token. Required; initRUM throws when empty. */
+  projectToken: string;
+  /** Escape hatch: OTLP to `${otlpEndpoint}/v1/{traces,logs}` instead of rum-api; token still sent. */
+  otlpEndpoint?: string;
   service: ServiceOptions; tracing?; replay?; session?; user?; debug?;
 }
+export { deriveIngestUrls, PROJECT_TOKEN_HEADER, type IngestUrls };
```

Behaviour changes: replay no longer needs a second URL and is on by default; the debug init
line has new keys; `tracing.ignoreUrls` built-ins narrowed from the whole `endpoint` origin to
the ingest paths.

## For the qa agent (live check against the new stack)

1. Build the SDK first (`npm run -w sdk/browser build`), then `npm run -w examples/web dev` with
   `examples/web/.env` holding `VITE_RUM_API=<rum-api>` and
   `VITE_OUO_PROJECT_TOKEN=pt_dev_demo_0000000000000000` (or whatever `deploy/docker/.env` sets as
   `OUO_PROJECT_TOKEN`; the SDK and rum-api must agree). With `VITE_RUM_DEBUG=1` the console shows
   `[ouo] @ouo/browser@0.2.0 initialised { endpoint, traces, logs, replay, otlpBypass: false, ... }`.
2. Network tab: `OPTIONS` then `POST <rum-api>/ingest/otlp/v1/logs` and `/ingest/otlp/v1/traces`
   (expect 200, request header `X-Ouo-Project-Token`), `POST <rum-api>/v1/replay/chunks` (202,
   gzip, `X-Ouo-Project-Token`, `x-ouo-session-id`, `x-ouo-seq`). Nothing to port 4318.
3. Negative checks: set a wrong token -> every POST is `401` and the console (debug) shows the
   OTel diag `export response failure (status: 401)`; serve the app from an origin not in the
   project's `allowed_origins` -> `403` on the POST (preflight still succeeds if any project
   allows that origin); empty `VITE_OUO_PROJECT_TOKEN=` -> the page throws
   `[ouo] initRUM: \`projectToken\` is required ...` at load and nothing is sent.
4. Unload path: navigate away / close the tab and confirm the last `/v1/replay/chunks` keepalive
   POST (plain JSON, no `content-encoding`) is accepted (202) with the token; this is the one
   browser-only behaviour the unit tests cannot prove.
5. Downstream: `ouo.project.id` on resources in Tempo/Loki is rum-api's job, but confirm the
   web-store session still appears in `GET /v1/sessions` with `has_replay: true` and in Grafana.
