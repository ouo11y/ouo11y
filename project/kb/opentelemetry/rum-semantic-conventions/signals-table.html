RUM signal map

Step 2 of the post-MVP plan, 2026-11-09. Every client signal: event or span, its name, its OTel status, and how sure we are that the final convention will match. All choices are proposals until the founder approves them. The reasoning is in the kb entries.

Five things to know

  1. Only the exception event and exception.* attributes are Stable. Everything else client-side is Development, or exists only in an SDK.
  2. Our rule: spans for network calls and two load phases (document load, app start), both created after the fact so they are never open. Everything else is an event.
  3. OTel's own SDKs disagree on several points, including app.crash against device.crash, and three spans against one for document load.
  4. OTel has no replay convention and no work in progress. Android's roadmap cites the absence of an OTLP data model for it.
  5. OTel has no React Native SDK. RN follows the mobile app.* names.
