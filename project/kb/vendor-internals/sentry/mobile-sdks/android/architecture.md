## 0. 8.62.0 vs 8.63.0 (what React Native users do not get)

React Native 8.34.0 ships sentry-android 8.62.0. The 8.63.0 changelog ([CHANGELOG.md#L3-L39](https://github.com/getsentry/sentry-java/blob/8.63.0/CHANGELOG.md#L3-L39)) adds:

- `Environment` on the `Scope`, applied also to the DSC, logs, metrics and profiles.
- Idle parent transactions now finish after the idle timeout (3 s) with status `ok`, instead of waiting for the 30 s deadline (`deadline_exceeded`). This changes `ui.load` durations and slow/frozen frame counts for `SentryTraced` users. App start, TTID and TTFD are unchanged.
- ANR profiling is skipped while a debugger is attached.
- `dist` is no longer set to the whole release on ANR / app-exit events without `+versionCode`.
- Faster mask/unmask class lookups in replay and screenshots.
- sentry-native 0.17.4 → 0.17.6; epitaph (tombstone parser) 0.1.1 → 0.2.0.
- Refuses servers whose certificate chains to leaked eMudhra intermediates.

None of these touch the envelope format or the on-disk layout (inferred: no cache or transport change is listed in that section).

## 2. Initialisation

### 2.1 Two entry points

1. **Auto-init (default).** `sentry-android-core` merges a `ContentProvider` into the app manifest: `.SentryInitProvider`, authority `${applicationId}.SentryInitProvider` ([AndroidManifest.xml#L7-L10](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/AndroidManifest.xml#L7-L10)). Its `onCreate` reads meta-data `io.sentry.auto-init` (default `true`). Unless the app is a Compose preview, it calls `SentryAndroid.init(context, logger)` with options from manifest meta-data only ([SentryInitProvider.java#L25-L28](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/SentryInitProvider.java#L25-L28)). `shutdown()` calls `Sentry.close()` ([#L34-L35](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/SentryInitProvider.java#L34-L35)). `attachInfo` throws if the authority lacks the applicationId prefix ([#L39-L45](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/SentryInitProvider.java#L39-L45)).
2. **Manual.** `SentryAndroid.init(context[, logger][, configuration])` ([SentryAndroid.java#L61-L98](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/SentryAndroid.java#L61-L98)). Set `io.sentry.auto-init=false` to stop the provider from initialising first.

A second provider, `SentryPerformanceProvider`, has `android:initOrder="200"`, so it runs early to timestamp app start ([AndroidManifest.xml#L12-L16](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/AndroidManifest.xml#L12-L16)).

### 2.2 Init priority (auto vs manual)

- Auto-init sets `InitPriority.LOW` when `io.sentry.auto-init` is true ([ManifestMetadataReader.java#L449-L452](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/ManifestMetadataReader.java#L449-L452)). The core default is `MEDIUM` ([SentryOptions.java#L643](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryOptions.java#L643)).
- A later init replaces the current one only if its priority is ≥ the previous one, or `forceInit` is true ([InitUtil.java#L47-L55](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/util/InitUtil.java#L47-L55)). So a manual init after auto-init replaces it.
- Mixed SDK module versions make init **throw** `IllegalStateException` ([InitUtil.java#L28-L41](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/util/InitUtil.java#L28-L41)).

### 2.4 Scopes (8.x)

- Scope types: `CURRENT, ISOLATION, GLOBAL, COMBINED` ([ScopeType.java](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/ScopeType.java)).
- Android runs in **global hub mode**: `Sentry.getCurrentScopes()` returns the root scopes on every thread instead of forking ([Sentry.java#L116-L134](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/Sentry.java#L116-L134)). Inferred effect: tags and user set on any thread apply to all threads.
- Default write target on Android is the **current** scope ([AOI#L124](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/AndroidOptionsInitializer.java#L124)); the core default is `ISOLATION` ([SentryOptions.java#L641](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryOptions.java#L641)).
- `Sentry.getCurrentHub()` / `IHub` remain as deprecated wrappers ([Sentry.java#L89-L98](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/Sentry.java#L89-L98)).

### 2.5 SentryClient

`SentryClient.captureEvent` ([SentryClient.java#L94-L300](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryClient.java#L94-L300)):

1. Apply scope data (not for `Cached` hints), run event processors and `beforeSend`.
2. Update the session (errored/crashed) **before** sampling ([#L180-L184](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryClient.java#L180-L184)). A dropped event can still send a session update.
3. `sampleRate` check; drops are counted as `sample_rate` client reports ([#L186-L198](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryClient.java#L186-L198)).
4. For an error/crash that is not backfilled or cached: `beforeErrorSampling`, then `replayController.captureReplay(isCrashed)`, then the replay id goes on the scope and on the transaction baggage ([#L218-L260](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryClient.java#L218-L260)).
5. Build the envelope (event + attachments + session + trace header) and `transport.send` ([#L262-L272](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryClient.java#L262-L272), [#L1008-L1011](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryClient.java#L1008-L1011)).
6. On crash/abnormal hints, force-finish a running transaction with `ABORTED` so it is persisted ([#L285-L300](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryClient.java#L285-L300)).

The transport is `AsyncHttpTransport` from `AsyncHttpTransportFactory` when no factory is set ([SentryClient.java#L54-L56](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/SentryClient.java#L54-L56)).

## 6. Crash handling

### 6.1 JVM uncaught exceptions

From [UncaughtExceptionHandlerIntegration.java#L110-L160](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/UncaughtExceptionHandlerIntegration.java#L110-L160):

1. Builds a `FATAL` event with mechanism `handled = false` ([#L119-L120](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/UncaughtExceptionHandlerIntegration.java#L119-L120), [#L167-L170](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/UncaughtExceptionHandlerIntegration.java#L167-L170)).
2. Hint `UncaughtExceptionHint(flushTimeoutMillis)`. If no transaction is active, the event id is marked flushable ([#L116-L126](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/UncaughtExceptionHandlerIntegration.java#L116-L126)).
3. `captureEvent` puts the envelope on the transport queue. The **crashing thread blocks** in `waitFlush()` until the transport worker has written the envelope file and called `markFlushed()`, or until `flushTimeoutMillis` (Android: 4000 ms) passes ([#L136-L144](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/UncaughtExceptionHandlerIntegration.java#L136-L144); marking at [AsyncHttpTransport.java#L276-L289](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/transport/AsyncHttpTransport.java#L276-L289)).
4. Storing an envelope with this hint also writes the `last_crash` marker ([EnvelopeCache.java#L201-L205](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/cache/EnvelopeCache.java#L201-L205)) and, within 2 s of SDK init, a `startup_crash` marker ([AndroidEnvelopeCache.java#L66-L90](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/cache/AndroidEnvelopeCache.java#L66-L90)).
5. Then it chains to the previous default handler; with no previous handler and `printUncaughtStackTrace` = true it prints the trace ([#L151-L158](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/UncaughtExceptionHandlerIntegration.java#L151-L158)).
6. The worker then tries the POST; the process usually dies first, the file stays and is sent next launch (inferred).

So "written synchronously" means the crashing thread waits up to 4 s for the transport thread's disk write. The write is not on the crashing thread (read).

### 6.2 Native (NDK) crashes

- `NdkIntegration` calls `io.sentry.android.ndk.SentryNdk.init` by reflection ([NdkIntegration.java#L20](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/NdkIntegration.java#L20)).
- `SentryNdk.init` waits up to 2000 ms for native libs, then passes DSN, debug, **outbox path**, release, environment, dist, `maxBreadcrumbs`, native SDK name, handler strategy, traces sample rate (0 if unset) and NDK app-hang settings to sentry-native ([SentryNdk.java#L43-L80](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-ndk/src/main/java/io/sentry/android/ndk/SentryNdk.java#L43-L80)).
- sentry-native writes crash envelopes into `<cacheDir>/outbox/` and keeps state under `<cacheDir>/.sentry-native/` (marker `.sentry-native/last_crash`, [EnvelopeCache.java#L69](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/cache/EnvelopeCache.java#L69)). The native file names are defined in sentry-native, not read here (**uncertain**).
- With `enableScopeSync` = true, Java scope changes are mirrored to native through `NdkScopeObserver` ([NdkScopeObserver.java#L23](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-ndk/src/main/java/io/sentry/android/ndk/NdkScopeObserver.java#L23)).
- Next launch: `SendCachedEnvelopeIntegration` (outbox) runs `OutboxSender`, which re-captures items (events go through `captureEvent` again) and deletes the file. It skips `session*`, `previous_session*` and `startup_crash` ([OutboxSender.java#L100-L105](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/OutboxSender.java#L100-L105), [#L147](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry/src/main/java/io/sentry/OutboxSender.java#L147)).
- With `enableTombstone` (API 31+), the OS tombstone is merged with the outbox native event if both are within `tombstoneMergeTimeThresholdMillis` = 5000 ([SentryAndroidOptions.java#L306-L313](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/SentryAndroidOptions.java#L306-L313)).
