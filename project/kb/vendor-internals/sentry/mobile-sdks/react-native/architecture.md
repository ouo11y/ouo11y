## 2. JS layer

### 2.1 Init (`Sentry.init`)

Read in [sdk.tsx#L71-L220](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/sdk.tsx#L71-L220):

1. Returns early when running inside the Metro dev server process ([L72](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/sdk.tsx#L72)).
2. Merges `__SENTRY_OPTIONS__` (the bundled `sentry.options.json`) under the passed options ([L82-L85](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/sdk.tsx#L82-L85)).
3. `enableNative` = user value AND `NATIVE.isNativeAvailable()` ([L90-L91](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/sdk.tsx#L90-L91)).
4. If native is on, patches the **global** and **isolation** scopes for scope sync to native ([L94-L97](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/sdk.tsx#L94-L97)). The current scope (`withScope`) is not patched (read: only these two calls exist).
5. Picks the transport: user transport, else `makeNativeTransport` when native is available, else `makeFetchTransport` from @sentry/react ([L149-L154](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/sdk.tsx#L149-L154)).
6. If `sentry.options.json` is bundled, it is a release build, and the user did not set `autoInitializeNativeSdk`, it sets `autoInitializeNativeSdk = false` (native is expected to be already started) ([L167-L177](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/sdk.tsx#L167-L177)).
7. `initAndBind(ReactNativeClient, options)` ([L194](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/sdk.tsx#L194)). `ReactNativeClient.init()` sets up integrations and then calls `NATIVE.initNativeSdk(...)` without awaiting it ([client.ts#L201-L204](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/client.ts#L201-L204), [L229-L291](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/client.ts#L229-L291)).

The client also sets `sdk.settings.infer_ip` to `auto` only when `sendDefaultPii` is true, else `never` ([client.ts#L58-L68](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/client.ts#L58-L68)), and defaults `parentSpanIsAlwaysRootSpan` to true ([L71-L72](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/client.ts#L71-L72)).

### 2.3 Error handlers

Read in [reactnativeerrorhandlers.ts](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/integrations/reactnativeerrorhandlers.ts):
- `ErrorUtils.setGlobalHandler` wraps RN's default handler ([L162](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/integrations/reactnativeerrorhandlers.ts#L162)). Fatal: `level: fatal`, mechanism `{handled: false, type: 'onerror'}`. Non-fatal: `level: error`, `{handled: true, type: 'generic'}` ([L200-L214](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/integrations/reactnativeerrorhandlers.ts#L200-L214)).
- In release builds it then waits on `client.flush(shutdownTimeout || 2000)` before calling RN's default handler, which kills the app ([L235-L262](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/integrations/reactnativeerrorhandlers.ts#L235-L262)). In `__DEV__` it calls the default handler immediately ([L227-L232](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/integrations/reactnativeerrorhandlers.ts#L227-L232)).
- Unhandled rejections: Hermes `enablePromiseRejectionTracker` when available, else the rejection-tracking polyfill when `patchGlobalPromise` ([L58-L106](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/integrations/reactnativeerrorhandlers.ts#L58-L106)). They are captured with **`handled: true`** on purpose, so they do not count as crashes ([L114-L121](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/integrations/reactnativeerrorhandlers.ts#L114-L121)).

### 2.4 Tracing on the JS side

- Native tracing is disabled on both platforms: iOS sets `tracesSampleRate = nil`, `tracesSampler = nil` and also removes these keys before parsing ([RNSentryStart.m#L229-L239](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/ios/RNSentryStart.m#L229-L239), [RNSentry.mm#L180-L185](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/ios/RNSentry.mm#L180-L185)); Android sets both to null ([RNSentryStart.java#L351-L353](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/android/src/main/java/io/sentry/react/RNSentryStart.java#L351-L353)). iOS turns on "hybrid SDK mode" for app start and frames so they are measured without native tracing ([RNSentryStart.m#L273-L281](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/ios/RNSentryStart.m#L273-L281)).
- `reactNativeTracingIntegration`: `traceXHR` true, `traceFetch` false (RN fetch is an XHR polyfill), `tracePropagationTargets` default **`[/.*/]`** on native, so `sentry-trace` and `baggage` go on every outgoing request unless the user sets targets ([reactnativetracing.ts#L72-L83](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/reactnativetracing.ts#L72-L83), [L146](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/reactnativetracing.ts#L146)).
- Idle root spans: `idleTimeout` 1000 ms, `finalTimeout` 600000 ms ([span.ts#L30-L49](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/span.ts#L30-L49)). A root span is cancelled when the app goes to the background (iOS: deferred on `inactive`) ([onSpanEndUtils.ts#L234-L305](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/onSpanEndUtils.ts#L234-L305)).
- Navigation: `reactNavigationIntegration` (`routeChangeTimeoutMs` 1000) ([reactnavigation.ts#L210-L218](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/reactnavigation.ts#L210-L218)), Expo Router, Wix navigation.
- App start: JS calls `NATIVE.fetchNativeAppStart()` once and attaches cold/warm app start to the first root span. It drops app start older than 60 s or longer than 60 s, or when the gap to first display is more than 5 s (non-standalone) ([appStart.ts#L73-L86](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/integrations/appStart.ts#L73-L86), [L645](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/integrations/appStart.ts#L645)).
- TTID/TTFD: `<TimeToInitialDisplay>` / `<TimeToFullDisplay>` render the native view `RNSentryOnDrawReporter`, which records a draw timestamp natively; JS pops it with `popTimeToDisplayFor('ttid-<spanId>')` ([timetodisplaynative.tsx#L11](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/timetodisplaynative.tsx#L11), [timeToDisplayIntegration.ts#L157](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/integrations/timeToDisplayIntegration.ts#L157), [L272](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/integrations/timeToDisplayIntegration.ts#L272)).
- Native frames: on every span start and end JS calls `fetchNativeFrames` (2 s timeouts) and sets `frames.total/slow/frozen` on spans ([nativeFrames.ts#L14-L28](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/integrations/nativeFrames.ts#L14-L28), [L87-L88](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/integrations/nativeFrames.ts#L87-L88), [L191-L192](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/integrations/nativeFrames.ts#L191-L192)).
- Stall tracking: a 50 ms JS timer loop, max 10 concurrent transactions ([stalltracking.ts#L20-L24](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/tracing/integrations/stalltracking.ts#L20-L24)).
- Touches: `TouchEventBoundary` adds `touch` breadcrumbs and rage-tap detection (default on) ([touchevents.tsx#L130-L150](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/touchevents.tsx#L130-L150)).

### 2.5 Replay: what JS does and does not do

Read in [replay/mobilereplay.ts](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/replay/mobilereplay.ts):
- JS does **not** capture frames. Recording is native. JS passes `mobileReplayOptions` into `initNativeSdk` ([client.ts#L264-L272](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/client.ts#L264-L272)). RegExp URL patterns are sent as their `source` strings ([mobilereplay.ts#L345-L350](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/replay/mobilereplay.ts#L345-L350)).
- On-error replay: in `beforeSend` JS reads `getCurrentReplayId()` and sets `contexts.replay.replay_id` ([L447-L493](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/replay/mobilereplay.ts#L447-L493)). In `afterSendEvent` it calls `NATIVE.captureReplay(isHardCrash)` to flush the buffer ([L495-L524](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/replay/mobilereplay.ts#L495-L524), [L731-L735](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/replay/mobilereplay.ts#L731-L735)). The source says the event is tagged before the native on-error sampling roll, so an event can carry a `replay_id` whose replay is never uploaded ([L441-L445](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/replay/mobilereplay.ts#L441-L445)).
- DSC: on `createDsc` JS adds `replay_id` from a **JS-side cache** of the native id ([L643-L653](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/replay/mobilereplay.ts#L643-L653)). The cache is reset only by JS replay controls and flushes ([L382-L427](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/replay/mobilereplay.ts#L382-L427)). Inferred: when native rotates the replay on its own (new session after background), the cache keeps the old id. This matches the stale `trace.replay_id` on transactions seen in the 8.30 iOS capture (lead from `kb-archive/sentry-react-native-demo.md`; not re-run on 8.34).

### 3.2 What native owns

- Crashes: SentryCrash on iOS (`enableCrashHandler`), UncaughtExceptionHandler + NDK on Android. `enableNativeCrashHandling: false` sets `enableCrashHandler = NO` on iOS ([RNSentryStart.m#L156-L163](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/ios/RNSentryStart.m#L156-L163)) but on Android removes the UncaughtExceptionHandler, **ANR** and NDK integrations ([RNSentryStart.java#L252-L262](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/android/src/main/java/io/sentry/react/RNSentryStart.java#L252-L262)).

## 4. How events cross the bridge

### 4.1 Transport

1. `ReactNativeClient.sendEnvelope` attaches pending JS client-report outcomes to the envelope, then calls `transport.send` and returns `{}` immediately ([client.ts#L165-L196](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/client.ts#L165-L196)).
2. `NativeTransport.send` puts `NATIVE.sendEnvelope(envelope)` in a `PromiseBuffer` (size `maxQueueSize`, default 30) ([transports/native.ts#L13](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/transports/native.ts#L13), [L26-L39](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/transports/native.ts#L26-L39)). It does not use @sentry/core `createTransport`, and returns no HTTP status.
3. `NATIVE.sendEnvelope` serialises the envelope to bytes in JS: header JSON + `\n`, then per item a header with `content_type` and `length` set, payload bytes, `\n` ([wrapper.ts#L225-L280](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/wrapper.ts#L225-L280)). String payloads get `text/plain`, Uint8Array payloads keep their `content_type` (default `application/octet-stream`), objects become JSON. Before that, `_processItem` maps level `log` → `debug` and, on Android, wraps `message` into `{message}` ([L1175-L1192](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/wrapper.ts#L1175-L1192)).
4. `hardCrashed` is true when any JSON item has an exception with mechanism `{handled: false, type: 'onerror'}` ([misc.ts#L11-L20](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/misc.ts#L11-L20)).
5. The bytes are base64-encoded **in JS** and passed as a string: `RNSentry.captureEnvelope(base64, {hardCrashed})` ([wrapper.ts#L282](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/wrapper.ts#L282), spec [NativeRNSentry.ts#L15-L20](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/NativeRNSentry.ts#L15-L20)). The module is resolved via `TurboModuleRegistry` on the New Architecture, else `NativeModules.RNSentry` ([wrapper.ts#L43-L47](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/wrapper.ts#L43-L47)).
6. iOS: base64 decode, `envelopeFromData`; in release builds `hardCrashed` → `store` (synchronous write to disk, sent on a later launch), else `capture` (send). Debug builds always `capture` ([RNSentry.mm#L638-L660](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/ios/RNSentry.mm#L638-L660)). These call `hub.storeEnvelope` / `hub.captureEnvelope` ([SentryInternalEnvelopeApi.swift#L17-L24](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/HybridSDK/SentryInternalEnvelopeApi.swift#L17-L24)).
7. Android: base64 decode; non-crash, debuggable app, or no disk cache → `InternalSentrySdk.captureEnvelope(bytes, !hardCrashed)`; release hard crash → `storeHardCrashEnvelope` writes the envelope plus a `crashed` session to the disk cache on the calling thread ([RNSentryModuleImpl.java#L647-L735](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/android/src/main/java/io/sentry/react/RNSentryModuleImpl.java#L647-L735)). New in 8.33.0 ([CHANGELOG.md#L53-L54](https://github.com/getsentry/sentry-react-native/blob/8.34.0/CHANGELOG.md#L53-L54)).
8. The native hub adds a `session` item when the envelope holds an `event` of level ≥ error: errors+1 for handled, `crashed` (and, on `capture`, a new session) for unhandled ([SentryHub.m#L931-L1087](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Sentry/SentryHub.m#L931-L1087); Android [InternalSentrySdk.java#L167-L210](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/InternalSentrySdk.java#L167-L210)). The native SDK does **not** enrich, sample or run `beforeSend` on these envelopes ([InternalSentrySdk.java#L150-L156](https://github.com/getsentry/sentry-java/blob/8.63.0/sentry-android-core/src/main/java/io/sentry/android/core/InternalSentrySdk.java#L150-L156)). The envelope header keeps the JS `sdk` (inferred: the repackaging code reuses `envelope.header`).

## 8. Sequences

### 8.1 JS exception (non-fatal) → envelope on the wire

1. `captureException` or ErrorUtils handler (non-fatal: `handled: true`).
2. @sentry/core pipeline in JS: integrations' `processEvent` (DeviceContext does a bridge call and merges native breadcrumbs/contexts; Release; SdkInfo), `beforeSend` (MobileReplay wraps it to tag `contexts.replay.replay_id`), then `sampleRate`.
3. `sendEnvelope` adds a pending `client_report` item if any outcomes exist ([client.ts#L169-L171](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/client.ts#L169-L171)).
4. `NativeTransport` → `NATIVE.sendEnvelope`: JS serialises and base64-encodes, `captureEnvelope(base64, {hardCrashed: false})`.
5. Native: decode; hub adds a `session` update (errors+1); client captures → native transport writes to the disk cache and sends over HTTP (gzip). Caching/retry rules: [../ios/reliability.md](../ios/reliability.md), [../android/reliability.md](../android/reliability.md).
6. `afterSendEvent` in JS → `NATIVE.captureReplay(false)` if a replay was linked → native uploads the buffered replay as `replay_video` envelopes.

### 8.2 JS fatal (release build)

1. ErrorUtils handler: `level: fatal`, `{handled: false, type: 'onerror'}`.
2. Same JS pipeline; `hardCrashed: true` on the bridge call.
3. iOS release: `hub.storeEnvelope`, session ended `crashed`, no new session → disk only. Android release: `storeHardCrashEnvelope` writes envelope + crashed session to the disk cache and deletes the current-session file.
4. JS waits up to `shutdownTimeout` (2 s) for the flush, then calls RN's default handler, which terminates the app.
5. Next launch: the native SDK sends cached envelopes. This is inferred from source. The 8.30 iOS capture saw the event before the process died (lead). Why is *uncertain*: possibly the native SDK sent cached envelopes after another successful request in the 2 s window.

### 8.3 Native crash → next launch

1. SentryCrash (iOS) / UncaughtExceptionHandler or NDK (Android) writes a crash report with the native scope (which contains the synced JS user, tags, breadcrumbs, contexts).
2. Process dies. JS does nothing.
3. Next launch: native SDK starts (from JS `Sentry.init`, or earlier from `RNSentrySDK`), turns the report into an `event` (`sdk` = `sentry.cocoa.react-native` / `sentry.java.android.react-native` / `sentry.native.android.react-native`) plus the `crashed` session update, and sends it. iOS order observed on 8.30: new session `init` first, then crash event + `crashed` session, then the crashed session's last replay segment (lead).
4. JS can read `Sentry.crashedLastRun()`.

## 9. Footprint

- No per-platform SDK size numbers are published in the repo. The repo runs a size analysis workflow on the sample app (Android AAB arm64, iOS) whose results are uploaded to Sentry, not stored in git ([.github/workflows/size-analysis.yml](https://github.com/getsentry/sentry-react-native/blob/8.34.0/.github/workflows/size-analysis.yml)).
- iOS: the pod stages a prebuilt `Sentry.xcframework` 9.33.0 ([RNSentry.podspec#L71](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/RNSentry.podspec#L71)). Android: `api "io.sentry:sentry-android:8.62.0"` ([android/build.gradle#L188-L193](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/android/build.gradle#L188-L193)), which pulls in the NDK and replay modules.
- Replay overhead (docs, Pocket Casts benchmark, SDK versions not stated): iOS iPhone 14 Pro CPU 4% → 13%, memory 102 → 121 MB, 10 KB/s; Android Pixel 2XL CPU 36% → 42%, memory 255 → 265 MB, 7 KB/s. Excluding `sentry-android-replay` saves about 40 KB compressed. The RN replay layer is described as a thin wrapper ([Session Replay performance overhead](https://docs.sentry.io/platforms/react-native/session-replay/performance-overhead/), accessed 2026-11-10).
- JS bundle: 8.33.0 compiles to ES2018 to reduce size ([CHANGELOG.md#L48](https://github.com/getsentry/sentry-react-native/blob/8.34.0/CHANGELOG.md#L48)). No number given.
- Per-event bridge cost (inferred from code): each JS event does at least one `fetchNativeDeviceContexts` call, plus a JS-side byte copy per item and a base64 string of the whole envelope. The JS encode polyfill is noted as slow above about 2 MB when Hermes lacks `TextEncoder` ([encodePolyfill.ts#L25-L31](https://github.com/getsentry/sentry-react-native/blob/8.34.0/packages/core/src/js/transports/encodePolyfill.ts#L25-L31)).
