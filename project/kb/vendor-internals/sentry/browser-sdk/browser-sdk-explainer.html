Sentry browser SDK internals

@sentry/browser and @sentry/react 11.11.0 (2026-11-05), compared with 10.78.0. Wire observed against self-hosted Sentry 26.10.0 on 2026-11-10. Step 6 vendor research. Details and sources: index.md.

Six findings first

  • Spans are streamed by default in 11.x. traceLifecycle defaults to 'stream': spans go out as span v2 containers with typed attributes, not transaction events. beforeSendTransaction does nothing unless you set 'static'. (configuration.md, wire-capture.md)
  • Data collection flipped. With no dataCollection, v11 sends user info, cookies, headers and asks Relay to infer the IP (infer_ip:"auto", session ip_address:"{{auto}}"). Logs and metrics have no on/off option any more.
  • Replay is zlib, not gzip. Each segment is {"segment_id":N}\n + a zlib stream (78 9c). Segments flush 5 to 5.5 s after activity; a tab closed inside that window loses the segment.
  • Client reports only on page hide. They are the only loss signal and flush() does not send them.
  • CORS decides whether rate limits work. A 429 without Access-Control-Expose-Headers is invisible to the SDK; it keeps sending and reports network_error.
  • The DSC rides only on some envelopes. Errors, spans, transactions and feedback carry the trace header; replay, profile, log, metric and session envelopes do not, so they link through ids in their payloads.
