## 0. Foundations: how a frame is produced

### 0.1 Android (AOSP, open source)

One frame on Android, in order:

1. Something calls `invalidate()` / `requestLayout()`. `ViewRootImpl.scheduleTraversals()` posts a sync barrier and a `CALLBACK_TRAVERSAL` to the Choreographer. [ViewRootImpl.java#L2888-L2897](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewRootImpl.java#L2888-L2897)
2. On vsync, `Choreographer.doFrame()` runs callbacks in order INPUT → ANIMATION → TRAVERSAL. [Choreographer.java#L846-L962](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/Choreographer.java#L846-L962) (input at L938, animation at L941, traversal at L945); `CALLBACK_TRAVERSAL = 3` [L259](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/Choreographer.java#L259)
3. The traversal runs `ViewRootImpl.performTraversals()`: measure, layout, then draw. [ViewRootImpl.java#L3350](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewRootImpl.java#L3350) → `performLayout` at [L4040](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewRootImpl.java#L4040) → `performDraw` at [L4303](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewRootImpl.java#L4303)
4. `ViewRootImpl.draw()` **fires `ViewTreeObserver.dispatchOnDraw()` before** recording the frame, then hands the tree to the hardware renderer. [ViewRootImpl.java#L5499-L5704](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewRootImpl.java#L5499-L5704) (`dispatchOnDraw` at [L5572](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewRootImpl.java#L5572), `mThreadedRenderer.draw` at [L5659](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewRootImpl.java#L5659)). This is the hook every Android replay SDK below uses: `OnDrawListener` means "a frame is about to be drawn", not "pixels are on screen".
5. `ViewTreeObserver.addOnDrawListener` / `dispatchOnDraw`: [ViewTreeObserver.java#L773-L790](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewTreeObserver.java#L773-L790), [#L1230-L1240](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ViewTreeObserver.java#L1230-L1240)
6. `ThreadedRenderer.draw()` rebuilds display lists (`updateRootDisplayList` → each `View.updateDisplayListIfDirty`) and calls `syncAndDrawFrame`, which hands the frame to the RenderThread. [ThreadedRenderer.java#L795-L827](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ThreadedRenderer.java#L795-L827), [#L689-L700](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/ThreadedRenderer.java#L689-L700); [View.updateDisplayListIfDirty L23630](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/View.java#L23630)
7. `View.draw(Canvas)` is the software path that `CanvasStrategy`-style capture replays into a `Picture`. [View.java#L24814-L25041](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/View.java#L24814-L25041)
8. `PixelCopy.request(Window|SurfaceView|Surface, Bitmap, …)` copies the composited buffer of a window or surface asynchronously. [PixelCopy.java#L109](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/graphics/java/android/view/PixelCopy.java#L109) (SurfaceView), [#L156](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/graphics/java/android/view/PixelCopy.java#L156) (Surface), [#L223-L226](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/graphics/java/android/view/PixelCopy.java#L223-L226) (Window). A window copy leaves holes where `SurfaceView`s are, which is why Sentry composites SurfaceViews separately (section 2).
9. Every root view of the process lives in `WindowManagerGlobal.mViews`; Sentry swaps this list via reflection to learn about new windows (section 2). [WindowManagerGlobal.java#L144](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/view/WindowManagerGlobal.java#L144)

Jetpack Compose (androidx at `3aea5205`):

[AndroidComposeView.android.kt#L285](https://github.com/androidx/androidx/blob/3aea5205fde166e0f234d814697111cebf0be582/compose/ui/ui/src/androidMain/kotlin/androidx/compose/ui/platform/AndroidComposeView.android.kt#L285). Keys used for masking: `Text` [L244](https://github.com/androidx/androidx/blob/3aea5205fde166e0f234d814697111cebf0be582/compose/ui/ui/src/commonMain/kotlin/androidx/compose/ui/semantics/SemanticsProperties.kt#L244), `EditableText` [L265](https://github.com/androidx/androidx/blob/3aea5205fde166e0f234d814697111cebf0be582/compose/ui/ui/src/commonMain/kotlin/androidx/compose/ui/semantics/SemanticsProperties.kt#L265), `Password` [L291](https://github.com/androidx/androidx/blob/3aea5205fde166e0f234d814697111cebf0be582/compose/ui/ui/src/commonMain/kotlin/androidx/compose/ui/semantics/SemanticsProperties.kt#L291), `Role` [L217](https://github.com/androidx/androidx/blob/3aea5205fde166e0f234d814697111cebf0be582/compose/ui/ui/src/commonMain/kotlin/androidx/compose/ui/semantics/SemanticsProperties.kt#L217), `InvisibleToUser` [L120](https://github.com/androidx/androidx/blob/3aea5205fde166e0f234d814697111cebf0be582/compose/ui/ui/src/commonMain/kotlin/androidx/compose/ui/semantics/SemanticsProperties.kt#L120).

### 0.2 iOS (closed source, docs)

- **Run loop and Core Animation commit.** UIKit changes are batched into an implicit `CATransaction` and committed to the render server near the end of a main run-loop turn. Docs: CATransaction <https://developer.apple.com/documentation/quartzcore/catransaction>, Core Animation Programming Guide <https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/CoreAnimation_guide/CoreAnimationBasics/CoreAnimationBasics.html> **(closed source, docs)**. The specific "CA commit observer runs at order 2,000,000" is **not documented by Apple**; it is stated in a PostHog code comment ([ApplicationRunLoopPublisher.swift#L85-L109](https://github.com/PostHog/posthog-ios/blob/3.94.3/PostHog/ApplicationRunLoopPublisher.swift#L85-L109)).
- **CFRunLoopObserver** (what Sentry and PostHog actually use, not CADisplayLink): <https://developer.apple.com/documentation/corefoundation/cfrunloopobserver>, <https://developer.apple.com/documentation/corefoundation/1542816-cfrunloopobservercreatewithhandl> **(closed source, docs)**.
- **CADisplayLink** (vsync timer; none of the four iOS SDKs read here uses it for replay pacing): <https://developer.apple.com/documentation/quartzcore/cadisplaylink> **(closed source, docs)**.
- **`UIView.drawHierarchy(in:afterScreenUpdates:)`** (snapshot of the view as rendered, includes visual effects): <https://developer.apple.com/documentation/uikit/uiview/drawhierarchy(in:afterscreenupdates:)> **(closed source, docs)**.
- **`CALayer.render(in:)`** (re-renders the layer tree on the CPU; skips some effects): <https://developer.apple.com/documentation/quartzcore/calayer/render(in:)>; `CALayer.presentation()` <https://developer.apple.com/documentation/quartzcore/calayer/presentation()> **(closed source, docs)**.
- **UIGraphicsImageRenderer** (Sentry replaced it because of its context cache): <https://developer.apple.com/documentation/uikit/uigraphicsimagerenderer> **(closed source, docs)**.
- **SwiftUI hosting**: `UIHostingController` <https://developer.apple.com/documentation/swiftui/uihostingcontroller>. SwiftUI draws into private `_UIGraphicsView`/`CGDrawingView` subviews or (iOS 26) bare CALayers; none of that is documented **(closed source, docs)**.
- **Touches**: `UIApplication.sendEvent(_:)` <https://developer.apple.com/documentation/uikit/uiapplication/sendevent(_:)> (all three iOS SDKs swizzle it) **(closed source, docs)**.
- **Video**: `AVAssetWriter` <https://developer.apple.com/documentation/avfoundation/avassetwriter>, `requestMediaDataWhenReady(on:using:)` <https://developer.apple.com/documentation/avfoundation/avassetwriterinput/requestmediadatawhenready(on:using:)> **(closed source, docs)**.

## 1. Sentry iOS (sentry-cocoa 9.33.0): video replay

### 1.1 Integration start

1. The integration init wires everything up: reads options, builds the view photographer and two utility queues (asset worker priority −1, processing −2), sets up touch tracking, recovers the last replay from disk, registers as a session listener and observes `didBecomeActive` / `UIScene.didActivate` as retry triggers. [SentrySessionReplayIntegration.swift#L78-L126](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayIntegration.swift#L78-L126); queues [#L170-L176](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayIntegration.swift#L170-L176)
2. Renderer choice: `enableViewRendererV2` (default **true**) → `SentryViewRendererV2`, else `SentryDefaultViewRenderer`; the same flag picks mask renderer V2. [#L145-L168](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayIntegration.swift#L145-L168); defaults [SentryReplayOptions.swift#L12-L20](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentryReplayOptions.swift#L12-L20)
3. On release-health session start, sample once: `startedAsFullSession = random < sessionSampleRate`. If not sampled and `onErrorSampleRate == 0`, stop. Otherwise mark `isPendingStart` and try to get a window. [#L239-L262](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayIntegration.swift#L239-L262)
4. Window resolution retries on lifecycle notifications (SwiftUI can init the SDK before `UIApplication.shared` exists). [#L264-L316](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayIntegration.swift#L264-L316)
5. `startWithOptions` creates the replay folder, the `SentryOnDemandReplay` maker (bit rate, size scale, frame rate, cache size = `duration × fps + 1` frames, i.e. 6 for session, 31 for buffer), the `SentrySessionReplay`, and starts it on the first window. [#L333-L388](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayIntegration.swift#L333-L388)

### 1.2 Frame scheduler: a run-loop observer, not CADisplayLink, not a timer

1. The default scheduler is `DefaultSentrySessionReplayRunLoopCaptureScheduler` ([SentryDependencyContainer.swift#L104](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/SentryDependencyContainer.swift#L104)).
2. It installs a `CFRunLoopObserver` on the **main run loop, common modes, order `CFIndex.max`** (after every other observer, including CA's commit), watching `afterWaiting | beforeTimers | beforeSources | beforeWaiting | exit`. [SentrySessionReplayRunLoopCaptureScheduler.swift#L48-L79](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayRunLoopCaptureScheduler.swift#L48-L79)
3. It only fires a capture opportunity on `beforeWaiting`/`exit` **if the run loop actually did work** this turn (an idle loop never wakes the SDK). It reports whether the loop is in `.tracking` mode (scrolling). [#L95-L108](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayRunLoopCaptureScheduler.swift#L95-L108)
4. `captureFrameIfNeeded` gates the opportunity: paused/full-session-paused, maximum duration (60 min → `sessionReplayEnded`), screenshot in flight, pacing deadline. [SentrySessionReplay.swift#L469-L557](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplay.swift#L469-L557)
5. **Pacing**: base interval `1 / frameRate` = 1 s ([#L559-L561](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplay.swift#L559-L561), `frameRate` default 1 at [SentryReplayOptions.swift#L42-L45](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentryReplayOptions.swift#L42-L45)). **Adaptive backoff**: if the main-thread part of a capture (redact + render) takes ≥ 150 ms, the interval doubles up to 2 s; faster captures halve it again. [CapturePacing #L649-L674](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplay.swift#L649-L674), [updateAdaptiveScreenshotInterval #L700-L715](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplay.swift#L700-L715)
6. **Animation deferral**: before capturing, `SentrySessionReplayCaptureGuard` walks the tree. An active interaction (scroll view dragging/decelerating, tracking `UIControl`, gesture recognizer began/changed) captures at the base rate without backoff; **≥ 4 running `CAAnimation`s** defer the capture by 250 ms, up to 1 s. [SentrySessionReplayCaptureGuard.swift#L7-L48](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplayCaptureGuard.swift#L7-L48), [screenshotDeferralDecision #L676-L698](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplay.swift#L676-L698)

### 1.3 Screenshot: drawHierarchy by default, `layer.render(in:)` when "fast"

1. `takeScreenshot` marks `processingScreenshot`, asks the delegate for the screen name, and calls the photographer. [SentrySessionReplay.swift#L888-L937](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentrySessionReplay.swift#L888-L937)
2. `SentryViewPhotographer.timedImage`: **on the main thread** compute redact regions, then render; then **on a background queue** draw masks at scale 1. [SentryViewPhotographer.swift#L66-L96](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryViewPhotographer.swift#L66-L96)
3. Renderers:
   - V1 `SentryDefaultViewRenderer`: `UIGraphicsImageRenderer` + `drawHierarchy(in:afterScreenUpdates: false)`. [SentryDefaultViewRenderer.swift#L7-L14](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryDefaultViewRenderer.swift#L7-L14)
   - V2 (default) `SentryViewRendererV2`: own `SentryGraphicsImageRenderer` (raw `calloc` + `CGContext`, no context cache) at screen scale; draws with `drawHierarchy(afterScreenUpdates: false)`, or with **`view.layer.render(in:)`** when `enableFastViewRendering` is on (the "experimental view renderer", default off). [SentryViewRendererV2.swift#L7-L29](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryViewRendererV2.swift#L7-L29), [SentryGraphicsImageRenderer.swift#L17-L93](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryGraphicsImageRenderer.swift#L17-L93); option docs ("~160 ms → ~30 ms", "can lead to rendering issues") [SentryReplayOptions.swift#L280-L310](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Integrations/SessionReplay/SentryReplayOptions.swift#L280-L310)
4. `afterScreenUpdates: false` means the image is the **last committed frame**; redact regions come from the layer tree at the same moment, so the two can drift during animation (hence the deferral above).

### 1.4 Redaction: a CALayer walk building ordered regions

1. Class lists built at init: `maskAllText` → `UILabel`, `UITextView`, `UITextField`, RN `RCTTextView`/`RCTParagraphComponentView`, SwiftUI `CGDrawingView` (and a base64-obfuscated private name for iOS < 18); `maskAllImages` → `UIImageView`, a private SF-Symbol hit-testing view, `SwiftUI._UIGraphicsView` **only when its layer is `SwiftUI.ImageLayer`**, `RCTImageView`. Always: `PDFView`, `WKWebView`, `UIWebView`, `SFSafariView`, `AVPlayerView`, a SwiftUI List background decoration view. Ignored by default: `UISlider`, `UISwitch`. [SentryUIRedactBuilder.swift#L136-L245](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryUIRedactBuilder.swift#L136-L245)
2. **iOS 26 (Liquid Glass) SwiftUI**: text, images and shapes are bare CALayers with no UIView, so a second list matches layer class names (`CGDrawingLayer`, `SwiftUI.ImageLayer`, `ColorShapeLayer`). [#L255-L290](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryUIRedactBuilder.swift#L255-L290), [shouldRedactLayer #L527-L530](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryUIRedactBuilder.swift#L527-L530)
3. `redactRegionsFor(view:)` starts at the **presentation layer** of the window and recurses over `CALayer.sublayers` sorted by `zPosition` (not `UIView.subviews`). SwiftUI-modifier regions are moved last so they always win; the list is reversed so clips apply before masks. [#L448-L472](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryUIRedactBuilder.swift#L448-L472)
4. Per layer (`mapRedactRegion`): skip hidden / opacity 0; if the layer's delegate is a `UIView`, decide ignore/redact (per-instance `maskView`/`unmaskView`, class lists, `UIImageView` exemptions); a redacted view that clips to bounds stops recursion, otherwise its subtree is force-redacted; a non-redacted **opaque** view either clears all collected regions (if it covers the whole root) or adds a `clipOut`; `masksToBounds` layers emit `clipBegin`/`clipEnd`; unreadable sublayers (ObjC exception) fail closed by redacting the whole layer. [#L555-L707](https://github.com/getsentry/sentry-cocoa/blob/9.33.0/Sources/Swift/Core/Tools/ViewCapture/SentryUIRedactBuilder.swift#L555-L707)

### 3.1 PostHog iOS: scheduling

1. `startRecording` checks triggers and sampling, then `startCaptureScheduler`, subscribes to `onApplicationEventWillDispatch` (touches) and background/foreground. [PostHogReplayCaptureBackoff.swift#L11-L91](https://github.com/PostHog/posthog-ios/blob/3.94.3/PostHog/Replay/PostHogReplayCaptureBackoff.swift#L11-L91), [structureFingerprint #L2044-L2120](https://github.com/PostHog/posthog-ios/blob/3.94.3/PostHog/Replay/PostHogReplayIntegration.swift#L2044-L2120)

### 3.2 PostHog iOS: wireframe mode (view → node)
