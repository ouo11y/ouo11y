What to record

Pixels or structure, at the level of real recorders. There are four families. Here all four record the same screen, side by side, with what goes on the wire.

Builds on: Pixels versus structure · Masking: data versus geometry

Lesson 1 ended with a split: what you can read (a tree) versus what you can only see (pixels). Every replay technique sits somewhere on that line. There are four families, and each one answers "what do we write down?" differently:

  1. Serialise the tree, then diff it. Write the document structure as text once (a full snapshot), then write only what changed. The player rebuilds a real, live copy. This is rrweb, and every web recorder.
  2. Wireframes. Walk the native view tree and turn each view into a typed rectangle: text, image, shape, input, with position and style. The player draws rectangles that look like the app; it never rebuilds the real UI. Datadog, PostHog wireframe mode.
  3. Pictures: screenshots or video. Copy the pixels, paint boxes over private things, compress like images or like a movie. The player shows images. Sentry (video), PostHog screenshot mode, OpenReplay mobile, and ouo's current mobile SDK (JPEG frames with tile patches).
  4. Draw commands. Record the drawing instructions the UI issued (drawRect, drawText, drawImage) instead of their result. The player re-executes them. This is how rrweb records <canvas>, how Sentry Android's canvas strategy masks, and what Flutter's PictureRecorder produces internally.

The decisive difference is where the knowledge of "what is private" meets the data. In tree, wireframe and draw-command capture, masking is a transformation of structured data (a string becomes ***). In picture capture, masking is geometry: you compute rectangles from one tree walk and paint them on pixels copied at a slightly different moment. That gap is where picture-based recorders leak, and why their masking code is the biggest part of them.

  • Datadog wireframes ship images separately, keyed by an MD5 of a small greyscale rendition, so the same image is sent once (UIImage+SessionReplay.swift L19–60).
