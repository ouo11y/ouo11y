Masking: data versus geometry

Masking hides private things (names, card numbers, typed text) before the recording leaves the device. With structure it is a change to data. With pixels it is a box painted at a position. That difference decides which recorders can leak.

Masking as data


In tree, wireframe and draw-command recording, the private value passes through the recorder as data, and the recorder rewrites it before writing it down. Nothing about timing can make it slip: the string that leaves is the masked one.

The weak spot of data masking is elsewhere: it can only mask what it can read. A view the recorder cannot describe (a custom-drawn chart, a SwiftUI drawing view) has no string to replace, so recorders mask such views whole or leave them out.



Masking as geometry


A picture recorder has two separate facts: the tree walk says where the private text is, the pixel copy says what is on screen. Masking means painting rectangles from the first onto the second. If anything moves between the two moments, a scroll, an animation, a keyboard sliding up, the boxes land on the wrong pixels and part of the text is left visible.


The decisive difference is where the knowledge of "what is private" meets the data. In tree, wireframe and draw-command capture, masking is a transformation of structured data (a string becomes ***). In picture capture, masking is geometry: you compute rectangles from one tree walk and paint them on pixels copied at a slightly different moment. That gap is where picture-based recorders leak, and why their masking code is the biggest part of them.
