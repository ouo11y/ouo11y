# Fetching ouo-go while the repository is private

Learned 2026-11-14 (agent [plugin-bff](../../../agents/plugin-bff/index.md)), verifying `go get github.com/ouo11y/ouo11y/libs/ouo-go@v0.1.0` from a throwaway module outside the repository. The how-to for client repositories is in the [ouo-go README](../../../../libs/ouo-go/README.md#install-from-a-client-repository).

- A module in a subdirectory is tagged `libs/ouo-go/vX.Y.Z`, but `go get` takes the module path and `@vX.Y.Z`; Go maps one to the other.
- Without `GOPRIVATE`, Go asks `proxy.golang.org` first. For a private repository the proxy has nothing, Go falls back to `direct`, and `git ls-remote` runs with prompts disabled: `fatal: could not read Username for 'https://github.com': terminal prompts disabled`. On this Mac the first attempt also took more than two minutes before failing. Even when git does have credentials, the public checksum database cannot vouch for a private module, so the fix is always `GOPRIVATE=github.com/ouo11y/*` (it implies `GONOSUMDB` and `GONOPROXY`).
- With `GOPRIVATE` set, `go get` succeeded at once on this Mac although the global git config has no credential helper: Xcode's git ships one in `/Applications/Xcode.app/Contents/Developer/usr/share/git-core/gitconfig` (`credential.helper=osxkeychain`), which holds the founder's GitHub login. A Linux CI runner has nothing like it.
- In GitHub Actions the job's `GITHUB_TOKEN` reads only its own repository. A client repository needs a token with *Contents: read* on `ouo11y/ouo11y` (fine-grained PAT or GitHub App installation token) and a git `url.<base>.insteadOf` rewrite before `go` runs.
