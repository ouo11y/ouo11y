# Funnels and Home on the spec wire: what the records look like

> Which records and labels do funnels and the Home page read, and what surprised us on the live stack?

Verified 2026-11-13 in env `pdemo` (`ouo-env up pdemo --muninn`) with `@ouo11y/browser` 0.4.1 in Chrome and mobile-shaped OTLP sessions; encoded in `libs/ouo-go/funnel_test.go`, `overview_test.go` and `tests/e2e/plugin-bff` steps 6 and 7. Decision: [ADR-0025](../../../../docs/adr/0025-funnels-and-home-in-the-bff.md).

- **Navigations differ by SDK.** Web 0.4.x: `browser.navigation` with `url.full` (and `browser.navigation.type`, `same_document`); a History API `pushState` is enough to make one. Mobile 0.4.x: `navigation` with `url.path` (the screen path) and `ouo.navigation.kind=screen`. A page step reads `url_path`, else the path of `url_full`.
- **The browser SDK 0.4.1 sets no `ouo.platform`.** Its records have `telemetry_sdk_name="@ouo11y/browser"`, `telemetry_sdk_language="webjs"`, `browser_*` and `os_name="macOS"`, and no `ouo_platform` label, so a selector `{ouo_platform="web"}` matches nothing. `ouogo.PlatformOf` derives `web`; platform filters run in Go. The mobile SDK and the Sentry bridge do set it.
- **Custom events**: web `recordEvent(name, attrs)` keeps the name as given and adds no `ouo.event.custom`; mobile `recordEvent` adds `ouo.event.custom=true`. Event steps match by `event_name` only, so both count.
- **Exceptions**: `exception` with `exception_type`, `exception_message`, `ouo_exception_fingerprint`; mobile fatal ones carry `ouo_exception_fatal="true"`. Booleans and numbers arrive as strings (`"true"`, `"812.5"`).
- **Vitals** arrive as event records with numeric attributes as strings: `browser.web_vital` (`browser_web_vital_name` lower case, `browser_web_vital_value`), `ouo.app.start` (`ouo_app_start_type`, `ouo_app_start_duration_ms`), `ouo.screen.display` (`ouo_screen_ttid_ms`), `app.jank` (`ouo_frames_total`, `ouo_frames_slow`, `ouo_frames_frozen`). A short headless page reports FCP, LCP and TTFB; INP and CLS need interaction and layout shifts.
- **Span metrics in Mimir**: Tempo's metrics generator (already on in `deploy/compose/tempo/config.yaml`) writes `traces_spanmetrics_calls_total` and `traces_spanmetrics_latency_bucket` (seconds) with labels `service`, `span_name`, `span_kind` (`SPAN_KIND_SERVER`), `status_code` (`STATUS_CODE_ERROR`). Spans sent as OTLP/JSON to the Collector's `/v1/traces` with the project's Basic auth show up in Mimir within about 30 s; spans older than the generator's ingestion slack (30 s) are not counted, so test spans need current timestamps. Muninn's own server spans appear there too.
- **Why not LogQL metric queries for Home**: `count_over_time(...) by (session_id)` returns a series per session and Loki refuses past `max_query_series` (500 by default). Two log reads of at most 5,000 records each, aggregated in Go, are enough for a pilot and say `truncated` past that.
