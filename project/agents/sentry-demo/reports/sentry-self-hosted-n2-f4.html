Findings

  • N2 holds. Nothing in the forwarding path changes with a real Sentry. The only spec drift: the bridge copies every upstream response header, not just Content-Type, X-Sentry-Rate-Limits, Retry-After.
  • Startup console lines get no session (5 records, ouo.sentry.session_match = none): rum mode ..., [rollout] next launch and the log copy of Running "main" are sent before sentry-cocoa's session init. Since the bridge has no session to attach them to, the breadcrumb copy and the log copy of Running "main" are not de-duplicated. A bridge fix: hold log items with no session for a short while (as replay segments are held) and attach them to the next session of the same device.
  • Info messages counted as errors. RN's captureMessage carries a synthetic exception (stack trace attached), so the bridge emits an exception record. Sentry keeps level: info. The bridge should use level (info/debug/warning → custom sentry.message) before exception.values.
  • Seek flashes black in the ouo video player while the next segment loads; Sentry showed the frame at once. Preloading the neighbouring segments would fix it.
  • Two clocks (session-relative Timeline vs replay-relative activity list), already noted in project/kb/sentry-replay-taps.md.
  • MCP needs https; solved with TLS on the ouo-env proxy. Browsers warn on https://sentry.ouo.localhost until the founder trusts the proxy CA once.
  • Install: macOS bash 3.2 is too old for the installer; Docker Hub HEAD timeouts from the Docker VM break the build step (pre-pull with retries); the first user needs an email address to be able to sign in.
