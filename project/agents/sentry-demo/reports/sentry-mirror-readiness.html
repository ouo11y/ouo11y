Verdict

Conditional go. The forwarding path is transparent and robust in every test (byte-identical requests, Sentry's exact answers, mirror failures invisible to the SDK). Switch the production DSN only when all four hold:

  1. This pull request is merged and a collector image with it is deployed (without it there is no passthrough_upstream and no mirror).
  2. passthrough_upstream is set to the production ingest host, so a key or project the table does not know is forwarded, not answered 403 (an SDK deletes the envelope on a 403).
  3. Nothing in front of the bridge turns "bridge down" into a 5xx: either a fallback proxy that sends straight to Sentry (deployment guide), or the SDK reaches the bridge directly (refused connection = cached and retried).
  4. The DSN host is a name the founder controls, so rollback is a DNS or proxy change, not an app release.

Then check one event in production Sentry for the device's IP and geo (X-Forwarded-For), and watch ouo_sentry_envelopes_total{outcome="upstream_error"} and the proxy's fallback count for the first hour.

Fan-out design (ADR-0028)

SDK ──► bridge ──► production Sentry ──► answer ──► SDK      (unchanged; the only answer)
          │  after the answer is written, non-blocking:
          ├──► mirror queue (per mirror, count + shared byte budget) ──► N workers ──► preview Sentry   (timeout, never retried)
          └──► translate queue (count + byte budget) ──► Loki / Tempo / replay
          primary unreachable ──► SDK connection aborted, nothing queued (the SDK's retry is mirrored)
          table miss ──► passthrough_upstream (production), untranslated, not mirrored

What a mirror with its own sentry_project_id / public_key rewrites, and nothing else: the project id in the path; sentry_key in X-Sentry-Auth, Authorization and the query (sentry_secret dropped); the envelope header dsn when present (gzip/deflate re-compressed). Relay answers 400 project id header mismatch when the dsn does not match the request (verified on the sandbox), so this rewrite is needed. Mobile SDKs send no dsn: their mirror bodies stay byte-identical.

Failure injection

Unit tests (mirror_test.go, run 5× with -race)

  • Three mirrors next to a healthy primary: one hangs, one answers 500, one answers 429. 40 envelopes: every SDK answer 200 with production's body, slowest primary answer under 200 ms while the hanging mirror's timeout is 500 ms; every copy accounted for (sent or dropped); shutdown bounded by its context, byte budget back to 0.
  • Byte budget: with room for two bodies, 8 of 10 copies dropped queue_bytes.
  • Primary down: SDK connection aborted (no 5xx), mirror gets nothing, nothing translated.
  • Credential rewrite: header shape (mobile) keeps the body byte-identical; query + dsn shape (JS) rewritten, items unchanged, production request untouched.
  • Passthrough: unknown key, unknown project, no auth, store, minidump (query key), security, OPTIONS.
  • Translator panic: envelope dropped (panic), next envelope forwarded and translated.

      - sentry_project_id: "<prod project id>"
