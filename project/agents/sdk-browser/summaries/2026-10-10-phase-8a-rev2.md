# sdk-browser: 2026-10-10 Phase 8a revision 2 (the collector is the edge, ADR-0007 section 6)

Branch `phase-8a-install-secure`, worktree `.claude/worktrees/mvp-product-roadmap-6becbb`.
`@ouo/browser` stays 0.2.0 (unreleased); revision 1's rum-api gateway contract
(`/ingest/otlp`, `X-Ouo-Project-Token`, `otlpEndpoint`) is gone, nothing of it shipped.

## What changed

- `sdk/browser/src/ingest.ts` (rewritten): `basicAuthorization(projectId, projectToken)` ->
  `Basic base64(id:token)` (UTF-8 safe: `TextEncoder` + `btoa`, `Buffer` fallback; throws on a
  missing id or token and on `:` in the id), `ingestHeaders(authorization)` ->
  `{ Authorization }`, `deriveReplayEndpoint(endpoint)` (port `4318` -> `4319`, same scheme,
  host and path; any other port -> `endpoint`), `deriveIngestUrls({ endpoint, replayEndpoint?,
  projectId, projectToken })` -> `{ endpoint, replayEndpoint, traces, logs, replay }`. Constants
  `AUTHORIZATION_HEADER`, `TRACES_PATH`, `LOGS_PATH`, `REPLAY_CHUNKS_PATH`, `OTLP_HTTP_PORT`,
  `REPLAY_PORT`. Pure, no I/O. `PROJECT_TOKEN_HEADER`, `OTLP_INGEST_PATH`, `otlpBypass` removed.
- `sdk/browser/src/index.ts`: derives URLs and the credential first (fails fast, nothing
  installed on a bad id/token); both OTLP exporters get `headers: { Authorization }`; the chunk
  uploader gets `{ replayEndpoint, authorization }`; built-in `ignoreUrls` are `^${endpoint}/v1/`
  and `^${replayEndpoint}/v1/replay/`; the debug init line prints `endpoint`, `replayEndpoint`,
  `traces`, `logs`, `replay`, `projectId`, `session`, `user` (never the token or the header
  value). Re-exports `deriveIngestUrls`, `deriveReplayEndpoint`, `basicAuthorization`, `IngestUrls`.
- `sdk/browser/src/replay/uploader.ts`: `UploaderOptions { replayEndpoint, authorization,
  logger, fetchImpl? }`; the `Authorization` header is in the single `headers` object used by
  the gzip path and the `pagehide` keepalive path. `X-Ouo-Project-Token` is never sent.
- `sdk/browser/src/types.ts`: see API diff below.
- `sdk/browser/CHANGELOG.md`: 0.2.0 entry rewritten as "unreleased" for this contract
  (breaking list, migration diff, stack requirements). `package.json` untouched (0.2.0,
  publishable metadata from revision 1).
- `sdk/browser/README.md`: intro, init snippet, options table (`endpoint`, `replayEndpoint`,
  `projectId`, `projectToken`), replay headers and CORS note, Debugging section (new init line,
  collector status codes), Development section (stub ports).
- `sdk/browser/playground/main.js` (`?otlp=`, `?replay=`, `?project=`, `?token=`) and
  `playground/server.mjs`: the :8090 stub is now a collector stub (401 with
  `WWW-Authenticate: Basic` without the right credential, accepts `/v1/{traces,logs,metrics}`
  and `/v1/replay/chunks` on one port, CORS `allowed_headers` lists `authorization`,
  `Access-Control-Max-Age: 600`).
- `examples/web`: `src/rum.ts` reads `VITE_OTLP_ENDPOINT` (default `http://localhost:4318`),
  `VITE_OUO_PROJECT_ID` (`demo`), `VITE_OUO_PROJECT_TOKEN` (`pt_dev_demo_0000000000000000`) and
  passes `{ endpoint, projectId, projectToken }`; `VITE_RUM_API` dropped from `.env.example`,
  `README.md` and code; `src/rum-stub.ts` mirrors the new `RUMConfig` (`projectId` +
  `projectToken` required, `replayEndpoint?` optional).
- `examples/fast-tracked/20-frontend.md`: section 0 bullets, section 2 rewritten (collector
  4318/4319, Basic credentials, stock-SDK equivalence, htpasswd, CORS on the collector, failure
  signatures), `.env` block, `rum.ts` copy, throw message, options table, section 6 expected
  console/network output, the rum-api curls now send the read token (`RT` var; rum-api is
  internal but still on `localhost:8080` in the local compose), section 8 file walk.
- `project/kb/otel-browser-sdk.md`: section renamed "Project credentials on the collector", items
  14-21 rewritten (exporter `headers` = stock `OTEL_EXPORTER_OTLP_HEADERS`; `btoa` Latin-1 vs
  UTF-8; URL derivation via `new URL`; CORS with `Authorization` is not a CORS credential so
  `*` origins still work, `OPTIONS` must bypass basicauth, two origins = two preflights unless
  proxied; keepalive; ignore lists; two-port stub; bundle). `project/kb/web-demo-storefront.md`: env
  gotcha line updated. No new kb file, `project/kb/index.md` untouched.
- No new dependencies. `package-lock.json` untouched this time.

## Public API diff (`RUMOptions`)

```diff
 export interface RUMOptions {
-  /** rum-api base URL; SDK derives /ingest/otlp/v1/{traces,logs} and /v1/replay/chunks. */
+  /** Collector OTLP/HTTP base; OTLP goes to `${endpoint}/v1/traces` and `/v1/logs`. */
   endpoint: string;
-  /** Public project identifier, sent as X-Ouo-Project-Token. */
-  projectToken: string;
-  /** Escape hatch: OTLP to `${otlpEndpoint}/v1/{traces,logs}` instead of rum-api. */
-  otlpEndpoint?: string;
+  /** Replay receiver base (`/v1/replay/chunks`). Default: endpoint with port 4319 when endpoint uses 4318, else endpoint. */
+  replayEndpoint?: string;
+  /** Basic auth username. Required; initRUM throws when empty or containing `:`. */
+  projectId: string;
+  /** Basic auth password (public). Required; initRUM throws when empty. */
+  projectToken: string;
   service: ServiceOptions; tracing?; replay?; session?; user?; debug?;
 }
-export { deriveIngestUrls, PROJECT_TOKEN_HEADER, type IngestUrls };
+export { deriveIngestUrls, deriveReplayEndpoint, basicAuthorization, type IngestUrls };
```

Wire: `Authorization: Basic base64(projectId + ":" + projectToken)` on `POST ${endpoint}/v1/traces`,
`POST ${endpoint}/v1/logs` and `POST ${replayEndpoint}/v1/replay/chunks` (gzip, or plain JSON
with `keepalive` on `pagehide`), plus the unchanged `x-ouo-session-id` / `x-ouo-seq` on replay.

## For the qa agent (live check against ouo-collector)

1. Build the SDK first (`npm run -w sdk/browser build`), then `npm run -w examples/web dev` with
   `examples/web/.env` holding `VITE_OTLP_ENDPOINT=http://localhost:4318`,
   `VITE_OUO_PROJECT_ID=demo` and `VITE_OUO_PROJECT_TOKEN=pt_dev_demo_0000000000000000` (or
   whatever `deploy/compose/.env` and `collector/projects.htpasswd` agree on). With
   `VITE_RUM_DEBUG=1` the console shows `[ouo] @ouo/browser@0.2.0 initialised { endpoint:
   "http://localhost:4318", replayEndpoint: "http://localhost:4319", traces, logs, replay,
   projectId: "demo", ... }`.
2. Network tab: `OPTIONS` then `POST http://localhost:4318/v1/logs` and `/v1/traces` (200,
   request header `Authorization: Basic ZGVtbzpwdF9kZXZfZGVtb18wMDAwMDAwMDAwMDAwMDAw`), `OPTIONS`
   then `POST http://localhost:4319/v1/replay/chunks` (202 or 200 as the receiver answers, gzip,
   `Authorization`, `x-ouo-session-id`, `x-ouo-seq`). Nothing to port 8080, no
   `X-Ouo-Project-Token` anywhere. Both preflight answers must list `authorization` in
   `access-control-allow-headers` and the replay one also `content-encoding`,
   `x-ouo-session-id`, `x-ouo-seq`.
3. Negative checks: wrong token -> `POST 401` on all three routes and the console (debug) shows
   the OTel diag `export response failure (status: 401)`; serve the app from an origin not in the
   collector's CORS list -> console CORS error and no `POST` at all; empty
   `VITE_OUO_PROJECT_ID=` or `VITE_OUO_PROJECT_TOKEN=` -> the page throws
   `[ouo] initRUM: \`projectId\` is required ...` (or `projectToken`) at load and nothing is sent.
4. Unload path: navigate away / close the tab and confirm the last `/v1/replay/chunks` keepalive
   POST (plain JSON, no `content-encoding`) is accepted with the `Authorization` header; this is
   the one browser-only behaviour the unit tests cannot prove, and it depends on the cached
   preflight (`Access-Control-Max-Age` on the collector).
5. Downstream: `ouo.project.id=demo` on resources in Tempo/Loki is the collector's job; confirm
   the web-store session still appears in `GET /v1/sessions` (with the read token) with
   `has_replay: true`, the replay chunk `meta.json` records the project id, and the session plays
   in Grafana.
6. Proxy case (VM path, Caddy): with `endpoint: https://otel.<domain>` (no port) the SDK derives
   `replayEndpoint = endpoint`, so `POST https://otel.<domain>/v1/replay/chunks` must be routed
   to 4319 by Caddy; one origin, one preflight per path.
