# sdk-browser: 2026-10-08 bugfix run (QA phase 6 bug 1)

## 2026-10-08: duplicate `session.start` on expired-session rotation

### Root cause
`SessionLogProcessor.onEmit` called `correlationAttributes()` -> `session.id()` -> `ensure()`
for every log record. A `session.end` record is emitted by `end()` after it has set
`current = null`, so the processor's `ensure()` created a session (first `session.start`,
persisted), control returned to `start()` / `ensure()` which called `create()` again (second
`session.start`, persisted last and therefore the one the page kept). The first id became a
one-event "healthy" session in rum-api. The same re-entrancy hit the same-tab timer path
(lazy restart) and the max-duration path.

### Fix
- `sdk/browser/src/session/manager.ts`: rotation is atomic. `rotate(rec, reason, now)` closes
  the old record (`close()`: marks ended, persists, returns the `session.end` attributes),
  installs the replacement (`install()`: new record set as `current` and persisted) and only
  then emits `session.end` followed by `session.start` (`announce()`). A re-entrant `ensure()`
  during either emit returns the replacement. `start()` and `ensure()` use `rotate()`;
  the timer path keeps `end()` (lazy restart on the next signal, per spec).
- `sdk/browser/src/telemetry/correlation.ts`: `SessionLogProcessor` no longer calls
  `session.id()` for a record that already carries `session.id` (`session.start`,
  `session.end`); it fills `user.id`, `ouo.user.anonymous`, `ouo.platform`,
  `service.version` only and reads `peek()` for `session.previous_id`. Same shape as the
  react-native processor, which already worked this way.
- No new dependencies.
