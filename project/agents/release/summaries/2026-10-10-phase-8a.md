## Secrets and external accounts the user must set up before any workflow publishes

1. **npm organisation `ouo`** (scope `@ouo`), the publishing user as owner, then a granular
   access token (packages read and write, scope `@ouo`, bypass 2FA) stored as repository
   secret `NPM_TOKEN`. Provenance also requires the GitHub repository to be public.
2. **GHCR**: nothing to create; after the first `rum-api-v*` / `grafana-v*` run, link each
   package to the repository and make it public in the package settings.
3. **Grafana plugin signing (optional)**: grafana.com account, access policy token with
   `plugins:write` as secret `GRAFANA_ACCESS_POLICY_TOKEN`, repository variable
   `GRAFANA_ROOT_URLS` (comma separated root URLs). Without them the release is unsigned and
   Grafana needs `GF_PLUGINS_ALLOW_LOADING_UNSIGNED_PLUGINS=ouo-rum-app` (the grafana image
   already sets it).
4. **iOS mirror (optional)**: create the empty public repository
   `github.com/ZiadMansourM/ouo-ios`, generate an ed25519 deploy key, add the public half
   with write access to that repository, store the private half as secret
   `OUO_IOS_DEPLOY_KEY`. Until then `release-ios.yml` tests and exits with a notice.
5. `GITHUB_TOKEN` permissions are declared per workflow (`packages: write` for images,
   `contents: write` for the plugin release); nothing to configure unless the repository
   restricts the default token permissions, in which case the declared permissions still
   apply.
