## Done

**N13, collector**

- `collector/extension/ouoauthextension` (new module, type `ouoauth`): an `extensionauth.Server` that delegates to
  `basicauth/server` and counts each rejection as `ouo_auth_failures_total{reason, authenticator}`, `reason` in
  `missing | malformed | invalid_credentials | other` (no project label: the username of a failed request is client
  input). Receivers `otlp` (HTTP and gRPC) and `ouoreplay` authenticate through it. Tests use a real basicauth.
- `ouoratelimit` extension (new, same module as the processor, sub-package `ouoratelimitextension` because ocb calls
  `NewFactory` per import path): a confighttp / configgrpc receiver middleware that takes the request's tokens from the
  processor's shared buckets before the OTLP receiver drops empty exports, answers 429 + `Retry-After` with an OTLP
  `Status` body (JSON or protobuf by request) or gRPC `RESOURCE_EXHAUSTED` + `RetryInfo`, and marks the context so the
  processor does not charge the request again. Processor refactored: `admit` / `keys` shared, behaviour unchanged for
  receivers without the middleware (`ouoreplay`, `ouosentry`).
- Project `internal` (`pt_dev_internal_00000000000000`, `{SHA}` line in `deploy/compose/collector/projects.htpasswd`) and
  `OUO_BACKEND_OTLP_HEADERS` now defaults to it, so rum-api's and the demo backend's telemetry has its own buckets.
  The VM install still sets that variable to the installation's project (unchanged, N29).
- Bucket sizes from `OUO_RATELIMIT_{PROJECT,CLIENT}_{RATE,BURST}` (defaults unchanged), used by the QA script.
- Module tags: ocb builds from tagged modules without `replaces` (verified: local tags `collector/<kind>/<name>/v0.4.0`
  on a bare clone, `insteadOf` to it, `GOPROXY=direct` for `github.com/ouo11y`; nothing pushed). Not switched: a commit
  must build its own component sources (tags exist only after a release; PR CI would build the last release instead),
  and the repo is private (no module proxy). Reasons and the future release step in `collector/README.md`.
- No self-observability dashboard folder exists (8c), so the PromQL for 401s and 429s is in `collector/README.md`.
