## Component contracts

### `ouoreplay` receiver
- Config: named `ServerConfig confighttp.ServerConfig` squash (all confighttp server keys), defaults `endpoint: 0.0.0.0:4319`, `max_request_body_size: 8388608`, plus `max_rrweb_chunk_bytes: 4194304` (bigger bodies only for `kind: "frames"`). `Validate`: endpoint non-empty, sizes non-negative, rrweb limit <= body limit.
- `POST /v1/replay/chunks`, gzip or identity or no `Content-Encoding` (confighttp decompresses; `identity` added as a decoder). Validation is a copy of rum-api's `parse.go` rules (rrweb + frames, session id regex, seq 0..999999, JPEG SOI, touch phases, schema_version 1).
- Project id = `client.FromContext(ctx).Auth.GetAttribute("username")`; absent -> 401; not matching rum-api's `^[a-z0-9][a-z0-9._-]{0,63}$` -> 403 (otherwise rum-api would answer a permanent 400 after we said 202).
- One log record per chunk: body bytes = decompressed JSON, timestamp = `started_at`, attributes `ouo.project.id`, `session.id`, `ouo.replay.seq` (int), `ouo.replay.kind`, `ouo.replay.encoding=json`; resource `service.name=ouo-replay`, `ouo.project.id`.
- Statuses: 202 `{"accepted":1,"session_id","kind","seq","events","frames","touches","bytes"}`, 400 invalid / bad gzip, 401 (+`WWW-Authenticate: Basic`), 403, 405, 413, 429 + `Retry-After` (ResourceExhausted from ouoratelimit), 503 + `Retry-After: 1` (other retryable), 500 (permanent). JSON errors `{"error": "..."}`.
- Self-metric `ouo_replay_chunks_total{ouo_project_id, ouo_replay_kind, outcome=accepted|rejected|throttled|failed, reason}` + standard `otelcol_receiver_*`.

### `ouoreplay` exporter
- Config: named `ClientConfig confighttp.ClientConfig` squash; defaults `endpoint: http://rum-api:8080`, `timeout: 30s`, `compression: gzip`; `ingest_token` (opaque, optional) -> `Authorization: Bearer`; `sending_queue` (exporterhelper default, enabled) and `retry_on_failure` (5 s initial, 5 min max). `Validate`: absolute http(s) URL.
- One `POST ${endpoint}/v1/replay/chunks` per record, headers `Content-Type: application/json`, `Content-Encoding: gzip`, `X-Ouo-Project-Id` (record attr, else resource attr; missing -> permanent), `X-Ouo-Session-Id`, `X-Ouo-Seq`. 2xx ok; 429/503 retryable honouring `Retry-After`; other 5xx and network errors retryable; other 4xx permanent. On a mid-batch retryable failure only the undelivered records are retried (`consumererror.NewLogs`).

### `ouoratelimit` processor
- Config: `project: {rate: 1000, burst: 5000}`, `client: {rate: 100, burst: 300, key_from: address}`, `idle_timeout: 10m`. `rate: 0` disables that bucket kind. `key_from: x_forwarded_for` = first `X-Forwarded-For` hop from `client.Info.Metadata` (needs `include_metadata: true`), falls back to the address.
- One token per call from both buckets atomically (or none). Instances with the same component id share one limiter (refcounted, idle sweeper every `idle_timeout/2`), so the limits are per request across traces, logs, metrics and replay.
- Over the limit: gRPC `ResourceExhausted` + `RetryInfo` (ceil seconds, min 1) -> OTLP/HTTP **429 + `Retry-After`**, OTLP/gRPC `RESOURCE_EXHAUSTED`. (A plain non-permanent error would have been 503 without Retry-After; see kb.) Self-metric `ouo_ratelimit_rejected_total{key_kind=project|client}`.

- `otlp.grpc` `0.0.0.0:4317` and `otlp.http` `0.0.0.0:4318`, both `include_metadata: true` and `auth: {authenticator: basicauth/server}`; http `max_request_body_size: 4194304`, CORS `allowed_origins: ${env:OUO_ALLOWED_ORIGINS:-http://localhost:*,http://127.0.0.1:*}`, `allowed_headers: [Authorization, Content-Type, Content-Encoding, traceparent, baggage]`, `exposed_headers: [Retry-After]`, `max_age: 7200`.
- `ouoreplay` receiver `0.0.0.0:4319`, same auth/metadata, 8 MiB, CORS with `[Authorization, Content-Type, Content-Encoding, X-Ouo-Session-Id, X-Ouo-Seq]` (the SDKs send the two X-Ouo headers, so a browser preflight needs them).
- `resource/project`: `delete` then `upsert from_context: auth.username` on `ouo.project.id` (the resource processor does support `from_context`; the delete makes a request without auth context unable to keep a spoofed value).
- Pipelines: traces `[memory_limiter, ouoratelimit, resource/project, batch]` -> `otlp_grpc/tempo`; logs `[memory_limiter, ouoratelimit, resource/project, transform/events, batch]` -> `otlp_http/loki`; metrics same as traces -> `otlp_http/mimir`; `logs/replay` `[memory_limiter, ouoratelimit]` -> `ouoreplay` (no batch). **Deviation from the brief:** `ouoratelimit` is also on `logs/replay`, so replay shares the per-project / per-client budget; remove it there if replay should be unlimited.
- `ouoreplay` exporter `http://rum-api:8080`, `ingest_token: ${env:OUO_INGEST_TOKEN}`, queue 1000, retry 5 min.
- Self-metrics: `service.telemetry.metrics` `level: normal`, readers `periodic` (15 s, `otlp` `http/protobuf` -> `http://mimir:9009/otlp/v1/metrics`) and `pull` prometheus `0.0.0.0:8888` (not published).

## What other agents must know

- **platform-infra**: config and htpasswd paths, image name, `OUO_INGEST_TOKEN` and the `command:` all match your compose. `projects.htpasswd` now exists and is committed (re-included past `deploy/compose/.gitignore`). gRPC 4317 **has** the Basic authenticator: loopback clients must send `authorization` metadata (verified). CORS reads `${env:OUO_ALLOWED_ORIGINS}` (comma-separated, no spaces; default `http://localhost:*,http://127.0.0.1:*`): pass it to the collector in compose / `install.sh` if you want `--allowed-origins` back. VM: set `ouoratelimit.client.key_from: x_forwarded_for` in the VM collector config (receivers already have `include_metadata: true`); with `address` all traffic shares Caddy's bucket. On Docker Desktop all host traffic arrives from `172.17.0.1`, so the per-client bucket is per laptop. smoke.sh: oversize OTLP is **400** (not 413); rate limit is **429 + Retry-After**; replay 202 body has `"accepted":1`. Collector self-metrics are pushed to `http://mimir:9009/otlp/v1/metrics`, so `ouo_ratelimit_rejected_total`, `ouo_replay_chunks_total`, `otelcol_*` appear in Mimir with `job="ouo-collector"`. Health check stays on 13133; 8888 is in-network only.
- **helm**: same config with the htpasswd as a Secret mounted at `/etc/otelcol/projects.htpasswd` and `OUO_INGEST_TOKEN` from a Secret; Service ports 4317/4318/4319/13133; Ingress `/v1/replay/*` -> 4319, rest -> 4318; behind the Ingress controller use `key_from: x_forwarded_for`. The image is `ghcr.io/ziadmansourm/ouo/collector` on `collector-v*` tags.
- **rum-api**: the exporter sends `Content-Encoding: gzip` bodies (rum-api stores them as-is), `X-Ouo-Project-Id`, `X-Ouo-Session-Id`, `X-Ouo-Seq`, `Authorization: Bearer ${OUO_INGEST_TOKEN}` (omitted when empty). Your 4xx are treated as permanent (chunk dropped and logged), 429/503 retried with `Retry-After`. Project ids the receiver lets through always match your `^[a-z0-9][a-z0-9._-]{0,63}$`.
- **SDK / qa**: every OTLP and replay request needs `Authorization: Basic base64(project:token)`; replay goes to port 4319 `/v1/replay/chunks`. Handle 429 with `Retry-After` (and 503) as retryable on both ports; 401 and 403 are configuration errors. Preflight allows `Authorization, Content-Type, Content-Encoding, traceparent, baggage` on 4318 and `Authorization, Content-Type, Content-Encoding, X-Ouo-Session-Id, X-Ouo-Seq` on 4319; any other custom header breaks the preflight. Project ids for replay must be lowercase `[a-z0-9._-]`.
- **fast-tracked**: `deploy/compose/collector/config.yaml` is final for this phase; re-inline it verbatim in `examples/fast-tracked/00-stack.md`.
