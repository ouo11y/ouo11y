# rum-api, Phase 8a revision 2: rum-api is internal, the collector is the edge (2026-10-10)

Branch `phase-8a-install-secure`. Scope: apply the revised ADR-0007 (section 5) to
`services/rum-api`: remove the ingest gateway added earlier today, turn
`POST /v1/replay/chunks` into the internal sink for the collector's `ouoreplay` exporter,
revert CORS, keep the read token and the replay metrics.

## Removed

- Packages `internal/ingest` (gateway, OTLP decode / stamp / encode, forward, rate limiter,
  `ouo.ingest.*` metrics) and `internal/project` (YAML / env registry, origin patterns) with
  their tests.
- Routes `POST /ingest/otlp/v1/{traces,logs,metrics}`.
- Config: `OUO_PROJECTS_FILE`, `OUO_PROJECT_ID`, `OUO_PROJECT_TOKEN`, `OUO_ALLOWED_ORIGINS`,
  `OUO_MAX_INGEST_BYTES`, `OUO_RATE_LIMIT_RPS/BURST`, `OUO_IP_RATE_LIMIT_RPS/BURST`,
  `OUO_TRUST_PROXY`, `OUO_COLLECTOR_OTLP_ENDPOINT`, `OUO_COLLECTOR_TIMEOUT`. rum-api starts
  with no project configuration; `Options.Gateway` and the startup panic without it are gone.
- The `X-Ouo-Project-Token` header, per-project CORS (403 preflights, origin patterns), the
  `Retry-After` exposure and the 429 path.
- Dependencies: `gopkg.in/yaml.v3` and `github.com/kr/text` are gone from `go.mod`;
  `go.opentelemetry.io/proto/otlp`, `google.golang.org/protobuf` and
  `google.golang.org/genproto/googleapis/rpc` are back to `// indirect` (pulled by the OTLP
  exporters). `go mod tidy` run.

## Changed

- `internal/httpapi/replay.go`: `postChunk` is the sink. Order: `Content-Length` above the
  frames limit 413; `Authorization: Bearer <OUO_INGEST_TOKEN>` when the variable is set,
  else 401 with `WWW-Authenticate: Bearer`; `X-Ouo-Project-Id` required and matching
  `^[a-z0-9][a-z0-9._-]{0,63}$` (trimmed), else 400 (`missing` / `invalid X-Ouo-Project-Id
  header`); then the unchanged body handling (gzip / identity, 413 wire and decompressed,
  415 other encodings, 400 bad gzip, rrweb 4 MiB vs frames 8 MiB). The project id is passed
  to `Store.Put`, returned as `project_id` in the 202 body and recorded in `meta.json`;
  `ErrWrongProject` stays 403. `X-Ouo-Session-Id` mismatch warning kept, `X-Ouo-Seq`
  mismatch warning added. Exported `ProjectIDHeader`, `ValidProjectID`.
- `internal/httpapi/metrics.go` (new): `ouo.replay.chunks` (`{chunk}`) and
  `ouo.replay.bytes` (`By`) with `ouo.project.id`, created from `Options.MeterProvider`
  (global provider by default; the meter provider wiring in `telemetry.go` predates 8a and
  is untouched).
- `internal/httpapi/cors.go`: pre-gateway behaviour restored (reflect `http://localhost:*`,
  `http://127.0.0.1:*`, `CORS_ALLOWED_ORIGINS` exact, trailing slash tolerated; no CORS
  headers otherwise, request still served). Allowed headers: `Authorization, Content-Type,
  Content-Encoding, X-Ouo-Project-Id, X-Ouo-Session-Id, X-Ouo-Seq, Accept, Accept-Encoding`;
  `X-Ouo-Replay-Kind` exposed. `readAuth` unchanged.
- `internal/httpapi/server.go`: `Options.IngestToken`, `Options.MeterProvider`;
  `Options.Gateway` removed; chain `cors(extras, readAuth(token, mux))`.
- `internal/config/config.go`, `main.go`: `OUO_INGEST_TOKEN` added, gateway variables and
  the `project.Load` / `ingest.New` startup removed; the startup log shows `ingest_token`
  and `read_token` booleans.
- `internal/replay/store.go`: doc comments only (project id comes from the collector, not a
  token); `Put(ctx, projectID, body, gzipBody)` signature and legacy-meta adoption unchanged.
- `README.md`: rewritten around "rum-api is internal": architecture diagram with the
  collector as the only public ingest, env table (`OUO_INGEST_TOKEN`, `OUO_READ_TOKEN`,
  `CORS_ALLOWED_ORIGINS` back as a normal variable), sink contract (headers, check order,
  statuses), metrics, curl examples imitating the exporter. No ingest route or variable left.
- `project/kb-archive/ingest-gateway.md`: rewritten as a short note on the sink contract and why the gateway
  moved to the collector (keeps three lessons for the collector components); `project/kb-archive/index.md`
  line updated.

### Environment variables (names and defaults)

| Variable | Default |
|---|---|
| `OUO_INGEST_TOKEN` | unset (sink accepts any caller with a valid project id) |
| `OUO_READ_TOKEN` | unset (read side open) |
| `CORS_ALLOWED_ORIGINS` | unset (localhost / 127.0.0.1 always reflected) |

### Sink routes and codes

- `POST /v1/replay/chunks`: 413 `Content-Length` -> 401 token -> 400 project id -> 413 / 415
  / 400 body -> 413 rrweb size -> 400 invalid chunk / 409 kind / 403 other project -> 202
  `{"accepted":true,"project_id":"demo",...}`.
- `GET` / `DELETE /v1/*`: 401 without `Authorization: Bearer <OUO_READ_TOKEN>` when set.
- `OPTIONS` preflight: 204 with CORS headers for local origins and `CORS_ALLOWED_ORIGINS`,
  otherwise falls through to the mux (404 / 405), never 403.

## What is left

- Read-side project scoping: the read token is global; sessions of all projects are listed

## What the other agents must know

- **platform-infra**: rum-api needs none of the `OUO_PROJECT*` / `OUO_RATE*` /
  `OUO_COLLECTOR*` / `OUO_TRUST_PROXY` variables any more and must not publish port 8080
  outside the compose network (the collector's 4318 / 4319 are the public ports). Set
  `OUO_INGEST_TOKEN` on rum-api and the same value on the collector's `ouoreplay` exporter
  (`Authorization: Bearer`), `OUO_READ_TOKEN` on rum-api and Grafana. `CORS_ALLOWED_ORIGINS`
  is optional again (local origins are implicit). Probes unchanged (`/healthz`, `/readyz`,
  `rum-api -check`). The e2e / smoke scripts should post OTLP and chunks to the collector,
  not to rum-api; a direct sink call needs `X-Ouo-Project-Id` + the ingest bearer.
- **helm**: rum-api is ClusterIP only, no Ingress; `OUO_INGEST_TOKEN` and `OUO_READ_TOKEN`
  from the same Secret the collector / Grafana read; drop the projects ConfigMap mount and
  the `OUO_TRUST_PROXY` value.
- **collector** (`ouoreplay` exporter): `POST http://rum-api:8080/v1/replay/chunks`,
  headers `X-Ouo-Project-Id: <auth.username>` (must match `^[a-z0-9][a-z0-9._-]{0,63}$`,
  so project ids in the htpasswd file must be lower-case), `Authorization: Bearer
  <OUO_INGEST_TOKEN>` when configured, `Content-Type: application/json`,
  `Content-Encoding: gzip` when forwarding the gzip body as received (or send the plain
  JSON; rum-api gzips on disk), optional `X-Ouo-Session-Id` / `X-Ouo-Seq`. Retry on 5xx and
  transport errors only; 400 / 401 / 403 / 409 / 413 / 415 are permanent. Body limit for
  frames chunks is 8 MiB decompressed.
- **plugin**: nothing changes versus the first 8a revision: every `GET` / `DELETE /v1/*`
  carries `Authorization: Bearer <readToken>` through the route proxy; replay meta has
  `project_id`.
- **qa**: the first-revision live checks against `/ingest/otlp/v1/*` and
  `X-Ouo-Project-Token` are obsolete; the sink sequence above is reproducible with the README
  curl examples. `ouo.ingest.*` metrics no longer exist; use the collector's
  `otelcol_receiver_*` / `ouo_ratelimit_rejected_total` for rejections and rum-api's
  `ouo.replay.chunks` / `ouo.replay.bytes` for stored chunks.
