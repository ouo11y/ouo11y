  tests over 8 fixture Loki responses in `testdata/` (one is a real Loki response for the
  Phase 2 session `a4d47dfa…`).

- `internal/tempo`: search by `{ span.session.id = "<id>" }` with required start/end, second
  `&& status = error` query for `has_error`, semaphore (8) + 60 s TTL cache, Grafana Explore
  `panes` deep links.

  tests with fakes for Loki/Tempo and the real FS store.

  `OTEL_SDK_DISABLED=true` for local runs), `otelhttp` server handler (probes and OPTIONS
  filtered) and transport (Loki/Tempo calls are child spans).
- `Dockerfile` (multi-stage, distroless nonroot, `-check` healthcheck), `.dockerignore`,

- `deploy/docker/compose.yaml`: `rum-api` service (port `${OUO_RUM_API_PORT:-8080}`, bind

## Deviations / decisions the plugin must know

- `GET /v1/sessions` returns an envelope `{sessions: [...], count, from, to}` (not a bare
  array); `GET /v1/stats/health` adds `from`/`to`; `GET /v1/sessions/{id}/traces` returns
  `{session_id, traces, count}`.
- Timeline items are `{ts, type, name, attrs}`: `name` is the raw `event.name` (needed for
  custom events), `attrs` keys use `_` (Loki form), values are strings.
- Trace objects have an extra `root_service`. `trace_count` is `-1` when Tempo failed.
- Replay meta includes a `chunks` array with `event_count` per chunk; chunk ack includes
  `events` and `bytes`.
- A `session.end` with reason `crash` classifies the session as crashed even without a
  fatal `exception` record (mobile crash marker on next launch).
- Session ids must match `^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$`.

- The web demo's chaos buttons did not react to accessibility-ref clicks in the Chrome
  extension (coordinate clicks worked); not an SDK or API issue.
- Only one page of Tempo results (limit 1000) per session; fine for the MVP.
- No metrics of our own beyond what `otelhttp` records; no rate limiting on chunk uploads.
- `deploy/data/rum-api` is created by compose on first start (gitignored via `data/`).
- Grafana login for the deep-link check used the compose default admin/admin.
