# rum-api, Phase 7: frame chunks for mobile replay (2026-10-08)

Branch `phase-7-ios-replay`. Scope: make rum-api accept, store and serve `kind: "frames"`
replay chunks (ADR-0006, `docs/specs/mobile-replay.md`) next to rrweb chunks.

## What was done

`services/rum-api`:

- `internal/replay/store.go`: `KindRRWeb` / `KindFrames`, `ErrWrongKind` (409), `Viewport`,
  `Chunk` gains `Kind`, `FrameCount`, `TouchCount`, `Viewport`, `Platform`; `ChunkInfo` and
  `Meta` gain `frame_count` / `touch_count` (always present, 0 for rrweb), `Meta` gains `kind`
  (always) and `viewport` / `platform` (frames only, `omitempty`). New `Store.Kind(ctx, id)`.
- `internal/replay/parse.go` (new, parser moved out of `fs.go`): one streaming token parser
  for both kinds. Frames validation: `schema_version == 1`, `started_at > 0`,
  `ended_at >= started_at`, `viewport.width/height > 0` (`scale` defaults to 1), `frames`
  array (may be empty) where each frame has `ts > 0` and a non-empty `jpeg` that base64
  decodes (padded or unpadded) and starts with `FF D8`; touches need `ts`, `x`, `y`, `phase`
  in `began|moved|ended`; at most 1000 frames per chunk; unknown keys ignored; unknown
  `kind` is 400. `PeekKind` scans only top-level keys.
- `internal/replay/fs.go`: kind check under the per-session lock **before** the chunk file is
  written (a 409 leaves nothing on disk); `meta.json` without `kind` (Phase 3 files) reads as
  `rrweb`; `kinds` cache (session id -> kind, evicted on `Delete`) so `Kind()` is a stat plus
  a map lookup for list requests.
- `internal/replay/stream.go` (new): `WriteEvents` (409 on frames) and `WriteFrames`:
  `{session_id, kind, viewport, platform, started_at, ended_at, frames: [...], touches: [...]}`,
  frames copied through as uploaded in seq order, touches buffered and emitted after the
  frames array (chunk key order does not matter).
- `internal/httpapi/replay.go`: body read up to `MaxFrameChunkBytes` (8 MiB); a body above
  `MaxChunkBytes` (4 MiB) is 413 unless `PeekKind` says frames; `ErrWrongKind` -> 409; ack
  gains `kind`, `frames`, `touches`. `GET .../replay/frames` and `.../replay/events` share
  `streamReplay` (404 / 409 decided before headers are sent, gzip when accepted,
  `X-Ouo-Replay-Kind` header).
- `internal/httpapi/sessions.go` + `internal/session/fold.go`: `replay_kind`
  (`"rrweb" | "frames" | null`) next to `has_replay` on list and detail records.
- `internal/config/config.go`, `main.go`: `MAX_FRAME_CHUNK_BYTES` (default 8 MiB, clamped to
  at least `MAX_CHUNK_BYTES`). No compose change needed (defaults).
- README: new limits, validation rules, response shapes, curl examples.

## Deviations from the spec / what the plugin agent must know

- Meta: `frame_count` and `touch_count` are always present (0 for rrweb); `viewport` and
  `platform` are omitted for rrweb. `chunks[]` entries carry `event_count`, `frame_count`,
  `touch_count`.
- Chunk ack: `{accepted, session_id, kind, seq, events, frames, touches, bytes}`.
- 409 bodies are `{"error": "..."}` and name the endpoint to use instead.
- Frame objects in `GET .../replay/frames` are the uploaded objects verbatim (`ts`, `jpeg`,
  `reason`, plus anything else the SDK sent). `touches` is `[]` when none. `viewport.scale`
  is 1 when the SDK omitted it.
- `replay_kind` on session records is the cheap way to choose the player; `has_replay`
  stays.
- Touch phase `cancelled` is rejected (spec allows `began|moved|ended` only); the iOS SDK
  must map cancelled touches to `ended` or drop them.
- Streaming endpoints decide 404 / 409 before writing headers; a mid-stream read error still
  truncates the body (logged), as before.
