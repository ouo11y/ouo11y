## Findings

1. **Rotation overlap does not work with upstream basicauth.** ADR-0007 section 2 says
   "two htpasswd lines for the same project with different tokens during the overlap". On
   kind the earlier line's token is rejected (401) as soon as a later line for the same id
   exists: basicauth 0.160 keeps the last line per username. The chart now refuses duplicate
   ids and the README documents rotation as a cut-over. The ADR text (not in my paths) and
   any doc promising an overlap need correcting, or an ouo authenticator extension with
   several tokens per project (already listed under the ADR's consequences) is needed before
   mobile customers rotate.
2. Empty OTLP requests (`{"resourceSpans":[]}`) bypass `ouoratelimit` (all 200 against a
   5/s bucket); real payloads are limited. Smoke tests of the limit must send data.
3. Deviation from my brief, aligned with the reference config: gRPC 4317 is authenticated
   (cluster-internal Service only), there is no unauthenticated receiver, so rum-api's own
   telemetry carries the first project's credential (`rumApi.otel.project` to pick another).
   It is stamped with that project's `ouo.project.id`, like compose does with `demo`.
