## Done

**N6, `sdk/ios`.**
- Profiled the old path: render 80 % (`UIGraphicsImageRenderer` defaults to a 16-bit half-float
  bitmap on wide-color screens), JPEG 16.5 %, thumbnail 2.4 %, view walk 0.5 %.
- What stays on the main thread: the view walk (class names cached) and `drawHierarchy` into our
  own 8-bit `CGContext`. It uses Display P3 when the screen is P3, and an integer fraction of the
  screen scale (3x → 1x: 402 × 874 px frames).
- Moved to a serial capture queue: redaction planning and compositing, the thumbnail, dedupe
  (before encoding), JPEG via ImageIO, `ChunkBuilder` and the uploader hand-off (`FrameComposer` in
  Core). At most 2 captures in flight.
- Signposts `snapshot` / `compose` (subsystem `dev.ouo.replay`).

**G1, `sdk/ios` + `sdk/react-native`.**
- `OuoCrashCore` (C, async-signal-safe) and `OuoCrash` (Swift: install, NSException handler,
  pending report). The report is JSON with frames (`instruction_addr`, `image_addr`), the binary
  images they point into (`code_file`, `debug_id`, `image_addr`, `image_size`, `image_vmaddr`), the
  signal or exception, the time and the session id.
- Previous signal and exception handlers are chained, never swallowed.
- Expo module functions `installCrashReporter`, `setCrashSessionId`, `takePendingCrash`. New pods
  `OuoCrashCore` and `OuoCrash`, vendored by `sync-ios.mjs`.
- JS `src/crash.ts`: takes the report at `initRUM` and hands it to `SessionManager` as
  `nativeCrash`. The session ends `crash` at the crash time. A fatal `exception`
  (`ouo.exception.kind = native`, Apple-style stack text) is emitted after `ready`.
- `RCTFatalException` (a JS fatal in Release) is not counted twice.
- New option `errors.nativeCrashes` (default true).

**Scripts** in `project/agents/ios-replay/perf/` (the sentry-mobile harness itself is unchanged and
only run): `profile-runs.sh`, `capture_stalls.py`, `signposts.py`, `crash-flow.sh` (+ `crashtap/`,
a one-test XCUITest that confirms iOS 27's "Open in …?" sheet), `report.py`, data under `results/sim`.

  the same traces: 32–45 ms.

  - ouo replay alone: 10.3 → 8.2 % of a core; idle 5.7 → 4.1 %.
  - Sentry + ouo replay: 17.3 → 15.2 %.
  - Sentry-only control: unchanged.
  - Memory unchanged.
- Crash flows on a second simulator against env `b1-ios-replay-crashes`:
  - Native crash in `parallel` mode: ouo session crashed at the crash time, and Sentry's
    `EXC_BAD_ACCESS` arrived through the bridge.
  - Native crash in `ouo` mode: crashed, ended at the crash time.
  - JS fatal: one fatal exception; the native `RCTFatalException` report only set the end time.
  - Checked in rum-api (`status: crashed`, `end_reason: crash`) and in the Grafana plugin

## Not done / next

- **iPhone 16 Pro Max run**: asked the founder (via the parent session) for the phone, a USB
  connection and an Apple ID in Xcode. This Mac has no code-signing identity. The scripts take
  `--device`; `report.py` renders `results/device` when present.
- The plugin does not render `exception.stacktrace` (told the b1-plugin session). Stacks are only
  in Explore.
- Limits are listed in the kb: crashed thread only; nothing before `initRUM`; no watchdog, OOM or
  SIGKILL; the last in-memory replay chunk is lost on a crash.
- A crash within ~1 s of a new session loses that session's `session.start`. rum-api then reads
  the start from the first event, although `session.end` carries `ouo.session.started_at` (rum-api
  could use it).
