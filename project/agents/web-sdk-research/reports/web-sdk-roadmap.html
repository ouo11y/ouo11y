Web roadmap recommendation

How competitive @ouo11y/browser and the ouo stack are on the web today, and what to build next, in which order, how much in parallel, and when each piece is done. Companion to project/kb/web-sdk-research/roadmap.md (the argument) and comparison.md (the side-by-side reading of Appendices O, A–F and M). 2026-10-29.

Verdict todayThe SDK is competitive, the read side is not yetCapture, delivery and page safety are at the leaders' level and ahead on offline delivery, page-hide correctness, LoAF events and W3C-first propagation. Missing: error issues, a vitals performance view, shipped alerts, session search.
Already rareOTLP to the customer's collector, with replay4 of 25 vendors export RUM over OTLP to the customer's own collector; only ouo combines it with replay, a lookback buffer, funnels and self-hosting.
Two steps backNext value is in rum-api and the pluginN36 is mostly done. Six of the ten packages read data the SDK already sends; they also serve the Sentry-bridge web path (N39).
ReplayStay on upstream rrweb2.2.0 fixes the leaks our soak found; every fork is years behind. Copy the field's worker, mutation breaker, text masking and stylesheet dedupe.
Constraint48 bytes of core budget left45,008 B gzip against 45,056 B. New capture goes into lazy chunks or needs a budget decision (§6).
ParallelismFour lanesSDK, rum-api, plugin and provisioning, spec / tests / tooling. Disjoint folders; a package spanning lanes merges one PR per lane.

1. Lanes and milestones

Widths are the upper bound of each package's cost in focused agent-days (orchestrator estimates, roadmap §2); the calendar is not a date promise. Packages in one lane are sequential; lanes run at the same time.

9. Widening what is already different

  • OTLP with replay: propose a replay / session-recording semantic convention upstream (ouo, Dash0, Splunk and Faro each invented their own attributes; semconv v1.44 has none); offer replay as OTLP logs next to the receiver.
  • One session across browser, backend and mobile: session.id in baggage, the same sampling hash in the browser, React Native and rum-api; make the bridge path (N39) join the same id.
  • Overhead measured and gated: no vendor read gates CPU or bytes in CI; WB10 does, with the harness public in the repo.
  • Privacy by default: mask all text, scrub query strings, consent API, a data-collection inventory per capability.
  • Upstream work: rrweb prototype-list fix; browser SIG session manager (crypto.getRandomValues ids, session.start / session.end, a page-hide-safe batcher).
