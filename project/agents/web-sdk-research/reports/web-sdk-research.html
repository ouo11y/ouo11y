Web SDK research: how the field captures RUM and replay, and where ouo stands

Sentry, Datadog, PostHog, Grafana Faro and the OpenTelemetry-shaped vendors, the replay specialists and 25 vendors in all, read from their source code at their latest release tags on 2026-10-29, next to @ouo11y/browser, rum-api and the Grafana plugin as they stand at f4a3010. Companion to project/kb/web-sdk-research/ (Appendices O, A–F, M and comparison.md); the recommendation is in web-sdk-roadmap.html.

Reading: without replay ouo has the smallest eager bundle and its main-thread cost is in the same band as Sentry and Datadog (IQRs overlap). Replay is where ouo trails Datadog: a 79.5 KB rrweb chunk against a 15.3 KB recorder (@rrweb/record measures 22.4 KB), +161 ms/min more main-thread work (about equal across all threads: Datadog deflates in a worker), 3.5× the decoded replay bytes. WB1 and WB5 target that; WB10 gates it in CI. Large DOM (10,000 nodes): ouo sends its first snapshot 97 ms after navigation with no long task; Sentry's and Splunk's snapshots each make one long task (54 ms and 60 ms).

8. Surprises worth knowing

  • Sentry 11 sends request bodies, cookies and user info by default (dataCollection), and its "last 60 s" replay buffer holds 0–60 s.
  • Datadog's replay is no longer rrweb format (Change encoding with a string table since v7), and its trace ids are 64-bit inside traceparent.
  • PostHog sends no traceparent; backend correlation uses its own headers.
  • Faro's production path turns structured RUM into one logfmt line per record in Loki.
  • Splunk's recorder became a closed module fetched from its CDN in May 2025, while the transport stayed OTLP logs.
  • New Relic v1.324.1 has no long-task or LoAF observer although its docs describe one.
  • Bugsnag's performance SDK independently chose OTLP JSON and <meta name="traceparent">, as ouo did.
  • ouo itself: SDK_VERSION still reports 0.2.0 in the 0.3.0 package.
