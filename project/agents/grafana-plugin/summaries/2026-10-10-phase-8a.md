# 2026-10-10 Phase 8a: read token in the plugin (secureJsonData + route header), config page, 401 banner

Branch `phase-8a-install-secure`, worktree `.claude/worktrees/mvp-product-roadmap-6becbb` (not committed
by this agent). Allowed paths: `plugins/ouo-rum-app/**`, `project/agents/grafana-plugin/**`,
`project/kb-archive/grafana-app-plugin.md`. Contract: ADR-0007 section 6. Plugin version 0.2.1 -> **0.3.0**.

## What changed

1. **`src/plugin.json`**: route `rum/*` keeps `url` (`jsonData.rumApiUrl`, default `http://rum-api:8080`)
   and gains `headers: [{ "name": "Authorization", "content": "Bearer {{ .SecureJsonData.readToken }}" }]`.
   Grafana evaluates it server-side per request; the browser never sees the token. `dist/plugin.json`
   contains the header after `npm run -w plugins/ouo-rum-app build`.
2. **Configuration page** (`src/components/AppConfig.tsx`, `/plugins/ouo-rum-app`): `rumApiUrl` (Input,
   jsonData) and `readToken` (`SecretInput`, secureJsonData, write-only: "configured" + Reset from
   `plugin.meta.secureJsonFields.readToken`). Save / Enable plugin `POST /api/plugins/ouo-rum-app/settings`
   with `{ enabled, pinned, jsonData, secureJsonData? }`; `secureJsonData` is sent only when a token was
   typed or a stored one reset (Grafana merges secure keys, absent keys are kept). **Test connection**
   calls `rum/healthz` and `rum/v1/stats/health?from=now-1h` through the proxy with the saved settings
   and reports: reachable (200), "read token rejected by rum-api" (401), or the error text. A note says
   when unsaved changes exist. The page reloads after a successful save (as before); tests inject
   `onSaved`.
3. **API client** (`src/api/client.ts`): `RumApiError.unauthorized` (status 401), message
   `HTTP 401: rum-api rejected the read token (...). Set the read token in the plugin settings to the
   OUO_READ_TOKEN value ...`; `rumApi.healthz()` added. **`ApiErrorAlert`** renders a dedicated warning
   banner on 401 (title "rum-api rejected the read token", `LinkButton` to `/plugins/ouo-rum-app`, Retry)
   and the old error alert otherwise. Overview, Sessions and Session detail already render the alert in
   place of their content; Session detail suppresses the replay alert while the detail call is 401 so
   only one banner shows. `PLUGIN_CONFIG_URL` added to `src/constants.ts`.
4. **Version 0.3.0** in `package.json`; `CHANGELOG.md` rewritten with 0.3.0 (and the earlier versions
   from the tracker).
5. **Tests** (10 new): `src/api/client.test.ts` (url building, 401 -> unauthorized + hint, 502 hint),
   `src/components/ApiErrorAlert.test.tsx` (401 banner with settings link, generic alert otherwise),
   `src/components/AppConfig.test.tsx` (save sends jsonData + secureJsonData; no secureJsonData when
   nothing typed; configured token is disabled "configured", kept on save, sent after Reset; test
   connection reports 401 and success, and hits the two proxy URLs).
6. **Docs**: `plugins/ouo-rum-app/README.md` (configuration table, settings API, test connection, route
   header, provisioning with `secureJsonData.readToken: $OUO_READ_TOKEN`, versioning rule),
   `project/kb-archive/grafana-app-plugin.md` section "Phase 8a additions" (header templating, settings API merge
   semantics, provisioning expansion, SecretInput/Field testing gotcha, Grafana's 401 retry, onSaved).

No new dependencies (`SecretInput`, `LinkButton`, `Stack` are already in `@grafana/ui` 13.2.2).

   and no empty table / no second banner. Check the browser is **not** logged out and the DevTools
   network tab shows the proxied 401 (expect one retry by Grafana's backend_srv).
