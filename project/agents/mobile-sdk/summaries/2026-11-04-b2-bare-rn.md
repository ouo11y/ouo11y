# B2 (JUHI gap): bare React Native 0.82 through install-expo-modules

Date: 2026-11-04. Branch `claude/b2-bare-rn`. JUHI runs a bare React Native 0.82 app with Firebase pods;
`@ouo11y/react-native`'s native side (replay, native crashes, hangs, terminations, vitals, gzip) is an
Expo module, acceptable to them through `npx install-expo-modules`. Built and tested only on Expo 57 /
React Native 0.86 before this.

## What was done

- **Which Expo SDK**: `install-expo-modules@0.18.3` has no entry for 0.82 (SDK 54 = `~0.81`, SDK 55 =
  `~0.83`). Built both against 0.82.1 under Xcode 27: SDK 55 needs `RCTDevMenuConfiguration` (0.83+);
  SDK 54's `expo-modules-core` 3.0.30 needs two `#import`s that 0.82's `TurboModuleUtils.h` stopped
  pulling in (`CallInvoker.h`, `CallbackWrapper.h`; SDK 55 has them). So: `--sdk-version 54.0.0` plus a
  `patch-package` patch. The SDK's Swift and Kotlin needed **no change**; no `peerDependencies` change
  (`expo-modules-core >= 2.0.0` already covers 3.0.30); `sdk/android` and the podspecs untouched.
- **`examples/ouo-bare-rn`**: `@react-native-community/cli init` at 0.82.1, `install-expo-modules
  --sdk-version 54.0.0`, `@ouo11y/react-native` (`file:` link), `use_frameworks! :linkage => :static`
  always, `FirebaseCore` / `FirebaseCrashlytics` / `FirebaseAnalytics` 12.x pods (linked, not configured;
  `--no-firebase` to leave out). Its JavaScript is the golden app's (`../ouo-mobile` screens, journey,
  `ouo-chaos` module through `expo.autolinking.nativeModulesDir`), so the suites drive the same UI.
  Fixes, each commented in place: `MainApplication.kt` (installer writes an SDK 55 call),
  `bindReactNativeFactory` (installer omits it: trap at first root view), `@expo/cli` resolved from
  expo (Android release build fails, iOS silently uses the RN CLI), `fmt` as C++17 (Xcode 27),
  pod deployment targets >= 15.1 (Xcode 27), a UIScene delegate (iOS 27 traps without), cleartext http
  in the manifest (RN's plugin forces the placeholder false in release), `edgeToEdgeEnabled=true`.
- **Scripts**: `scripts/build-ios.sh`, `scripts/build-android.sh` (Release, `--env`, `--no-install`),
  `scripts/verify-ios.sh` + `verify-ios.py` (the real app on a simulator through the native suite's
  OTLP proxy: the golden `verify.py --vitals --feedback`, replay frames, SIGSEGV crash, hang, memory
  kill, gzip). `tests/e2e/mobile-android/run.sh` takes `OUO_ANDROID_APP=ouo-bare-rn`; `journey.sh` and
  `w4-signals-sim.sh` take `OUO_IOS_BUNDLE`.
- **Golden journey fix** (`examples/ouo-mobile/src/journey.ts`, `App.tsx`): `action/areas` notes
  rectangles relative to a root `View`. React Native before 0.86 subtracts the status bar from
  `measureInWindow` on Android even edge to edge, so on the 0.82 app every C8.2 rectangle was 28 to 52 pt
  off while the frames were fully masked. On 0.86 the root measures (0, 0): no change for the golden app.
- **CI**: job `bare-rn` on the Mac runner (`[self-hosted, macOS]`, like `android` and `swift`), path
  flag `bare-rn`: `npm ci`, the SDK build, the app's `npm ci` (applies the patch), Android Release APK,
  iOS Simulator Release app with the Firebase pods. Build only: the Mac runner runs one job at a time
  and has no stack; the suites run by hand.
- **Docs**: `sdk/react-native/README.md` "Bare React Native" (the steps, the SDK table, the patch, the
  three installer fixes, the Xcode 27 items); `docs/compatibility.md` "React Native hosts" (RN, Expo SDK /
  `expo-modules-core`, iOS min / Xcode, AGP / Kotlin / Gradle / JDK / compileSdk / minSdk, status,
  evidence; outside the `compat:` markers the release check parses); `docs/specs/mobile-sdk.md` (suites);
  `tests/e2e/mobile-android/README.md` (bare option, 4 GB AVD, edge to edge); kb
  [rn-bare-install-expo-modules.md](../../../kb/rn-bare-install-expo-modules.md).

## Verified, and how

All local, own env `b2-bare-rn` (`ouo-env up --src` this worktree), own simulator `ouo-b2-bare`
(iPhone 18 Pro, iOS 27.0), own AVD `ouo-b2-bare` (API 35, 4 GB, port 5590). No phone.

- iOS Simulator, `scripts/verify-ios.sh`: **6/6**, twice (before the journey change, and on a fresh build
  of the final head: hang 3067 ms, 54/54 gzip). The first run's numbers: Golden `verify.py --vitals --feedback` 20/20 (13 backend
  requests traced end to end, sessions with traces, 2 failed requests, feedback with screenshot frame,
  cold app start, TTID on 9 screens); replay 13 frames; C2.2 `SIGSEGV EXC_BAD_ACCESS` reported by the next
  launch, session crashed; C3.1 one hang of 3100 ms; C3.2 termination cause `memory`; C11.2 56/56 OTLP
  requests gzip.
- Android emulator, `OUO_ANDROID_APP=ouo-bare-rn tests/e2e/mobile-android/run.sh`: **19/19**, React
  Native Android L2 on C1–C11 (C8.2 pixels: every noted area black, means 0 to 0.0012). Two runs before
  failed C8.2 (and once C8.3, the known N92 timing): a 2 GB AVD (navigation-mode replay), then the
  `measureInWindow` offset; both explained in the kb, the second fixed in the golden journey.
- Golden Expo 57 app (`examples/ouo-mobile`) on the same emulator and env: 19/19 before the journey
  change (baseline at origin/main's code) and 19/19 after it.
- Both Release builds through the scripts (the commands CI runs); `lychee --offline` on the changed docs:
  0 errors; `tsc --noEmit` in `examples/ouo-mobile`: clean.

## Left, and what the next session must know

  a real `GoogleService-Info.plist`). React Native 0.81 and 0.83–0.85 are "expected, untested".
- Expo SDK 54 + React Native 0.82 is outside Expo's own support matrix; when JUHI moves to 0.83 they can
  drop the patch and use SDK 55 (`install-expo-modules` picks it).
- The shared main checkout is mid-merge with conflicted workspace `package.json` files: npm in any nested
  worktree fails unless `--prefix` is given (kb diy-browser-rum.md). Not touched.
- Dependencies added (example only): `expo` ~54 and its modules (`expo-constants`, `expo-device`,
  `expo-file-system`, `expo-status-bar`: the golden screens use them), `@react-navigation/*`,
  `react-native-screens`, `react-native-safe-area-context` (golden screens), `patch-package` (the
  `expo-modules-core` patch). Nothing added to the SDK or the workspaces.
