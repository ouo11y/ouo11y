## What was done

- **React Native SDK** (`sdk/react-native/src`):
  - `ui.tap` gains `ouo.ui.view_type` (the control's `role` / `accessibilityRole`, else the component that carries the label, else the innermost name, else the host view), `ouo.ui.gesture` (`swipe` when the touch moved 10 pt or more, else `long_press` at 500 ms or more, else `tap`) and `app.screen.name` (the last segment of the current `url.path`). The body is the readable step: `Tap add-to-cart (button) on Product`.
  - `RUMProvider` records a touch when it ends (`onTouchEnd`, and `onTouchCancel`, which is how a scroll view's takeover ends a swipe), stamped at its start so the plugin still pairs it with the replay's touch, and on the screen it started on. The open touch lives in the SDK instance (`_touchStart`, `_touchEnd`), so a re-render during a long press cannot lose it; a nested provider (same event object) and a second finger (`touches.length > 1`) do not start one, and any other start replaces a touch whose end never came.
  - Kill switch `timeline.tapLabels: false` (the one new option): `ouo.ui.target` is the view type, no `ouo.ui.path`; gesture, view type and screen stay. `trackTap(target, path, gesture?)` keeps the app's own target.
  - `navigation` records carry `ouo.navigation.kind = screen`, as the bridge's do.
- **Spec** (`docs/specs/mobile-sdk.md`): C6 is no longer draft (record, body, kill switches), C7 no longer says the SDK lacks the kind, C6.1 and C7.1 rows describe the new checks, matrix C6 moves to L2.
- **Conformance suite** (`tests/e2e/mobile`): the golden app now drives its three touches through `RUMProvider` with fibers shaped like React Native's (`Pressable` with `role`, a `FlatList`), a tap, a 700 ms long press and a cancelled 160 pt drag. C6.1 is required and checks target, view type, gesture and screen; C7.1 also checks one `navigation` of kind `screen` per screen change. The native module did not change, so `standin.cjs` did not either.
- **Plugin** (`plugins/ouo11y-rum-app`, two lines of rendering plus a helper): the session timeline and the replay activity list read a tap as a step, `Long press` + `add-to-cart (button) on Products`, from `ouo_ui_gesture`, `ouo_ui_view_type` and `app_screen_name`; bridge taps without them read as before.
- **Quickstart M6** `examples/quickstarts-mobile/tiny-shop-mobile-funnels/` (README, build-it-yourself guide, `result/`): the Tiny Shop Mobile app of M5 (#102) without the Debug section, with `add_to_cart` in the cart and `order_paid` after a paid checkout, `role="button"` on the buttons, a journey runner driven by launch arguments, and `generate-sessions/generate.mjs`: 30 sessions over 7 journeys with the expected count per step computed from the journey table with the funnel's strict order.
- **kb**: a W5 section in [funnels.md](../../../kb/funnels.md) (touch events, what a fiber walk can name, gesture thresholds, launch arguments instead of deep links, the npm walk-up cause).

## Review (ADR-0013)

The reviewer (a background agent of the orchestrator session) found two bugs and two nits; all four are answered in this PR:

- **F1** `app.screen.name` was read when the finger lifted: an `onLongPress` that navigates gave the next screen. The screen is now read at the touch start; a test navigates between start and end.
- **F2** a touch whose end never came blocked the next one for up to 10 s and then hijacked its end. The open touch moved from the provider (a `WeakMap`) into the SDK instance (`_touchStart`, `_touchEnd`): the same event object (a nested provider) or `touches.length > 1` (a second finger) start nothing, any other start replaces the open touch. The 10 s timeout and the exported `TrackTouch` type are gone. A test loses an end and then taps three times.
- **N1** the spec's kill-switch line now says it covers the taps `RUMProvider` records, and `trackTap` targets are the app's own.
- **N2** `ouo.navigation.kind = screen` overrides a kind passed through `trackNavigation(path, attrs)`: intended, the kind says where the record comes from, as in the bridge.
- After the fixes: 160 Vitest tests, conformance OK, and the real-tap runs repeated on a build of this head (labels on and off), same lines as above. The first device runs had used an older pack of the SDK: `npm install` of a `file:` tarball with the same name kept the locked copy (kb).
