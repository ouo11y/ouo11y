# 2026-10-30 W4: hangs, terminations, TTFD and error context

Branch `claude/w4-signals`, work package W4 of [roadmap.md](../../../kb-archive/mobile-sdk-research/roadmap.md) (§3, §10), mobile spec C2 to C4. Lane A (Swift) and lane B (the React Native error context), on top of W3a (PR #118) and W6 (PR #120), using W6's `RecentEvents` buffer (`ouo.last_events`), which W4 reuses instead of a second buffer. Env `w4-signals`, simulator `ouo-w4` (E9F929A9-B8C8-4232-A868-A2095B1286E7, iPhone 18 Pro, iOS 27.0).

## What was done

- **App hangs** (`sdk/ios`, C3.1): `HangDetector` (OuoVitals, pure) applies sentry-cocoa's V2 rules (read from `SentryANRTrackerV2.swift` and `SentryDelayedFramesTracker.m`) to the display link frames OuoVitals already counts: frame delay of the last 2 s every 400 ms, fully blocking at 2 s of a single awaited frame, not fully blocking above 99 %, stop below 160 ms of delay in 800 ms, a 2 s quiet period, a late watchdog tick forgets the frames. One change: `fully_blocking` is decided on the whole hang (a frame of 2 s or more in it), because on the simulator a 300 ms render before a 3 s block made the 99 % rule fire first. `OuoVitals.startHangTracking` runs the watchdog thread (not while inactive or under a debugger). `OuoCrash.startHangTracking` reads the main thread's stack at detection (`ouo_crash_main_thread_backtrace`: suspend, `thread_get_state`, the crash handler's frame-pointer walk, resume; the main thread's port comes from an image constructor) and builds a `hang` report in the crash report format, so W7's dSYM symbolication reads it.
- **Foreground terminations** (C3.2): `RunTracker` keeps `run.json` next to the crash report (active, session, 5 s heartbeat while active, memory warning, hang in progress); `takePendingReport` returns the crash report, else, once per process, a `termination` report when `Termination.decide` says the previous run was killed while active (no `willTerminate`, debugger, app or OS update, reboot). Cause `memory` (warning in the last 60 s), `watchdog` (hang in progress) or `unknown`. `run.json` is removed once read, so a launch that dies early cannot report the same termination twice. MetricKit is not used: no per-run attribution, late delivery (kb).
- **TTFD** (C4.2): `rum.reportFullyDisplayed()`; the screen's `ouo.screen.display` now waits for it until the screen is left, background or 30 s (Sentry's deadline), and carries `ouo.screen.ttfd_ms` (never below TTID).
- **Error context** (C2): every `exception` carries `ouo.last_events` (W6's buffer, last 20), `app.screen.name`, `ouo.device.locale`, and on iOS `ouo.memory.app_bytes`, `ouo.memory.available_bytes`, `network.connection.type` (`ErrorContext` in OuoCrash: `TASK_VM_INFO`, `os_proc_available_memory`, `NWPathMonitor`). The screen and last events are persisted (`ouo.context`: at once after a tap, navigation or exception, else at most every 5 s, and on background and flush), so a native crash or a termination reported by the next launch carries the crashed run's.
- **React Native**: `crash.ts` reads `hang` and `termination` reports (kinds, fatal, messages), `onHang` events from the Expo module (`Events("onHang")`, started by `installCrashReporter`, JS listens first), `getErrorContext`. No new option: `errors.nativeCrashes` covers hangs and terminations.
- **`session.previous_id`** was already on `session.start` after a background rotation (C1.1 passes); nothing to do.
- **Spec**: C3 no longer draft (the rules above), the error context in C2, the TTFD API in C4 and `mobile-vitals.md` §5, C2.1/C2.2/C3.1/C3.2 rows, matrix C3 and C4 at L2 for React Native iOS. **Conformance**: C3.1, C3.2, C4.2 required; C2.1, C2.2 and C3.1 also check the error context; `standin.cjs` models `run.json`, the termination report and the hang watchdog (`onHang` 0.6 s after a block of 2 s or more).
- **Demo**: `examples/ouo-mobile/modules/ouo-chaos` (demo-only Expo module: main-thread block, stutter, memory warning + SIGKILL), two Chaos buttons, journey mailbox actions, Products reports full display. `verify/w4-signals-sim.sh` drives it.

## Review round 1 (PR #122, `Review: changes needed`), what changed

- **B1**: every hang start now gets its end. A late watchdog tick ends a hang in progress at the last tick that saw it (it used to drop it, leaving `hangStartedMs` in `run.json`). `onStart` and `onEnd` carry the hang's start, and `HangPairing` in OuoCrash ignores a start whose end came first (`interrupt` on main beating the watchdog's `onStart`). Run-state writes happen under OuoCrash's lock, in pairing order. Tests: late tick, a debugger attaching mid-hang, end before start, a start paired with its own end.
- **1**: measuring restarts at `now` when tracking starts, on `interrupt` (resign and become active) and after a late tick, so a block before the first frame is a hang. Tests: a 5 s block right after resume is one hang from the resume; a block right after tracking starts.
- **2**: the watchdog waits on an `NSCondition` while the app is not active (no wakeups in the background). `HangWatchdog` now compiles without UIKit, and `HangWatchdogTests` checks no ticks while inactive, ticks while active, none after it resigns.
- **3**: an `atexit` handler marks `terminated` (test: `OuoCrashProbe none` exits, `run.json` says terminated, no termination); `release` ends with the main executable's `LC_UUID` (`ouo_crash_main_image_uuid`; test: a rebuilt binary is no termination); `os` is `major.minor.patch (kern.osversion)`.
- **4**: `run.json` is written `completeFileProtectionUntilFirstUserAuthentication` on iOS (no macOS test: the option is a no-op there).
- **5**: done here, not deferred: the hang's stack goes into `run.json` (`hangStack`) at `onStart`, and a `watchdog` termination carries it (`exception.stacktrace`, `ouo.crash.frames`, `ouo.crash.images`); `standin.cjs` models it. Tests in Swift and Vitest.
- **6**: the context persister writes at once after `ui.tap`, `navigation` and `exception`, otherwise at most every 5 s, and on background and flush (`context.test.ts`). The navigation tracker now makes the new screen current before emitting its record, so the persisted screen is the new one. **Measured apart**: two 3-round B3 runs, cells `none` and `ouo-T3`, back to back on the same simulator, persister on and off (a local, uncommitted change): CPU delta against `none` +5.03 pp (IQR 4.92 to 5.73) with it, +4.66 pp (4.53 to 4.70) without: about **0.4 pp at T3**; idle +3.94 against +3.79 pp. Both 3-round runs are about 1 pp above the 10-round run of the first round, with `none` itself at 7.2 to 7.8 % instead of 6.4 %, so the comparison holds only within that pair.
- **7**: `reportFullyDisplayed` after the deadline or the background logs that the record was already sent, naming the screen (test); `mobile-vitals.md` §5 says a crash while a record waits loses it.
- **8**: the kb link in `RunState.swift` is fixed, and the redundant `didEnterBackground` observer is gone.
