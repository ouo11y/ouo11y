# 2026-10-31 W8 part 1: the native iOS SDK (`OuoSDK`)

Branch `claude/w8-native-ios`, work package W8 of [roadmap.md](../../../kb-archive/mobile-sdk-research/roadmap.md) (§3, §10), part 1 of 2: what a UIKit or SwiftUI app needs to send the spec's records without React Native. ADR-0016 (dependency-free Swift, OTLP/JSON). Env `w8-native-ios`, simulator `ouo-w8` (617FDFE0-01F9-4EF8-8E0F-89F4C000931E, iPhone 18 Pro, iOS 27.0). Design notes and the risk table: [ios-native-sdk.md](../../../kb-archive/ios-native-sdk.md).

## What was done

- **`OuoSDK`** (new product in `sdk/ios`, on top of OuoReplay, OuoCrash, OuoVitals): `Ouo.start(OuoConfig)` and a static Swift and `@objc` API: `trackScreen`, `reportFullyDisplayed`, `setUser` / `clearUser` / `endSession`, `captureError` / `captureException`, `addEvent`, `log`, `startSpan` / `withSpan` (`OuoSpan`), `flush`, `sessionId`, `userId`.
- **Sessions (C1)**: `SessionManager`, the React Native manager made synchronous (the state is `session.json`): start, cold-start end of the previous session (`crash` from the crash or termination report, a passed deadline, else `terminated`), background timeout, inactivity, max duration, `session.previous_id`, N52 (a crashed session the file never saw ends from the report's `session_started_ms`); and what the spec has and the React Native SDK lacks: `user_change`, `manual`, `device.id`. Sampling per session id with rum-api's hash (vectors from Node). A background launch starts a session marked as in the background.
- **Export (C11)**: OTLP/JSON for logs and traces by hand (`OTLP.swift`), batches of at most a second or 64, gzip and the Basic credential at send time, through an outbox on disk: `DiskQueue`, extracted from `ChunkUploader` (which now runs on it too, public API unchanged), 5 MB / 500 requests / 24 h, 1 s doubling to 30 s, `Retry-After`, sent on the next launch, foreground and `flush`. A batch the disk refuses is sent once from memory.
- **Lifecycle**: `app.lifecycle` on changes (the launch state is none), the background rule, flush to disk and a send inside a background task on `didEnterBackground`.
- **Network (C5)**: `-[NSURLSessionTask resume]` swizzled on every class of a real task's hierarchy that implements it; CLIENT spans with the spec's attributes, `traceparent` + `baggage` (session, user, platform) set through the task's `currentRequest` only for `propagateTo` (prefixes at a boundary), `http.request.failed` / `http.request`, SDK uploads ignored, an app's `traceparent` kept.
- **Wiring**: OuoCrash (previous report as a fatal exception of the crashed session with the persisted screen and last events; hangs as `hang` exceptions; session and start into the crash state), OuoVitals (app start, TTID / TTFD for `trackScreen` screens, frame windows; `OuoVitals.nextFrame` added), OuoReplay (started, rotated or paused per sampled session; the previous run's open chunk recovered), error context (last 20 events, screen, locale, memory, network) on every exception.
- **`PrivacyInfo.xcprivacy`** in `OuoSDK` (no tracking; crash, performance, other diagnostic, product interaction, device id, not linked; UserDefaults CA92.1, system boot time 35F9.1).
- **W4 review note**: the comment in `DisplayLinkTracker.start` (hang detection before the first frame relies on the link firing while active).
- Docs: `sdk/ios` README ("OuoSDK: native apps") and CHANGELOG, spec matrix (native iOS C1–C5, C7–C9, C11 at L1; L2 needs the native suite, part 2), kb [ios-native-sdk.md](../../../kb-archive/ios-native-sdk.md), release-please bumps `Ouo.sdkVersion`.
- No new dependency.

## What could go wrong, and how it was tested

Threads (one lock, never held across hooks or app code; concurrency test), app extensions (refused), background launches (session marked background, no app start), file protection before the first unlock (`completeUntilFirstUserAuthentication`, send once from memory), clock changes (monotonic clock anchored at launch), offline (outbox; unit tests and the simulator run with the collector stopped), kill mid-write (atomic writes, at-least-once queue, context on disk at once after navigation / tap / exception), the swizzle (hierarchy walk, claim once, `responds(to:)` before KVC), `propagateTo` leaking to look-alike hosts (boundary match). The table with each test is in the kb. Found by the tests and the simulator, and fixed: a refused `start` (bad config) blocked a later good one; the frame time was the display link's `timestamp` (the frame already shown), which made TTID negative or near zero, now `targetTimestamp` on the SDK's clock.

## Review round 1 (PR #123, `Review: changes needed`), what changed

- **B1, launch kind**: `applicationState` is `.background` in `didFinishLaunching` of every app with scenes (SwiftUI `App`, new Xcode projects), so those launches lost app start and the first TTID, and their session was marked background. The SDK now reads the task role (`task_policy_get(TASK_CATEGORY_POLICY)`): `TASK_FOREGROUND_APPLICATION` is a launch for the user, the background, Darwin-background and non-UI roles are background launches, anything else counts as foreground. Test `LaunchKindFromTheTaskRole`; the verify package has three app shapes now (no scenes, a scene delegate, a SwiftUI `App`) and the checker asserts app start, Home's TTID and a first `app.lifecycle` that is a real change for each: all pass on the simulator. The launch notes show the bug and the fix: the scene app's `applicationState` was `.background` (2) in `didFinishLaunching` and its task role `TASK_FOREGROUND_APPLICATION` (1); the no-scene app was inactive (1) and the SwiftUI `App` active (0), role 1 in both.
- **B2, before the first unlock**: the store tells `missing` from `unreadable` (the file exists and cannot be read). While unreadable nothing is saved over it; the first save after it becomes readable, or `protectedDataDidBecomeAvailable`, ends its session as a cold start would and keeps its `device.id` and user (an identified user set meanwhile wins). Tests on a `chmod 000` file (`AFileThatCannotBeReadYetIsAdoptedOnceItCan`, fails without the `unreadable` case: checked by mutation) and on a store that unlocks (`AdoptionHappensOnTheNextSaveAndKeepsAnIdentifiedUser`). A corrupt file is still replaced.
- **B3**: `docs/specs/mobile-replay.md` says what the queue does now (no retry with the next chunk; chunks wait with a pending retry; no retry on foreground, so up to 60 s after an outage).
- **B4**: `device.id` is a resource attribute (the exporter's resource gets it from the session store, also after B2's adoption). Test `DeviceIdIsOnTheResource`.
- **1**: session changes reach OuoCrash and replay in order (a generation number, `InOrder`). Test `SessionChangesAreDeliveredInOrder`.
- **2**: `context.json` is snapshotted under the lock and written on a serial queue after it, newest wins; the previous run's is read there too. `ContextWritesDoNotBlockTheCaller` holds the write and checks the calls return (fails when the write is synchronous: checked by mutation). The cost, in the kb: a crash within about a millisecond of a tap can lose that write, as React Native's asynchronous storage can. `session.json` and the crash report stay on the calling thread in `start`, because the session must exist when `start` returns and the report decides how the previous session ended; measured `start` on the main thread: about 20 ms on the simulator's cold launch (an instrumented build, not committed: 10 ms the swizzle's class walk, which creates the process's first `URLSession`, a cost the app's first request pays anyway; 3–4 ms OuoCrash reading the previous run; the rest under 2 ms each). Moving the class walk off the main thread would miss requests started in the first milliseconds, so it stays; measuring `start` on a device and deciding on that walk belong to part 2's B3 cells.
- **3**: `start` copies the config (`Settings`). Test `TheConfigIsCopiedAtStart`.
- **4**: `AttributeValue`, `Attributes` and `SteadyClock` are internal; the CHANGELOG lists the removed `ChunkUploader.UploadError`.
- **5**: `TheDeviceClockChangingMidRunMovesNothing` moves an injected wall clock back an hour and forward two (through the core too); `StartRefusesInAnAppExtension` calls `start` with an `.appex` bundle; the unlock tests use unreadable and unwritable files (B2, `AnUnwritableOutboxSendsOnceFromMemory` with `chmod 555`). The weak tests they replace are gone.
- **6**: CI's swift job builds `OuoSDK` for the iOS simulator after `test.sh`. When a future iOS drops `setCurrentRequest:`, the SDK says so once, also without `debug`.
- **7**: one flush on background, inside the background task (`didEnterBackground(completion:)`). Test `BackgroundFlushCompletesAfterDelivery`.
- **8**: `DiskQueue.put` sends a refused write once from memory itself (`sendIfRefused: false` for held chunks); `Severity` is gone, `OuoLogLevel` carries the OTLP numbers. Test `ARefusedWriteIsSentOnceFromMemory`.
- **9**: README lines: an app calling `setUser` declares User ID, linked, in its own manifest; `url.full` keeps the query string, as the React Native SDK does.
- **10, 11**: open, see below (N55 extended to the iOS queues, N77 new).
- Also fixed on the way: `os.name` said `iOS` on an iPad (a flag that was never set); it now comes from the model identifier. A caller's `flush` could return while a timer-started flush still held a batch, so the drain after it missed that batch (the exporter test caught it about one run in ten): flushes are serialized. The export `URLSession` is made at the first send instead of in `Core.init` (the first one in a process costs about 8 ms on the main thread).

## Plan for part 2 (adds to this API, nothing breaks)

- **Screens (C7, C4)**: `OuoConfig.screens` (default true): a `UIViewController.viewDidAppear` swizzle for content controllers (containers, keyboard and system controllers skipped), the name from the class or an `OuoScreen` protocol property; SwiftUI `.ouoScreen("Cart")`. Both call the existing `Core.trackScreen`, which already emits `navigation`, measures TTID with `OuoVitals.nextFrame` and keeps the screen for errors; TTID's start moves to `loadView`/`viewWillAppear` for UIKit.
- **Taps (C6)**: `ui.tap` from the window's touches (reusing OuoReplay's `TouchObserver`), label from `accessibilityIdentifier` / `accessibilityLabel`, view type from accessibility traits or the class, gesture tap / long press / swipe, readable body; `OuoConfig.taps` and `tapLabels` (the kill switch), `Ouo.trackTap`.
- **SwiftUI masking**: `.ouoMask()` / `.ouoUnmask()` setting the `ouo-mask` / `ouo-unmask` identifiers the planner already honours.
- **The UIKit + SwiftUI example app** (`examples/`), its conformance suite with the same check ids on a simulator (promoting `verify/w8-native-sim.sh` and its checker), C1–C9 and C11 to L2; an Objective-C smoke target compiling against `OuoSDK-Swift.h`; B3 cells for the native app. Optional: `Ouo.feedback` (C10) on the same last-events buffer.

## Left, and what the next session must know

- Native iOS is L1, not L2: no conformance suite in CI yet (part 2).
- **N55** (open, checklist): a request the collector answers 5xx to every time blocks the queue until the bound or 24 h; it covers the native OTLP outbox too now. Needs a C11 change.
- **N77** (open, checklist, new): `DiskQueue` names files and ages them with the wall clock, so a clock moved more than 24 h forward drops what is queued. Not a one-liner: the steady clock is anchored to the wall clock at each launch, so the age across launches needs the boot time or a monotonic clock that survives the process.
- OuoCrash's own files (`report.json`, `run.json`) are also unreadable before the first unlock: a background launch then sees no crash report (it stays for the next launch) and no previous run state. Not changed here.
- `OuoSDK` and `@ouo11y/react-native` in one app are not supported (both would install the handlers).
- The verify app is a SwiftPM executable wrapped into an `.app` by the script; see the kb for the trick.
- Env `w8-native-ios` (http://grafana.w8-native-ios.ouo.localhost) and simulator `ouo-w8` stay up until the PR merges, then `ouo-env down w8-native-ios` and `simctl delete`.
