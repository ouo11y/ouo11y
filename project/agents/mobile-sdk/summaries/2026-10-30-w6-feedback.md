# 2026-10-30 W6: the feedback primitive

Branch `claude/w6-feedback`, work package W6 of [roadmap.md](../../../kb/mobile-sdk-research/roadmap.md) (§2.2 item 12, §3, §10), mobile spec C10. Env `w6-feedback`, simulator `ouo-w6-feedback` (E2FBE78D-74AC-4CF7-8EE4-92E2A1AF4335, iPhone 18 Pro, iOS 27).

## What was done

- **React Native SDK** (`sdk/react-native/src`):
  - `rum.feedback({ message, contact?, screenshot? })` emits one `feedback` event on the current session (body and `ouo.feedback.message`, `ouo.feedback.contact` when not empty, `ouo.feedback.id` UUID, which it returns). Trimmed, cut at 4096; an empty message sends nothing and returns `undefined`. No new option.
  - **The shared last-events buffer** (`telemetry/recent.ts`, `RecentEvents`): a log processor right after `SessionLogProcessor` keeps the session's last 20 records (events and log lines) as `{ts, name, body}` with a readable body; `read(sessionId)` is the plain read function. The feedback carries them as `ouo.last_events` (JSON). **W4 reuses it for error context**: `recent.read(session.id())` before emitting `exception`, same attribute name.
  - `screenshot: true` with replay recording sets `ouo.feedback.screenshot = true` and calls the recorder's existing `screenDidChange()` (`replay.frameForFeedback()`): a frame in `navigation` mode; `session` mode's interval frames already show the screen. No native change, so `standin.cjs` is unchanged and PR #118 is not touched.
- **Sentry bridge** (`collector/receiver/ouosentryreceiver`, spec section 9c): `feedback` items (`contexts.feedback`) and legacy `user_report` items become the same `feedback` record; contact = email, else name; the feedback's breadcrumbs go to the timeline (section 9b). New session rule `event`: the bridge remembers up to 64 emitted error / message event ids per session, so `associated_event_id` and a `user_report`'s `event_id` find the session.
- **Plugin**: a Feedback list in the replay panel (message, contact, "replay recording" badge, the steps before it from `ouo.last_events`, else the last 20 timeline events up to it for bridged records, "Replay at feedback" seek), a `feedback` look in the timeline / activity list, a feedback marker on the replay bar.
- **Spec** (`docs/specs/mobile-sdk.md`): C10 no longer draft (record, buffer, screenshot semantics, bridge, plugin); C10.1 describes the stronger check; matrix C10: React Native iOS L2, React Native Android L1 (JS). Draft note now names C3 only.
- **Conformance** (`tests/e2e/mobile`): C10.1 required; it checks message, contact, the returned id, the screenshot flag, the last three steps (`Swipe cart-items (FlatList) on Cart`, `golden log line`, `Error: golden handled error`) and that the replay covers the feedback time.
- **Demo** (`examples/ouo-mobile`): a "Report a problem" form on the Cart screen, a journey command `action/feedback`, the journey sends one on Cart, `verify.py --feedback` (opt-in, `run.sh` passes it; CI's Node leg sends no feedback).
- **kb**: [feedback.md](../../../kb/feedback.md).

## Review (ADR-0013, PR #120)

The reviewer approved with ten items; all but two are answered in this PR:

1. `onActivity()` now runs before the frame request, so after an idle timeout the frame, the last events and the record go to the new session (test: feedback after an idle timeout, the rotation reaches the recorder before the frame request).
2. `HeldReplaySession.feedback` counts the session's feedback (a second tally, `ouo.replay.feedback`, kept like the error count), so `keepAtNextLaunch` can keep the replays users reported on; tested and documented (C10, README, mobile-replay.md, the option's doc comment).
3. `frameForFeedback()` and the `isRecording` hoist are gone: `feedback()` calls `replay.isRecording()` and `replay.screenDidChange()` itself; the controller only gained `onFeedback()` for the tally.
4. Spec 9c: a `user_report` whose error is unknown stays without a session (`none`), with the reasons; holding it is N75.
5. The plugin lists a record sent twice (same `ouo.feedback.id`, a Sentry retry) once (test).
6. One cut rule: 4096 bytes of UTF-8, whole characters, then `…`, in the SDK (`cutUtf8`, also for the 200-byte step bodies) and the bridge (`truncate`); C10, 9c and the README say the same.
7. `ouo.last_events` is sorted by `ts`, stable (test with a vital stamped before the records emitted before it).
8. The bridge passes the feedback's replay id to `resolve` instead of writing it into the event; a comment says why rule `event` learns no device context or trace.
9. Open as **N75**: a bridge feedback (and a `user_report`) in the `sentry-mobile` CI journey and its verify.
10. Open as **N76**: `FrameReason.feedback` in `sdk/ios` after #118, then a tighter C10.1 frame check. The badge now says "replay recording" (tooltip: the replay at its time shows the screen, masked).

N56 to N74 were left alone: #98 and W5's quickstart row use ids in that range.

## Decisions worth knowing

- The draft spec said the record does not copy the events; the brief and the W4 error-context need both asked for them, so the record carries `ouo.last_events` and the spec now says so.
- The screenshot is a seek, not an image: the deduper means no new frame on a static screen, so "first frame after the feedback" would land on the next screen (kb).
- Feedback follows session sampling like every record (C1). With `session.sampleRate < 1` some feedback is never sent; keeping feedback outside sampling would change C1 and needs an ADR. Open question for the founder.
