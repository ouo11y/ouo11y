What ouo should build from the mobile SDK research, in which order, how much in parallel, and when each piece is done. Companion to project/kb/mobile-sdk-research/roadmap.md (the full argument) and comparison.md §12 (the thirteen recommendations it ranks). 2026-10-29.

1. Lanes and milestones

Widths are relative cost in focused agent-days (orchestrator estimates, §3 of the roadmap); the calendar is not a date promise. Packages in one lane are sequential; packages in different lanes run at the same time. W3 spans three lanes and merges as three PRs in the order schema and player, Swift tiles, React Native gzip and offline.

Lane D starts at the earliest point allowed (after W1 and W2, with tooling in place). On the Mac that exists today it has no toolchain, so without a second machine W9 slides to after W8 and M5 moves right by about three weeks. The founder's 2026-10-23 gate (web SDK, then the bridge) comes before day 0 of this chart; only W2, the ADRs and the shared record names can start before it.

Still missing after W10, in the order a prospect notices

  1. Profiling (Pyroscope in LGTM is the opening).
  2. Release-health comparisons and regression alerts across versions (Phase 9).
  3. Feedback widget UI: shake, annotation, ticket integrations.
  4. Paths / journey view (PostHog's paths) over the funnel query shape.
  5. Issue grouping and ownership (fingerprints, assignment, resolve / regress). What rum-api groups today was not verified in this research.
  6. Wireframe capture for UIKit / View apps that need text-searchable replays.
  7. Network body and header capture, GraphQL operation names, WebView bridging.
  8. Native Android and Flutter at L3.
  9. Platforms outside the six: tvOS, macOS, watchOS, Unity, .NET MAUI, Kotlin Multiplatform, Capacitor.
  10. Privacy and compliance surface: per-capability data inventory, user-level delete, SOC 2 evidence.
