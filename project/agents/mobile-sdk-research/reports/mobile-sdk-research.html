Mobile RUM and session replay SDKs

Sentry, PostHog, Luciq and the rest of the field, read from their source code where it is open. Research of 2026-10-29 by the mobile-sdk-research agent (one orchestrator, eight Opus sub sessions). Detail with line-level citations lives in project/kb-archive/mobile-sdk-research/: comparison.md and appendices A to H.

1. The questions, answered

RUMSentry is APM-grade, PostHog is analytics, Luciq is APM plus bug reportingSentry: sessions, crashes, ANR, app start, frames, screen loads with TTID/TTFD, network spans, profiling. PostHog: $screen, lifecycle, opt-in crashes, no ANR, no app start, no frames, no spans. Luciq: cold/hot launch, screen load, UI hangs (250 ms), app hangs (3 s), ANR, OOM, force restart, network with latency breakdown, user steps, a 60 s session profiler.
OpenTelemetryNone of the three exports OTLP from a mobile SDKSentry propagates sentry-trace + baggage (W3C opt-in). PostHog speaks OTLP/JSON for logs only. Luciq: none, only a home-made W3C traceparent for deep links into Grafana, New Relic or Dynatrace. Only Embrace, Splunk, Honeycomb, Elastic and LaunchDarkly run OTel in process; nobody sends replay over OTel.
ReplayAll three, three different techniquesSentry: screenshots encoded to H.264 mp4 segments on device, same pipeline on iOS, Android, RN and Flutter. PostHog: wireframe JSON by default, screenshots for SwiftUI, Compose, RN and Flutter. Luciq: WebP screenshots on screen transitions (or interactions, or a ≥ 500 ms timer), ≈10 KB each, played as a stepped timeline with user steps and logs; closed source.
Wire sizeSentry iOS measured: ≈110 KiB/min masked, ≈362 KiB/min unmaskedFrom 77 real segments captured in this repo. PostHog wireframes: a few KB/min gzipped. PostHog screenshots: 15 to 40 KB per changed frame. ouo today (ADR-0006 JPEG frames): nominal 1.2 to 2.4 MB/min while changing; measured at matched quality ≈2× Sentry (N50).
Same technique across frameworks?Sentry yes, PostHog noSentry RN is 100 % native; Flutter only swaps the capture step for Dart. PostHog forces RN into screenshot mode and captures Flutter in Dart as PNG. Everyone needs Dart-side capture for Flutter: the native tree is one opaque surface.
Open source?Sentry and PostHog fully; Luciq wrappers onlyEvery flow for Sentry and PostHog was read in MIT code. Luciq's native SDKs are binaries, so its appendix is docs, wrapper code and header names. Sentry's player is FSL, read for the reconstruction only.
Performance measurementMostly manual runs; Sentry Android is the exceptionThe iOS view renderer V2 numbers came from a timing patch on an iPhone 8 that never shipped. The Android startup blog is backed by an in-repo Jetpack Macrobenchmark. PostHog publishes nothing. Datadog, Embrace, New Relic have reproducible methods.
FunnelsPostHog strong, Sentry has noneThe claim "limited on Sentry" is generous: Sentry has no funnel or journey product. Luciq, Datadog, Amplitude, Mixpanel, UXCam and Contentsquare all ship funnels.

3. The replay pipelines, step by step

Thread of each step: main / UI thread background queue event or transport

Sentry iOS (sentry-cocoa 9.32.0)

Session starts → one draw: sessionSampleRate → session mode, else onErrorSampleRate → 30 s buffer
CFRunLoopObserver after UI work: 1 fps base, full rate while interacting, deferral in animations, ×2 backoff when a capture costs ≥ 150 ms
Redact: walk presentation layers → regions (class lists incl. RN and SwiftUI private classes, clipOut / clipBegin / clipEnd)
Render V2: drawHierarchy(afterScreenUpdates:false) into a calloc'd CGContext at screen scale (≈12 MiB on a 3× phone)
Mask at 1× (points), fill with text colour or average colour; PNG to disk for crash recovery; keep 6 (session) or 31 (buffer) frames
Every 5 s: AVAssetWriter H.264 Main, 40 kbit/s target, keyframe ≤ 6, no B-frames; identical frames are not deduped, H.264 P-frames absorb them
Envelope item replay_video = msgpack {event, rrweb recording with touches and breadcrumbs, mp4}; gzip; 30-envelope disk cache shared with everything
Crash: async-signal-safe C writes segment id and end time; next launch re-encodes the PNGs when the fatal event is processed

Sentry Android (sentry-java 8.62.0)

RootViewsSpy swaps WindowManagerGlobal.mViews; last added root is recorded (a dialog replaces the activity)
Main-looper postDelayed(1000 / frameRate), 1 fps; OnDrawListener dirty flag; no draw → re-emit the same bitmap
PixelCopy.request(window → RGB_565 at dp × scale, rounded to 16); View + Compose semantics tree built in the callback
Mask: per-line text rects in text colour, image rects in average colour, else black; JPEG q30 to disk; .ongoing_segment metadata
Every 5 s: MediaCodec H.264 VBR 75 kbit/s, I-frame every 6 s, MediaMuxer mp4; buffer mode encodes nothing until an error
Same msgpack replay_video item; crash → last segment rebuilt from JPEGs on next launch

PostHog iOS, wireframe mode (posthog-ios 3.92.7)

Swizzled UIView.layoutSublayers(of:) → throttled to 1 s with a trailing call; no timer
SwiftUI root? → return and log "enable screenshotMode"
Recursive walk → RRWireframe per visible view: id = view.hash, geometry, type (text, input, image, web_view…), style, text masked to *, unmasked images as base64
Emit $snapshot: meta on first frame, then always a type-2 full snapshot; no diff, no dedupe (Android diffs by id into type-3 mutations)
Disk replay queue, flushAt 20 / 30 s, gzip, POST /s/; browser converts wireframes to rrweb DOM at play time

Flutter: Sentry vs PostHog

Both wrap the app in a RepaintBoundary and walk the Element tree synchronously in the same frame for mask rects
RenderRepaintBoundary.toImage(pixelRatio: 1.0): logical points, ≈1.34 MiB RGBA per iPhone frame
Sentry: paint masks in the widget's text colour, hand raw RGBA to native (malloc pointer on iOS, JNI into a reused Bitmap on Android); no dedupe
PostHog: FNV-1a hash of every byte on the UI isolate (drop if unchanged), paint black masks, encode PNG, method channel → native decodes and re-encodes WebP
Native SDK segments / batches and uploads. Who schedules: sentry-cocoa pulls on iOS, Dart pushes on Android; PostHog Dart Timer + post-frame callback

6. The two Sentry blogs, grounded in code

iOS: view renderer V2

  • What was slow: V1 created a UIGraphicsImageRenderer per frame and called drawHierarchy; ≈155 ms per frame on an iPhone 8 at 2× (SentryDefaultViewRenderer.swift:8-13, PR #4940).
  • The fix: a hand-made CGContext (calloc w×h×4, flipped CTM, UIGraphicsPushContext, makeImage, free) at screen scale, ≈80 % less main-thread time (SentryGraphicsImageRenderer.swift:43-89, SentryViewRendererV2.swift:14-28). The same flag selects a V2 mask renderer, which the blog does not mention.
  • The rejected shortcut: layer.render(in:) is faster still but drops tab-bar SF Symbols, so it is opt-in as enableFastViewRendering, default false.
  • Versions: experimental in 8.47.0 (the blog says 8.48.0), GA and default in 8.50.0 (the blog says 8.50.2, which fixed one init path).
  • What came after: the display-link cadence became a run-loop observer with backoff and animation deferral (#7851, 9.19.0: slow frames 4.1 → 1.4 %), and encoding reads frames from memory (#8636, 9.26.0).

9. What ouo should build

  • Keep screenshot capture with on-device masking. Every vendor falls back to it for SwiftUI, Compose, RN and Flutter. Wireframes can be an optional later track for UIKit/View apps (New Relic's open captors are the reference).
  • Replace JPEG frames with a diffed representation before Android. Sentry's H.264 segments (≈110 KiB/min masked, needs a video player plus rrweb overlay) or LaunchDarkly's 64-px tile diff emitted as rrweb <img> mutations (zero bytes when static, plays in the rrweb player we ship). Prototype tiles first; keep kind: "video" for Sentry-sourced replays. Needs an ADR revision.
  • Change-driven cadence with a budget: layout/draw dirty flag → at most one capture per second → Sentry's backoff when a capture costs ≥ 150 ms → Datadog's 100 ms-per-second time bank → report skipped frames.
  • Rendering: copy V2 on iOS (drawHierarchy into a raw CGContext, downscale off main); PixelCopy into RGB_565 at dp resolution with RootViewsSpy on Android.
  • Masking fails closed: drop the frame when mask geometry moved between two samples, during transitions, or when the masked render fails; mask whole subtrees when a tree read throws; keep RN class lists for both architectures.
  • Crash durability: frames on disk, async-signal-safe metadata from the crash handler, finish the last chunk on the next launch; a separate disk budget for replay.
  • React Native: thin native module, container-view masks with collapsable={false}, never cache session or replay ids in JS without a native→JS rotation event, compress natively (Hermes has no CompressionStream).
  • Flutter: Dart-side capture at 1× logical pixels, synchronous mask walk, hash a downsampled copy, skip the walk when unchanged, hand one buffer to native without a PNG round trip.
  • OTel is the differentiator: build on opentelemetry-android and opentelemetry-swift, use the semconv session attributes and events, emit taps and screen views as log events; nobody else exports RUM plus replay to the user's own collector.
  • Borrow from Luciq: a navigation-only capture mode with a per-session byte budget for low-end devices, human-readable user steps as OTel log events with a content kill switch, and a next-launch keep/drop hook that sees the previous session's summary (client-side tail sampling).
  • Fill the gaps everyone leaves: ANR, app start with a kernel process-start origin, 700 ms frozen frames, TTID/TTFD, then a basic screen-sequence funnel in Grafana, which already beats Sentry.
  • Measure and publish: replay-on vs replay-off builds, per-run data in the repo, a trace section around init; no vendor gates replay overhead in CI today.
