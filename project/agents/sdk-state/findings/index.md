# sdk-state data

The inputs and outputs of Step 5. JSON files are read by the scripts in [`../scripts/`](../scripts/index.md).

| File | What it holds |
|---|---|
| [audit-brief.md](audit-brief.md) | The brief the four auditors worked from: method, statuses, output shape |
| [requirements.json](requirements.json) | The spec's 199 requirement ids with section, level (strongest keyword) and text, extracted from `sdk-spec.md` |
| [features.json](features.json) | Step 4's 125 features with target and platforms, extracted from `target-list.md` |
| [audit-web.json](audit-web.json), [audit-ios.json](audit-ios.json), [audit-android.json](audit-android.json), [audit-rn.json](audit-rn.json) | Per SDK: every requirement's status, `file:line` evidence, method and note; violations; feature states; architecture notes; how it was checked |
| [effort.json](effort.json) | Rough effort size (S, M, L) and what closing each Must and Should feature takes |
| [gaps.json](gaps.json) | Generated by `build_gaps.py`: ours against Sentry per feature and platform |
| [budgets.json](budgets.json) | The proposed section 13 budgets, the measurement setup text, and what was not measured |
| [overhead.json](overhead.json) | Generated by `summarize_overhead.py`: medians, ranges and chart rows from the harness results |
