## Headline

- **Compliance: 152 of 621 applicable MUST cells met (24 %)**, 176 partly. Web 42 of 157, iOS 40 of 152, Android 30 of 152 (standalone), React Native 40 of 160. The SDKs predate the spec; six structural differences explain most of it: replay is custom JSON to `/v1/replay/chunks` rather than OTLP, MVP names and scopes, no privacy layer (consent, `beforeSend`, URL sanitising), MVP session and sampling rules with no bypass set, no drop counting or self-disable, and the native SDKs do not wrap OTel.
- **Top Sentry gaps (Must)**: errors from unsampled sessions are lost (all four), no `beforeSend` (all four), no network timeline in mobile replay, no buffer-on-error replay on iOS and Android, no fingerprint override, no global attributes. Android as a standalone SDK is one large gap: 20 Must features. We are ahead on cross-tab sessions, session-level sampling, OTel logs interop and web compression.
- **Overhead**: ouo is smaller and cheaper than Sentry on most measures (web CPU two thirds of Sentry core, about half with replay; iOS app delta 3.5x smaller and init 12.6 against 47.1 ms; iOS replay peak memory 3.8 against 42.5 MiB; React Native JS 2.6x smaller). The exceptions: iOS core journey CPU (928 against 662 ms per minute), too many requests (web 31, iOS 38 per minute; Sentry iOS 8), and an idle iOS screen (387 ms per minute core, 2476 with replay).
- **Budgets proposed** for every row of section 13, with how CI enforces each; see overhead.md.
- **Web encoding**: keep OTLP/JSON with gzip; protobuf saves 7 % after gzip for 2.1 KB of bundle.

## How it was verified

- **Audits**: four parallel auditors, one per SDK, each graded all 199 ids from the code with `file:line` evidence and a method. I re-opened about a dozen cited lines per SDK; all matched. Unit tests ran on this commit and passed: browser 202, React Native 212, iOS 233, Android JVM 26. No wire capture per rule: the section 14 conformance suite does not exist yet.
- **Gaps**: generated by `build_gaps.py` from the audits and Step 4's Sentry cells; one Step 4 cell corrected (web `TRN-g` is not OTLP).
- **Overhead**: three harnesses written for this step, kept in `measure/`. Web on a quiet host (load about 2), 5 rounds, 3 more at 4x throttling. iOS and Android were first run under heavy contention (load 15 to 480, a parallel session's emulator and simulator) and rerun on the quiet host; the report uses the quiet runs. No iPhone was used: device budget spent 0 runs, 0 minutes.
- `lychee --offline` clean; the report checked in a browser at desktop and phone width.

## Dependencies added

None to the product. The harnesses pin `@sentry/browser` 11.11.0, `@sentry/react-native` 8.34.0, `esbuild` 0.25.12 and `@playwright/test` 1.64.1 (web), `sentry-cocoa` 9.33.0 through SwiftPM (iOS), `sentry-android` 8.63.0 and OkHttp 4.12.0 (Android): the versions Step 4 researched, to compare against.

## What the next agent must know

1. **Nothing here is a decision.** Budgets and the JSON recommendation go to Step 7 with the spec review.
2. **Bugs worth fixing before Step 12**: the React Native debug log prints part of the project token; a bad `jpegQuality` throws on an Android SDK thread and crashes the app; iOS forces the sampled flag on in unsampled sessions; web and React Native overwrite an app-set `traceparent`.
3. **`.gitignore` ignores every `data/` folder**, which is why the audit files live in `findings/`.
4. **Android has no native SDK.** Its compliance and gap rows judge `sdk/android` alone; most "not met" there means "not built", and its overhead is a lower bound.
5. **Mobile runtime numbers are simulator and emulator numbers.** One iPhone run at a checkpoint would calibrate them.
6. **Rebuild the report** after changing anything in `findings/` or `measure/*/results`: `build_gaps.py`, `summarize_overhead.py`, `build_report.py` (`--check` fails when stale).
7. No env was started; the simulators, emulators and servers the harnesses started were stopped by PID.
