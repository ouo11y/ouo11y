## Headline

- **Compliance: 143 of 612 applicable MUST cells met (23 %)**, 176 partly. Web 42 of 157, iOS 40 of 152, Android 21 of 143 (standalone; nine rows met only because the feature is absent count as not applicable), React Native 40 of 160. The SDKs predate the spec; six structural differences explain most of it: replay is custom JSON to `/v1/replay/chunks` rather than OTLP, MVP names and scopes, no privacy layer (consent, `beforeSend`, URL sanitising), MVP session and sampling rules with no bypass set, no drop counting or self-disable, and the native SDKs do not wrap OTel.
- **Top Sentry gaps (Must)**: errors from unsampled sessions are lost (all four), no `beforeSend` (all four), no network timeline in mobile replay, no buffer-on-error replay on iOS and Android, no fingerprint override, no global attributes. Android as a standalone SDK is one large gap: 20 Must features. We are ahead on cross-tab sessions, OTel logs interop and web compression; session-level sampling counts as ahead but is the same design as the first gap until a bypass set exists.
- **Overhead**: ouo is smaller and cheaper than Sentry on most measures (web CPU two thirds of Sentry core, about half with replay; iOS app delta 3.5x smaller and init 12.6 against 47.1 ms; iOS replay peak memory 3.8 against 42.5 MiB; React Native JS 2.6x smaller). Where it is worse: too many requests (web 31, iOS 38 per minute; Sentry iOS 8) and an idle iOS screen (387 ms per minute core, 2476 with replay). iOS core journey CPU is not settled: ouo's median is 928 against Sentry's 662 ms per minute, but ouo's 3 runs span 555 to 932, and B3 (React Native, N = 10) found ouo lighter.
- **Budgets proposed** for every row of section 13, with how CI would enforce each; see overhead.md. Mobile runtime gates go into the existing B3 benchmark (docs/benchmarks.md) as native cells at N ≥ 10, not a second harness; noisy metrics fail only when the lower quartile of the paired deltas is above budget.
- **Web encoding**: keep OTLP/JSON with gzip; protobuf saves 7 % after gzip for 2.1 KB of bundle.

## How it was verified

- **Audits**: four parallel auditors, one per SDK, each graded all 199 ids from the code with `file:line` evidence and a method. I re-opened about a dozen cited lines per SDK; all matched. Unit tests ran on this commit and passed: browser 202, React Native 212, iOS 233, Android JVM 26. No wire capture per rule: the section 14 conformance suite does not exist yet.
- **Gaps**: generated by `build_gaps.py` from the audits and Step 4's Sentry cells; one Step 4 cell corrected (web `TRN-g` is not OTLP).
- **Overhead**: four harnesses written for this step, kept in `measure/` (web, React Native bundle, iOS, Android). Web on a quiet host (load about 2), 5 rounds, 3 more at 4x throttling. iOS and Android were first run under heavy contention (load 5 to 500, a parallel session's emulator and simulator), discarded whole (`discarded_runs` in each results file) and rerun; the rerun journeys ran at load 2 to 5. The iOS init launches started while that load was still falling (about half at load 10 to 139); the medians of the launches below load 10 match within 0.7 ms. Mobile is n = 3, below the N ≥ 10 of docs/benchmarks.md: the report shows every range. No iPhone was used: device budget spent 0 runs, 0 minutes.
- `lychee --offline` clean; the report checked in a browser at desktop and phone width.

## What the next agent must know

1. **Nothing here is a decision.** Budgets and the JSON recommendation go to Step 7 with the spec review.
2. **Bugs to fix when each SDK is fixed** (web and React Native in Step 7, iOS and Android in Step 12): the React Native debug log prints part of the project token; a bad `jpegQuality` throws on an Android SDK thread and crashes the app; iOS forces the sampled flag on in unsampled sessions; web and React Native overwrite an app-set `traceparent`.
3. **`.gitignore` ignores every `data/` folder**, which is why the audit files live in `findings/`.
4. **Android has no standalone SDK yet.** Its compliance and gap rows judge `sdk/android` alone; most "not met" there means "not built", and its overhead is a lower bound.
5. **Mobile runtime numbers are simulator and emulator numbers.** One iPhone run at a checkpoint would calibrate them.
6. **Rebuild the report** after changing anything in `findings/` or `measure/*/results`: `build_gaps.py`, `summarize_overhead.py`, `build_report.py` (it also writes the budget table of overhead.md; `--check` fails when either is stale).
7. **Founder decisions after this step** (2026-11-10): the SDKs go OpenTelemetry-first, replacing the never-approved MVP-era ADR-0016 and ADR-0017. React Native keeps the OTel JS SDK; Android becomes a standalone SDK on `opentelemetry-android`; iOS moves to the `opentelemetry-swift` API and SDK core with ouo's own OTLP/HTTP exporter. "Native" means iOS and Android; React Native and Flutter are cross-platform. Plan: Step 7 reviews the spec after Step 6 and fixes web then React Native; Steps 8 to 11 are Muninn, the plugin front end and BFF, the full demo and the cloud; Step 12 fixes iOS, Android and Flutter. The golden rule (the app must not pay for the SDK's failures) is graded by the failure-safety checklist, PR #177.
8. No env was started; the simulators, emulators and servers the harnesses started were stopped by PID.
