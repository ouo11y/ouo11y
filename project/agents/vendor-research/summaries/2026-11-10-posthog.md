## Top findings

1. **gzip without a flag.** posthog-js 1.447.6 sends gzip bodies as `text/plain` with no `compression` param and no `Content-Encoding`. The server sniffs the gzip magic. Replay `/s/` bodies are a bare JSON array, not `{api_key, batch}`.
2. **Partial gzip inside web replay.** Only FullSnapshot and Mutation fields are compressed (`cv: "2024-10"`), so ingestion can count clicks and console lines. Capture merges a whole HTTP batch into one `$snapshot_items` Kafka message keyed by session. The consumer writes snappy NDJSON blocks (`[windowId, event]`) into shared S3 objects addressed by byte range. `session_replay_events` indexes the block URLs. Deletion is crypto-shredding.
3. **Mobile replay is one rrweb-shaped format with two node kinds.**
   - Wireframe trees: iOS sends a full snapshot per changed frame; Android sends mutations.
   - A single `screenshot` node: WebP q30, 1 px per point.
   - The proxy puts a screenshot frame at 7–23 KB (+33% base64), against about 1–5 KB for a wireframe.
   - `maskAllTextInputs` masks all text, labels included, on both platforms.
4. **Web delivery is in memory only.** A 3 s timer, 10 retries with exponential backoff, and one sendBeacon at pagehide. Native queues are file-backed and retry without limit: `maxRetries` applies only to push. RN drops a batch after 3 retries. Quota-limited analytics is silently 200 OK.
5. **Footprint and filters.** The core is 120.5 KB gzip plus a 68.8 KB recorder. surveys.js (47.7 KB) loads by default. HeadlessChrome is bot-filtered, so synthetic monitoring sends nothing. The `$posthog_config` replay custom event echoes the full init config into every recording.

## What the next agent must know

  - Override the HeadlessChrome UA, or no events are sent.
  - `OUT=<dir>` keeps runs apart.
