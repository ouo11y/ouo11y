## Open points for other agents

- collector: (1) `projects.htpasswd` must exist in `deploy/docker/collector/` before
  `compose up` (a missing bind-mount source makes Docker create a *directory* and the
  collector fails to read it); (2) behind Caddy (VM) the TCP peer is always Caddy, so a
  per-`client.address` `ouoratelimit` bucket throttles the whole site; key on
  `X-Forwarded-For` from the request metadata or let the VM config disable the per-client
  limit; (3) if the gRPC protocol is left without `auth`, the docs' "4317 loopback for
  backend development" note is exact; if it gets the authenticator, the note still holds
  (header required) but say so in your summary; (4) `cors.allowed_origins` is a tracked
  file edit for operators today; `${env:OUO_ALLOWED_ORIGINS}` would let `install.sh` take
  `--allowed-origins` again.
- rum-api: own telemetry now goes through the collector with the demo credential
  (`OUO_BACKEND_OTLP_HEADERS`), so rum-api's and the demo backend's spans carry
  `ouo.project.id=demo`. Acceptable for the dev stack; a dedicated `internal` project (one
  more htpasswd line) is the clean fix later.
- qa: `scenario.mjs` must send `Authorization: Basic ${OUO_PROJECT_BASIC}` on every OTLP
  (`${OUO_OTLP_URL}/v1/*`) and replay (`${OUO_REPLAY_URL}/v1/replay/chunks`) post and
  `Bearer ${OUO_READ_TOKEN}` on `${OUO_RUM_API_URL}/v1/*` reads; the replay receiver
  answers 202.
- fast-tracked: re-inline `deploy/docker/collector/config.yaml` verbatim in `00-stack.md`

- helm agent (FYI): the VM override's `volumes: !override` pattern and the `{SHA}` line

- Laptop stack still publishes Loki/Tempo/Mimir/rum-api on `0.0.0.0` (unchanged scope);
  the VM override binds them to loopback.
