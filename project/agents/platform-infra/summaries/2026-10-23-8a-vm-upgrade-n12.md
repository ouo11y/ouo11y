3. **Fixes from the runs** (each a trip point a non-founder would hit; details in
   `project/kb/vm-install-fresh-linux.md`):
   - rum-api exited with `mkdir /data/replays: permission denied` (root-owned bind mount; the
     image runs as 65532): the installer chowns `deploy/data/rum-api`.
   - Grafana crash-looped after 0.2.0 -> 0.3.0 with `plugin not installed: "ouo11y-rum-app"`,
     and every later Grafana image upgrade would have kept the first plugin: the `grafana-data`
     volume hides the image's plugin dir. New one-shot `grafana-plugin` service in
     `deploy/compose/compose.images.yaml` (outside my paths; it is the compose twin of the
     chart's init container and blocked the upgrade).
   - `ouo.service` hard-coded the build-mode files; after an `--images` install `systemctl
     start` rebuilt from source and swapped in stock Grafana. The installer rewrites
     ExecStart / ExecStop for the mode, and starts the unit (`enable --now`).
   - The 0.2.0 installer cannot upgrade to 0.3.0 (`deploy/docker/compose.yaml: no such file`,
     ADR-0010). The new installer moves `.env` and `projects.htpasswd` to `deploy/compose/`,
     and hands over to the checked-out installer only when that one knows the hand-over
     (an env var, not a flag: old scripts exit 2 on unknown options).
   - A re-run without `--ref` moved the checkout to `main`; it now stays put.
   - The Sentry bridge (4320) was neither published nor routed: Caddy `/api/*` -> 4320, a
     generated DSN key for new installs (upgrades keep the default their apps use), the DSN in
     the summary.
   - `--allowed-origins` writes `OUO_ALLOWED_ORIGINS`; the README still said to edit the
     collector config. `docker-buildx` added to the apt list (Compose warned without it).
