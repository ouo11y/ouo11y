## What changed

### `sdk/react-native` (`@ouo/react-native` 0.1.0 -> 0.2.0, breaking)

- `src/endpoints.ts` (new): `resolveEndpoints({ endpoint, otlpEndpoint })` derives
  `${endpoint}/ingest/otlp/v1/traces`, `/ingest/otlp/v1/logs` and `${endpoint}/v1/replay/chunks`
  (trailing slashes and whitespace trimmed, path prefixes kept); `requireProjectToken` throws a
  `TypeError` naming the option; `PROJECT_TOKEN_HEADER = "X-Ouo-Project-Token"`, `ingestHeaders`.
- `src/types.ts`: `RUMOptions.endpoint` is the rum-api base URL, `projectToken: string` is
  required, `otlpEndpoint?: string` is the escape hatch; `replayEndpoint` removed.
- `src/index.ts`: validates `endpoint` and `projectToken` before anything is installed; both OTLP
  exporters get `headers: { "X-Ouo-Project-Token": token }`; ignore patterns cover
  `^${otlpBase}/` and the replay chunks URL; the native replay controller receives the rum-api
  endpoint and the token; the debug init line prints the derived URLs and a truncated token.
  Exports: `resolveEndpoints`, `PROJECT_TOKEN_HEADER` added, `defaultReplayEndpoint` removed.
- `src/replay.ts`: `DEFAULT_REPLAY_PORT`, `defaultReplayEndpoint` and the `url.ts` import are
  gone; `ReplayControllerOptions.projectToken` and `NativeStartOptions.projectToken` are passed
  to native `start(endpoint, options)`.
- `src/version.ts` 0.2.0. `android/build.gradle` 0.2.0. `playground/scenario.cjs` reads
  `OUO_RUM_API` / `OUO_PROJECT_TOKEN` (optional `OUO_OTLP` escape hatch).
- Packaging: `package.json` 0.2.0 with `exports` (`types`, `react-native`, `require`, `default`,
  plus `./package.json` and `./expo-module.config.json`), `repository` (`directory:
  sdk/react-native`), `homepage`, `bugs`, `keywords`, `publishConfig.access: public`, `prepack:
  npm run build`, `files` adds `CHANGELOG.md`; `ios/.npmignore` (empty on purpose) so the

## `sdk/ios` and SwiftPM (for the release agent)

SwiftPM resolves `.package(url:)` only when `Package.swift` is at the root of the fetched
repository (subpaths are not supported; SwiftPM reads the manifest at the checkout root and
tags the whole repo). `sdk/ios/Package.swift` lives in a monorepo subdirectory, so native iOS
apps can only consume it by local path today, and CocoaPods only through the vendored copies in
the npm package. Options the release agent can pick from: (a) a mirror repository (for example
`ouo-ios`) that a release workflow populates from `sdk/ios` with `git subtree split` and tags
`v0.2.0`; (b) a `Package.swift` at the monorepo root that points its targets at `sdk/ios/Sources`
(works, but SwiftPM then clones the whole monorepo including the Grafana plugin and demo apps
for every consumer); (c) a binary `xcframework` attached to GitHub releases with a
`.binaryTarget`. No mirror or root manifest was created here.

Dependencies: none added (RN, Swift, demo app).

## QA: how to verify live on the iOS simulator once the new rum-api is deployed

1. Stack with the Phase 8a rum-api up; note the development token (`pt_dev_demo_0000000000000000`
   in `deploy/compose/.env.example`) and the read token (`OUO_READ_TOKEN`).
2. `npm run -w sdk/react-native build`, then in `examples/mobile`: `npm install`,
   `npx expo prebuild --platform ios`, and
   `EXPO_PUBLIC_RUM_API=http://localhost:8080 EXPO_PUBLIC_OUO_PROJECT_TOKEN=pt_dev_demo_0000000000000000 BACKEND_URL=http://localhost:8081 EXPO_PUBLIC_QUIET_LOGBOX=1 npx expo run:ios --device "iPhone 18 Pro"`
   (ports as in your `deploy/compose/.env`; on this Mac rum-api is 8080, backend 8082).
3. Metro log must show `[ouo] @ouo/react-native@0.2.0 initialised {rumApi, traces:
   ".../ingest/otlp/v1/traces", logs: ".../ingest/otlp/v1/logs", replayChunks: ".../v1/replay/chunks",
   projectToken: "pt_dev_d…"}` and no `[ouo:otel] export response failure (status: 401)`.
4. Drive Products -> Product -> Add to cart -> Cart -> Checkout; wait ~7 s. Then with the read
   token: `curl -s -H "Authorization: Bearer $OUO_READ_TOKEN" 'localhost:8080/v1/sessions?from=now-1h&platform=mobile' | jq '.sessions[] | {session_id, status, replay_kind, replay_frame_count}'`
   must list the session with `replay_kind: "frames"`; `GET /v1/sessions/<id>` timeline must show
   `navigation` events; Tempo must have the `HTTP GET/POST` client spans joined with the backend.
5. Negative checks: restart Metro with `EXPO_PUBLIC_OUO_PROJECT_TOKEN=pt_wrong` -> Metro shows
   `export response failure (status: 401)` and `xcrun simctl spawn booted log show --last 2m
   --predicate 'process == "mobilestore"' | grep "ouo replay"` shows `upload of seq=0 failed
   (httpStatus(401))`; rum-api's `ouo.ingest.requests` metric counts `outcome=rejected, reason=token`.
   Then `curl -s -X POST localhost:4318/v1/logs` from the Mac still works (127.0.0.1 binding) but
   `http://<mac-lan-ip>:4318` from a phone must not.
6. Optional: `OUO_REPLAY_STUB_URL=http://localhost:8080 OUO_PROJECT_TOKEN=pt_dev_demo_0000000000000000 ./test.sh --filter RealHTTP`
   in `sdk/ios` pushes two real gzip chunks through URLSession with the header.
