## Bugs and observations (not fixed, see `project/agents/qa/reports/phase-8a-bugs.html`)

1. minor, rum-api: resource attributes (`ouo_project_id`, `device_*`, `session_previous_id`) show
   up as custom-event attributes in the timeline (`add_to_cart ouo_project_id=demo product_id=…`).
   Repro: `GET /v1/sessions/d6eedf18-04e7-40b5-be33-ec535335df53` custom entries.
2. minor, sdk-react-native: a fatal error produces a second non-fatal `exception` record after
   `session.end` (`error_count 1` with no handled error); likely LogBox's console.error in dev.
   Repro: dev client, Chaos > Fatal error, relaunch, read the timeline of the crashed session.
3. observation, sdk-react-native: two dev-only 1-span `HTTP POST` traces at crash time (Metro
   symbolicate calls are traced).
4. environment, sdk-browser / qa: keepalive chunk delivered on navigation (seq 11) but lost when the
   Claude pane closed the tab (seq 9 gap, no rejection counted); confirm in stock Chrome.
5. environment, examples/mobile docs: `expo.extra` is evaluated by expo-constants during
   `xcodebuild`, so `EXPO_PUBLIC_*` / `BACKEND_URL` must be set for the native build (or in
   `examples/mobile/.env`), not only for Metro; a bare RN debug app connects to Metro 8081 and the
   `dev.ouo.mobilestore://expo-development-client/?url=` link does not switch it (no
   expo-dev-client); `defaults write dev.ouo.mobilestore RCT_jsLocation "localhost:8091"` does.
6. observation, grafana-plugin kb: Reset + empty save drops the secure key on Grafana 13.2.1; the
   "still configured" quirk in `project/kb-archive/grafana-app-plugin.md` does not occur and can be reworded.

Carried from Phase 6: React dev double-reports the uncaught error (`crash_count 2`); Tempo strips
leading zeros from trace ids.
