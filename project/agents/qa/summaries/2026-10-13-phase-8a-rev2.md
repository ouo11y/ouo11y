## Bugs and observations (not fixed; `agents/qa/reports/phase-8a-bugs.html`)

1. R2-1 minor, examples/web: no `replayEndpoint` option. With OTLP on any port but 4318 the SDK
   sends chunks to the OTLP port, which answers 404 (`curl -u demo:… -X POST
   localhost:4330/v1/replay/chunks` -> 404). Fix: `VITE_OUO_REPLAY_ENDPOINT` -> `replayEndpoint`.
2. R2-2 minor, examples/mobile: same, plus the installed dev client's baked `expo.extra`
   (`otlpEndpoint :4318`, `backendUrl :8081`) ignores Metro's env, so on this Mac the app would
   report to the other compose project and call the other session's Metro as its backend. Fix: read
   `process.env.EXPO_PUBLIC_*` first in `src/rum.ts`, add a replay endpoint variable, rename
   `BACKEND_URL` to `EXPO_PUBLIC_BACKEND_URL` (or document a rebuild).
3. R2-3 observation, collector: 401s are invisible in Mimir (basicauth rejects before receiver
   counters; no `http_server_*` for the collector at level normal; `ouo_replay_chunks_total` has
   only `accepted`). Suggest an auth-failure counter.
4. R2-4: revision 1 findings 1 (resource attrs in custom-event timeline), 2 (RN second exception
   after `session.end`) and 3 (RN dev symbolicate traces) still reproduce; finding 4 (chunk lost on
   tab close) did not. Carried from Phase 6: React dev double-reports the uncaught error
   (`crash_count 2`).
